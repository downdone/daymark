# ADR-036 业务后台与许可统计

2026-11-12，接受。用户授权实施BIZ-01/TEL-01，随后明确取消客户端通知中心，替代此前暂缓决定。后台公告管理保留，不新增桌面投递/未读/已读。十二项设计见[系统设计](../design/daymark-business-platform.md)，真实状态见PROGRESS。

继续模块化Go单体。业务表接续现有SQLite迁移，使用独立的强类型BusinessTx端口复用同一个有界写者；统计使用独立metrics.sqlite、有界写者与事务。管理HTTP/模板和统计协议独立版本，不改变任务同步DTO或本地schema11。Qt统计关闭时不建立队列或发请求，开启须服务端许可确认；账号/服务绑定、撤回、跨库删除可恢复。

同日用户确认重新评估后的取舍：本期使用独立版本HTTP JSON批次协议，不引入OpenTelemetry SDK、Collector或OTLP适配器。当前仅少量产品事件和低频性能分桶，标准传输不能代替许可、白名单、去重与看板；增加协议适配收益不足。强类型事件、队列、传输和接收仓储保持边界，未来确有接入统一观测平台或跨服务追踪需求时再评审OTLP。服务端运行日志/请求关联与用户产品统计分开。

后台使用Go html/template、嵌入CSS，无前端运行时依赖。独立管理员身份/Argon2会话、TOTP及恢复码、同源CSRF、Secure Cookie、最小权限。TOTP选用github.com/pquerna/otp v1.5.0（Apache-2.0，官方tag），取代手工实现认证算法；传递二维码barcode依赖仅库内引入，已核验锁定模块MIT LICENSE并保留原文。不引入二维码页面功能、CDN、Redis或消息中间件。版本和校验和锁在go.mod/go.sum；许可说明同步third-party-notices。

管理员引导只通过维护CLI，不提交生产管理员/密钥。管理入口默认关闭；开发可仅环回HTTP，公网必须既有HTTPS入口与MFA。客户端产品统计默认OFF，明确告知/主动同意，任务内容、URL、账号、原始错误/路径不进入事件；可关联删除的主体称假名化，不宣称匿名。

替代：微服务/独立部署增加运维成本；第三方分析SDK不符合默认离线与最少依赖；将后台SQL放HTTP或QML会破坏层次；把通知/埋点塞进任务协议会扩大兼容故障域，均不采用。
