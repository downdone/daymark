# ADR-020：上下文任务工作区与就近面板

日期：2026-10-25。状态：**已接受并实施；2026-10-25用户要求完整实现规划，实际验证见PROGRESS**。用户要求全产品系统评估，补充macOS日/周/月/年参考，并提出列表详情是否也可就近小面板呈现。FR-034/035成为当前契约，验证结果及平台边界见PROGRESS。

## 背景

ADR-016/019已统一任务及起止属性，但当前列表/日历共用同一view枚举，日历投影全量cache，详情以独立主区页面呈现。旧FR-011“无小时轴”与新的时间规划目标需要明确分开；仅把窗口缩小无法解决范围、草稿和时间语义。

## 决策

1. 范围与呈现分离：同一QueryService结果可用列表或日历查看；保留范围、筛选、taskId及滚动锚点。日历日/周负责具体时段，月负责分布/跨日，年先负责导航。
2. 任务详情默认就近面板，长内容/窄窗/大字按需展开同一editorSession；不把完整能力另存为第二套表单。列表、日历、子任务与组件使用同一任务身份。
3. 新面板及展开容器结束编辑前保存，失败保留输入并阻止离开；明确放弃才丢草稿。此目标覆盖现有完整页显式保存的体验策略，迁移后列表、日历与展开形态使用相同规则。
4. 保留两层任务、父子完成/删除/分类移动联动、日期和标签独立、软删/CAS/备份，以及历史深层/时间冲突资料的兼容。无本轮schema变更。

## 时间命令与范围

小时轴整体平移的UTC时长、显示时区与原任务时区、按日改期墙钟语义、DST歧义/缺失、相对提醒及系列范围由[ADR-021](021-calendar-time-commands.md)定义。年导航不引入全年实例物化；全年负荷预测另行设计。不引入账号、订阅、邀请或云服务。

## 迁移与替代

原行/完整页现有草稿安全继续作为基线。先建立共享会话和失败关闭门，再替换列表入口，最后接子项/日历/组件；不同时开放两个编辑同一任务的容器。日/周/月/年逐片交付，未完成不放空按钮。旧FR-010/011、ADR-009等保留历史，目标差异在新需求与本提案明示。

不采用：全量推倒重写、每个入口各一份编辑器、只剩一只塞满所有字段的小窗、打开年视图向数据库写满一年循环实例。具体设计和验收见[系统评估](../design/system-ux-review-2026-10.md)、[日历v2](../design/calendar-workspace-v2.md)、[就近任务面板](../design/contextual-task-inspector.md)。
