# Daymark 产品哲学与功能定义

UI-32追加：正常任务仅父任务—子任务两层，子任务列表点击直达详情，无空的下级入口；旧深层资料兼容保留，见[当前关系契约](design/compact-navigation-and-subtasks.md)。父子联动规则继续有效。

Daymark把日历的时间安排与提醒事项的执行管理结合起来：先记下任务，再按需要添加属性。简约而不简单，用户无需先搭建一套组织体系，只有标题也能开始使用。

日历新建同样遵守这一点：在所选位置打开任务草稿，标题之外的属性均可选；添加后回到原日历，点击条目再编辑，不自动进入另一页面。小窗依靠层级、对齐和紧凑间距节省空间，文字缩放与完整能力保留。

## 核心模型

| 概念 | 回答的问题 | 规则 |
|---|---|---|
| 任务 | 做什么 | 可独立完成、取消、恢复；可以没有日期和分类 |
| 分类 | 放在哪里 | 任务至多直接归属一个分类；只分一级、二级，不区分其他类型 |
| 标签 | 如何横向查找 | 平级、多选；跨分类筛选，不改变归属 |
| 父子任务 | 如何拆解行动 | 子任务是完整任务，有自己的属性与状态；父任务完成、删除、移动分类会联动后代，恢复保留此前独立处理的状态 |
| 时间与提醒 | 何时开始、何时结束、何时提醒 | 同一对开始/结束可只设日期或指定时间，列表与日历一致；提醒另设，循环生成可独立执行的任务 |
| 特别关注与置顶 | 什么更重要、什么先看到 | 重要性与显示顺序分开，不替代日期、分类或状态 |

软件只保留“分类”这一种归属概念。分类不是需要完成的行动，没有开始/截止、执行状态和完成流程；仅保留名称、说明、层级和归档。已有资料中的历史元数据在兼容层保留，避免升级或导入丢失，不作为当前功能入口。

一级分类可以包含任务和二级分类，点击一级汇总两层任务；二级只显示自己的任务。统一使用文件夹图标，层级由缩进、展开箭头和完整路径表达，不用不同图标暗示不同类型。一级可以降为其他一级的子分类，二级可以换上级或提升为一级；含子分类的一级需先移动子分类，避免出现三级。

## 日常操作链

收集 → 澄清 → 安排 → 执行 → 回顾。分类和标签是可选的整理工具，不能反过来成为录入任务的前置条件。

导航保留分类、标签两个分区。分类树贯通导航、管理、新建与任务归属：分区加号新建一级，一级右键新建二级；所有创建共用一个短表单。右键或键盘菜单直接编辑、移动、排序、归档和安全删除，集中管理用于总览和恢复归档。

拖拽分类到行上/下边缘调整顺序，中间落在一级分类上表示移入；插入线和文字先说明结果。移动保留分类和任务的身份，失败整体回滚。删除分类保留任务，二级提升一级；删除标签只移除标记。

## 同一任务，两种视图

列表负责组织与执行，日历负责查看和调整同一任务的时间。范围回答“看哪些任务”，列表/日历回答“怎样看”；切换不能暗中扩大范围。日历目标职责为：日、周安排具体时段，月看分布与跨日，年用于总览定位；日期任务不等于全天占用，未安排任务不被虚构到今天。详见[日历定义v2](design/calendar-workspace-v2.md)。这是UX-34目标，当前交付仍只有月格/无小时轴周格，实际状态见PROGRESS。没有规划导航分类，也没有另一套可编辑日程实体。

导航顶部由收集箱与今天、计划、全部、特别关注、完成五个自动范围组成六个入口；分类和标签负责整理，收集箱是未分类范围而非分类。日期不改变分类。普通列表可显示/隐藏子任务，以缩进和极简连接线表达；智能视图只列独立匹配的任务，通过蓝色数量链接进入父任务的子任务面板。简易编辑退出先保存，失败保留输入和焦点；展开完整详情继续同一草稿，完整详情显式保存。

## 就近操作的目标

默认详情推荐使用列表/日历共用的就近任务面板，长内容或空间不足时展开同一个编辑器；根任务保留详情/子任务tab，子项在面板内访问和返回，不层层弹窗。只维护一个草稿和命令来源。新面板推荐结束编辑前保存，失败保留面板与输入；现有完整详情仍显式保存，迁移通过后才替换。入口、保存边界及空间适应见[任务面板目标方案](design/contextual-task-inspector.md)，不因采用小窗而删减能力或安全保护。

## 设计取舍

默认界面只呈现当前内容与必要动作，复杂能力按上下文展开。减少重复入口、同义概念、常驻说明和装饰，保留错误、撤销、数据安全和键盘路径。数据可靠和可恢复优先于视觉形式。

界面遵守[原则P-13/14](principles.md)，HIG依据及来源见[UI调研](design/ui-research.md)。最新视图和父子操作见[提醒事项式设计](design/task-list-context.md)及[ADR-017](ADR/017-reminders-views-and-task-trees.md)。基础行为契约见[统一任务系统](design/unified-task-system.md)和[分类与浏览设计](design/catalog-and-list-system.md)，实际证据与平台边界见[进度](PROGRESS.md)。历史规格、ADR与导入格式保留用于兼容，不恢复已经取消的产品概念。

UX-34：列表负责组织与执行，日历负责时间安排；侧栏选择范围，日/周/月/年只是同一范围的呈现。详情默认就近打开，长内容和大字展开同一编辑会话，结束编辑前保存、失败留在原处。见[当前实现索引](design/ux34-implementation.md)。
