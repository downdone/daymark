# UI-81 / ACCOUNT-01 Daymark 界面与账号焕新

设计评审稿。2026-11-10最新范围：**仅在设计稿内，基于现有实现，参考macOS统一UI/UX风格，不做大的交互改动**。全局以§8.11为准，详情以§8.10为准；撤回停靠/大面板及改变原入口顺序的候选。技术映射见[技术设计](daymark-interface-refresh-technical.md)。本轮不改Qt产品、业务、协议或schema，不把原型通过当作正式UI已实现。覆盖 FR-012、FR-018、FR-029、FR-031、FR-034/035、FR-039、FR-042/043。当前证据见[PROGRESS](../PROGRESS.md)。

## 1 功能定义

主窗服务于收集、处理与安排；小窗服务于桌面查看和直接处理；Mini 提供不占空间的当前摘要；悬浮球提供固定入口。四者是同一工作区的不同显示密度，账号中心独立承担身份和同步管理。本地使用是完整路径，登录仅在用户主动进入时出现。

参考图建立了三层操作关系：在侧栏搜索或选范围，在正文处理任务，必要时进入完整属性。选中、编辑、打开详情须分别定义，静态图不能证明触发手势。首轮原型把范围做成窄侧栏里的平铺列表，也把快速录入放成页面横条，削弱了智能视图的层级并把正文压到较低位置。后续精修从完整操作链重新评审，见 §8.3～8.5；比例校准只是其中一部分。截图里的地理围栏、联系人提醒、URL 和图像不进入本轮范围。

## 2 现状、选型与品牌

现有 `Main.qml` 同时编排侧栏、视图和编辑器。焕新后的侧栏保留 Daymark 六个智能范围的卡片入口，重做卡片内部和与下方分类、标签的层级关系。`Theme.qml` 已通过 `DesignTokens.qml` 取值，`WidgetWindow.qml` 已共用 `WidgetViewModel`、形态状态与渲染事务。账号窗口已有登录、注册、资料切换、冲突与重试。Go + SQLite 已实现改密、设备、导出及注销接口，客户端当前缺少相关管理面；托管环境是否启用导出与注销仍以实际 capabilities 为准。

现有主窗有 `TaskEditorSession`、原行快编、列表/日历锚点及离开保存门。`Main.qml` 的 `detailDocked` 继续为 `false`；直接在现有editor Pane、`TaskTimingFields`、`TaskDetailsFields`与选择器上精修。保留原就近定位、边界夹紧、手动移动和用户显式展开，不增加停靠/整页宿主，不给正文扣详情列宽。

保留 Qt 6.10.2 / Qt Quick / Go + SQLite / HTTPS JSON，分批抽出视图区域。品牌沿已定稿的 A 形图标与小写字标，重调产品用色、留白、圆角和动作层级。标识短笔用暖橙保留识别；蓝色承担交互和焦点，橙色在业务界面只表示需要关注的状态。分类颜色局限于图标、标记和标签，名称始终可读。组件默认采用清晰实体表面；透明度作为现有偏好，菜单与编辑层保持实体。

## 3 架构与数据流

`窗口壳 → 导航范围 → 任务列表或日历 → 同一个编辑会话`。导航仅发范围意图；`TaskWorkspace/QueryService` 继续负责智能视图、计数、排序、分类和时间语义。工作区和桌面组件复用同一任务 ID、行视觉角色和既有命令。账号壳使用单独控制器调度身份和敏感操作；`Coordinator` 保留同步编排及资料绑定，网络与凭据不进入 QML。

## 5 协议及兼容

视觉切片没有网络变更。账号管理先接入现有 `/v1/me`、`/v1/auth/password`、`/v1/devices`、`/v1/account/exports`、`/v1/account/deletion-intents`、`DELETE /v1/account` 和删除状态接口。旧服务根据已有能力位显示导出/注销。邮箱验证和找回另设计可选能力端点，如 `GET /v1/account/security-capabilities`；旧服务返回 404 时隐藏相应能力并保留登录。既有 v1 `features` schema 拒绝额外字段，新能力不直接塞入其中。沿 HTTPS/错误码/请求关联，复用官方账号与自定义 URL 两种选择。参考 [v1 协议](../api/sync-v1.md)。

## 6 接口与数据结构

窗口状态 `WorkspaceLayout { availableWidth, effectiveTextScale, sidebarMode, inspectorMode }` 只处理展示；选中任务及草稿属于原编辑会话。布局切换不发保存/新建请求；切任务、切资料、关闭窗口仍按既有保存结果决定是否离开。

账号 UI 状态 `AccountViewState { connection, serviceKind, loginLabel, pendingCount, lastConfirmedSyncAt?, capabilities, action, diagnosticCode? }`。同步时间只接受实际完成确认。设备行复用现有 `Session { id, device_name, platform, created_at_utc, expires_at_utc, current }`。现有改密服务会撤销所有会话，界面明确提示当前设备也需重登，本地队列保留。导出显示准备、下载、校验、保存；下载先验清单/分块散列，再原子写入用户选定路径。注销先备份或明确跳过、确认影响、再输入当前口令并确认；超时后查询同一 `operation_id`，服务端结果未明时显示「确认中」。

后续恢复能力候选：本人认证后请求/确认邮箱；未登录时按账号提交找回请求，统一对外返回是否受理的固定文案；确认口令重设使用短期单次挑战，绑定服务端用户与用途。新动作使用现有诊断体系，不把邮件地址、挑战码、密码和令牌写进诊断。MFA 和 Passkey 作为独立安全切片评审，避免与恢复政策同批替换。

## 7 数据库与事务

品牌、布局及既有账号接口接线复用当前 schema 和资料库；窗口偏好沿设备设置。邮箱与恢复若进入实现，使用独立服务端 SQLite migration。拟增已验证联系邮箱表、挑战表与最小邮件任务队列；邮箱原文受控加密存放，按账号关联，挑战只存摘要、用途、过期、尝试次数和消费时间。若队列需重发，邮件载荷使用独立密钥加密、到期清除。消费挑战、写入口令哈希、撤销会话在同一事务；既有账号无需补填邮箱即可继续使用。

### 8.2 重设计方案

当前实用稿的100%样例取页面标题26、页计数24、任务正文14、导航/卡片标签13、卡片计数20、辅助文字12。卡片约52高，圆底22、内图标13，列间8；细指针单行任务36、带摘要40，粗指针至少44，完成圈16。早期36/32字级由§8.6字体复审覆盖，弹层尺寸/披露由§8.7覆盖，最终密度取舍见§8.8。普通选中保持行高；单击标题直接原行编辑，进入编辑才出现备注和快捷字段，取消另一个「快编→改名称」层级。信息按钮单独打开详情，Esc退出并恢复来源焦点。生产值以DIP作为起点，使用同一字号语义和系统缩放重新实测。

| 区域 | 职责与布局 |
|---|---|
| 顶区 | 侧栏顶端放 Daymark 与搜索；列表／日历、筛选、新建和 Windows 窗口按钮各有固定位置。当前页面的大标题与任务计数同轴，页面切换保持标题和列表起点稳定。 |
| 导航区 | 按内容设最小/推荐/最大宽度，放大不无限扩张。最终原型导航204～248，详情列248～330 px；这些是自主候选，Qt下按有效字号转为DIP并允许调整。初始参考图约27%的构图不作为所有宽度的约束。收集箱、今天、计划、全部、特别关注、完成排成两列三行。每张卡片上部左放彩色圆形图标、右放计数，下部用单行标签标识。分类和标签用次级列表，账号与设置在底部，最近删除保留具名入口。极窄时只保留品牌与「导航」入口；展开搜索/范围、选定后收回，焦点回入口。 |
| 工作区 | 标题与计数下面直接进入任务。新增通过顶区动作或列表内录入，不让全宽常驻输入挤开任务。完成圈、标题、分隔线共用对齐轴，只有已有的日期、分类或提醒才形成次行。列表／日历共享范围且恢复位置。 |
| 详情区 | 使用现有就近小弹窗，按原左右避让和边界夹紧规则定位；自然高度，内容溢出才滚动。打开不挤压正文、不新增整栏背景；窄窗不自动铺成大面板。Esc或关闭走原保存门并回来源；原用户显式展开/移动入口保留。 |
| 小窗 | 页首「范围 + 计数」始终可读。分类快查放在范围按钮内，常用分类按需展现；主体只有任务列表，底部可直接新增。沿用排序、右键、置顶、穿透与恢复通路。 |

### 8.3 从设计目标到操作模型

2026-11-09 深度复审。依据包括用户截图、Apple 当前官方使用指南、HIG，以及 Daymark 自己的产品哲学和既有列表契约。**文档事实、设计推断和自主决定分开记录**：不能从截图推断点击手势，也不能将 Daymark 的像素、断点或对用户效率的预期写成 Apple 的官方要求。下表的「目标」是我们对可观察结构的设计解释，最终仍须用任务测试检验。

| 维度与依据 | 目标与取舍 | Daymark 的具体设计与反例门禁 |
|---|---|---|
| 任务心智模型；Apple 添加指南 [R1] | 先把事情记下来，再补组织与时间，降低开始成本 | 只要求标题。新建沿当前可解释范围赋默认归属；完成/最近删除不接受模糊新增，显式转收集箱并显示目的地。无日期任务不自动塞入日历时段；设置日期不会使任务离开收集箱。 |
| 信息架构；侧栏与分栏 [R2] | 区分「我在看哪一组」「这些任务怎样呈现」「我正在改哪一项」 | 导航管范围，列表/日历管呈现，详情管单项属性；搜索是明确的结果范围。分类单归属、标签多归属、关注和置顶各有含义。列表与日历切换不偷偷重置范围，计数必须说明同一筛选交集。 |
| 注意力；布局与披露 [R3] | 扫读正文时不需要遍历所有可编辑属性 | 默认无详情、无常驻全宽新建框；任务显示标题与已有信息。日期/标签/关注在原行编辑时出现，完整详情按需打开。频繁字段前置、截止与重复再披露；有值的高级字段即使折叠也有摘要，不能隐藏既定事实。 |

| 连续录入；Apple 添加指南 [R1] | 降低每项重复定位和鼠标往返 | 新建/列表末尾进入同一个连续草稿，Enter 提交成功后停在下一项，空白不创建；选中现有任务后有继续新建命令，Windows 采用自身快捷键，输入法候选确认不提交。布局迁移不清空输入。 |
| 扫读与信息密度；列表与排版 [R4/R5] | 正文容易从左到右定位，辅助信息不会和标题争注意 | 完成圈→标题→信息按钮三条稳定轴；父子展开槽独立。分类范围内不逐行重复同一分类；空值不拼占位分隔符。标题允许必要换行，已有日期/标签形成次行。字号使用语义角色，不因放不下把必读字压到 10px。 |

| 色彩与材质；色彩 [R7] | 色彩表达身份和状态，低噪声表面帮助阅读 | 中性正文、稍低亮度的导航/详情、蓝色交互、暖色关注、红色错误。导航类别色仅小面积身份标记，配具名标签；选中是柔底，键盘焦点另有轮廓。菜单与编辑表面实体，避免重演透明菜单/黑条问题；不把 Liquid Glass 当跨平台目标。 |
| 时间与提醒；Daymark P-04 | 用户能区分计划日、截止、时段和真正会触发的提醒 | 同一 `TaskTimingFields` 展示开始、截止、可选时段、独立提醒和重复。只有日期的任务不自动触发午夜提醒；相对提醒须有可解释的时刻基准，指定提醒可独立设置。时间识别先建议、手动优先，实际触发仍使用 UTC 瞬间。 |
| 层级与批量；Apple 子任务指南 [R8]、Daymark UX-37 | 个人清单能从几项增长到项目，批处理不产生隐含影响 | 普通范围可展开两级子任务，智能范围平铺实际匹配项、显示父名/子项入口。分类也只两级；不把分类导航和任务树混成一种层级。Ctrl/Shift 选择、箭头导航、可见范围全选，显示选中 N/影响 M；集合内右键作用集合，集合外先单选；任务 ID 保持锚点。 |
| 反馈与恢复；设计原则 [R6] | 不怕误点，也能理解操作是否真正完成 | 完成/软删提交成功才反馈且可撤销；原行编辑、详情、导航统一经过保存门。失败原处保留草稿与焦点，读写忙碌有说明。加载、空数据、搜索为空、过滤为空和服务错误各自有恢复动作；不能以绿色文字模拟真实持久成功。 |
| 键盘、辅助与本地化；输入/排版 [R4/R5] | 让鼠标、键盘和读屏对同一任务产生相同结果 | 选中、焦点、编辑、完成是独立状态；文本焦点内保留文字快捷键和 IME。信息按钮有任务名，完成公开状态，覆盖层约束焦点并准确返回来源。200% 字号、高对比、长中文/英文/多位计数/RTL 单独验收；悬停不是必要入口。 |
| 四种形态；Daymark 产品哲学 | 按注意力占用逐级提供能力，用户明白每种形态为何存在 | 球是入口，Mini 是摘要，小窗是执行，主窗是整理/安排。共享桌面任务范围和语义，主窗范围独立；各形态可禁用、有明确切换。菜单、输入、草稿、拖动时保持形态；动画保持共同锚点，失焦回收不吞动作。 |

| 链路 | 正常路径 | 中断、错误与退出 |
|---|---|---|
| 临时想起一件事 | 主窗新建或小窗底部 → 标题 → Enter → 下一条；之后补日期/分类 | 空标题不写入，IME Enter 不提交；非空新草稿退出按保存门，不静默丢弃；存储失败不清输入。 |
| 连续整理收集箱 | 点击标题原行编辑 → 备注/常用字段 → 离开提交；需要更多再点信息 | 原行和详情使用同一草稿，打开详情不先保存再重读覆盖；切换目标先处理前一会话。失败仍停原任务，列表查询结果改变后给有效位置。 |

生产状态至少分为 `currentTaskId`、`selectedTaskIds`、`selectionAnchorId`、`editorTaskId/draft`、`inspectorOpen` 和 `captureDraft`。不能再用一个 `selected` 变量同时决定高亮、完整详情和编辑身份。列表控件接管方向键；文本字段内保留文本行为，焦点变化不等于提交命令。原型只演示其中交互，不替换既有 C++ 状态与事务。

### 8.6 字体、字号与显示尺度复审

2026-11-09，用户反馈整体比 macOS 大。覆盖 P-13/15/17/18/21，UX-01/02/04/05/10/11/79/80。**审计结论：上一稿的标题和垂直节奏确实偏强，不能全归因于屏幕；正文没有依据整体缩成小字。** 本轮只修原型与契约，不改正式 Qt token、用户文字偏好、协议或数据库。

#### 判断尺寸的四个层次

1. **逻辑字号与设备像素。** Win32 只读测得本机主屏 2560×1600 / 150%，另一屏 2560×1440 / 125%，Windows 辅助文字比例 100%。例如 14 DIP 的 em 分别对应约 21 / 17.5 设备像素，字形实际墨迹高度还取决于字体。这不能直接推断两块屏上的物理毫米大小：还需面板尺寸、PPI 和观看距离。本轮未读取用户资料库，Daymark 内部文字偏好及聊天宿主缩放未据此认定为 100%。
2. **截图与显示倍率。** 用户参考原文件 2112×1246，PNG 中约 72 DPI 是图片元数据，不能拿来确定 macOS 的显示缩放。截图在聊天中还会缩放展示。未获得原 Mac 的 backing scale、辅助文字偏好和窗口逻辑尺寸，因此不声称精确还原 Reminders 的字号。
3. **字体 em、可见字形与行框。** `font-size=14` 不代表墨迹恰好高 14。字重、CJK 字面、数字宽度和行高都影响观感。上一稿 CSS 的混排实际由两种字体绘制，而正式版使用同一字体；字号相同也不等于同一文字管线。
4. **板块的比例与留白。** 大标题、页计数、卡片标签普遍加粗，配上 1.5 倍默认行高和 44 起步的控件，会让整页显得放大。应按角色恢复层级、压掉叠加行距，保留正文可读性与点击热区。

Qt 6.10 的界面和 QML `font.pixelSize` 使用设备无关坐标，DPR 再负责光栅化。当前 `main.cpp` 明确 `setPixelSize(13)`，字体 token 用 `pixelSize` 和应用文字比例；审计未发现 QML 文字再乘 `devicePixelRatio`。不能为追求小字把系统缩放除回去。[Qt 6.10 High DPI](https://doc.qt.io/qt-6.10/highdpi.html)

**单位陷阱：** AppKit 所说的 point 是其界面的逻辑度量，不能直接作为 CSS `pt` 或 Qt Windows 的 `pointSize` 输入。CSS `13pt` 在标准 96 DPI CSS 坐标下约为 17.33px；Qt pointSize 的换算还受逻辑 DPI 影响。当前正式版不是这种误用，焕新稿也保持 CSS px / Qt DIP 的实现边界。

#### 官方基线与产品自主选择

已只读核对 Apple 官方 `typography.md` 的 macOS 表：Large Title **26/32 pt**、Title 1 **22/26**、Title 2 **17/22**、Title 3 **15/20**、Body **13/16**、Callout **12/15**；这是 HIG 字体角色基线，**不是该 Reminders 截图的取样结果**。Windows 11 官方 Text 基线为 **14/20 epx**，Small 为 **12/16**，Title 为 **28/36**。因此 Windows 中文正文选择 14，配 12 的辅助信息有明确理由，不机械套用 macOS 10pt caption。[Apple HIG Typography](https://developer.apple.com/design/human-interface-guidelines/typography) · [Microsoft Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)

#### 字体家族与字重

- Windows 校准稿与正式版对齐：`Microsoft YaHei UI`，缺失回退 `Segoe UI` / 系统字体；中英与数字先走同一家族。macOS 使用平台系统 UI 字体及 CJK 回退，不分发 Apple 字体、不把雅黑优先级带到 Mac。
- 上一稿 CDP 实际字体证据：中文标题为 `MicrosoftYaHeiUI-Bold`，任务中文为 `MicrosoftYaHeiUI`；混排元数据同时使用 `Segoe-UI-Variable-Text` 和 `MicrosoftYaHeiUI`。校准后同一元数据行全部为 `MicrosoftYaHeiUI`。CSS 声明列表不作为实际使用字体的唯一证据。
- 正文 400，轻量身份/摘要 500，主要标题/选中 600；不再普遍用 700～750。微软雅黑 UI 在本机没有所有中间字重，浏览器会选择可用字面；例如选中卡片的 600 实际仍为 Bold。不能只改 `font-weight` 数字就宣称产生了新的真实字重。
- 中文不套用上一稿给全部标题的 `-.045em` 字距；默认字距，必要的拉丁光学校准独立处理。计数只在需要列对齐的地方使用等宽数字特性。

#### 各板块字体角色（100% 候选）

下表为 Daymark 自主值；「字号/行高」用逻辑 px 表达，Qt 实施按自然字形度量验证 DIP。字号变化不修改 OS 缩放和用户文字比例。字号不等于图标尺寸，也不等于命中区域。

| 区域/角色 | 上一稿或正式版事实 | 校准候选与理由 |

#### 垂直节奏与可访问性

实测上一稿双行任务为 **49px**（标题21 + 摘要18 + 上下padding10），虽声明最小44，实际内容已更高。校准为 **40px**（标题20 + 摘要16 + 上下padding4），正文14和摘要12都保留。最终无摘要行36，普通选中不额外撑高，原行编辑为新增字段自然增高。导航卡片最终52、工具区40；不通过全窗 `zoom` 缩小。

36/40是细指针桌面浏览候选；粗指针的有效行/按钮热区至少44，编辑字段至少16px。生产的200%文字必须联动自然行高、容器留白、分栏和可达滚动；不以固定行高或减少字体抵消用户缩放。

原型提供「实用排版 / 初稿对照」切换，以同一合成任务和窗口作字级/密度对照，不重建任务、选择和草稿，也不代表切回历史版本全部行为。比较时先统一外观、窗口宽度、宿主缩放，再比较各角色；物理大小与macOS实机字体仍单独验证。本轮无macOS实机，不能宣称字体栅格化与原生Reminders等同。

### 8.7 弹出层紧凑性复审

用户追加：macOS 的弹出窗口紧凑，而稿件巨大。问题需要同时审查信息量、容器职责和默认展开状态。**已确认的宽窗停靠/窄窗覆盖继续保留；任务详情、单属性选择器、确认对话框不能共用「大表单」尺寸。** [HIG Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers)要求临时层聚焦少量相关任务、大小适合内容、指向来源、避免级联层，非模态自动关闭保护编辑；[Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)要求简短明确的标题、必要说明及具体动作。这些是原则，下面尺寸为 Daymark 自主候选。

#### 问题与责任分配

- 稿件详情按「每组一个 legend + 每字段一行输入 + 10px 组间隔」构成，未设置属性也占完整行，备注还有最小高度。紧凑不能只换小字号，应先让已设置值直接可读、编辑控件按意图出现。
- 正式源码的独立问题也须在实施中覆盖：`CatalogPicker` 宽度 `320*scale`、高度至少220且用固定基础预算推算；`DatePickerDialog` 使用 `360*scale × 460*scale` 上界；`TimeRangePicker` 使用 `460*scale × 620*scale`。这些不等于每次实际尺寸，但说明不能只迁移新的字体 token。普通小表单不应继承完整时段编辑器的预算。
- 容器、头部、正文和底部各自 padding 不能叠成多圈。弹层外缘10～12，字段间4，属性组间8～12；只有一个容器拥有相邻留白。标题采用15～17，正文13～14，辅助12，靠层级而非巨大标题建立主次。
- 字体增大需要给字形和必要内容留空间；不能简单把所有默认宽高乘文字比例，也不能把宽度锁死再裁字。按测量的标签/值/控件最小宽与窗口预算重排，放不下时转换承载，确实超出才使用一条正文滚动轴。

#### 当前原型的具体收敛

备注按内容利用24起步高度，长内容仍可编辑；标签为紧凑具名项，保留可访问组语义；安排默认显示「今天10:30」或「添加日期」，展开才显示日期/时间控件；提醒不藏到二级菜单。截止/重复折叠后也显示已设置值。属性控件视觉行收敛到24～28，常用表面组间6，表单固定上沿。选中任务改变只换数据，展开态按用户意图保留，不用每次重开来伪装变小。窗口很窄、大字和粗指针仍恢复必要命中空间。

单属性选择器不得从详情再弹出多层详情；同一时刻仅一个临时选择器。选择器 Esc 先关闭并回到原属性，详情 Esc 再经保存门返回来源；点击另一个属性可在保护草稿后一步换目标。外点关闭提交合法编辑，非法/失败留在原处并解释。菜单/弹层实体与平台 Z 序继续沿原原生链路，不能因紧凑重引入透明和黑条。

#### 紧凑菜单的可操作样例

原型右键任务或Shift+F10/Menu键可打开同一个实体菜单：任务详情、编辑名称、安排日期、特别关注、完成/恢复。§8.9修订后短样例为176×149，宽高按内容计算，只有相关命令；多选集合内改为完成所选/取消选择，集合外先选择正确任务。空白右键不打开面板命令，文字字段保留输入上下文。方向键/Home/End定位，Enter执行，Esc/Tab关闭回来源；切布局/场景及窗口resize关闭临时菜单，不抢走外点目标的焦点。

菜单开启动作通过同一草稿保存门，非法标题阻止导航；点击动作复用现有原型命令，完成可撤销。关闭与打开另一个菜单不新建任务。示例只验证常用命令组织与交互，不替代真实存储、父子级联、删除/置顶等完整业务验收。

**尺寸计算澄清。** 前轮194×149是五项样例的测量结果，194是当时的示例宽度；§8.9已将当前宽度改为内容测量、176下限及320/视口上限。原型没有显式height或整块min-height：5项含分隔149，隐藏一项123，多选的2项无分隔62。26是普通单行项的最小/基准行高；放大字、较高图标或自定义内容应按自然尺寸增长，不能硬裁到26。

`Hnatural = 上下内边距 + Σ可见项自然高度 + Σ有效分隔高度 + 边框`；`Hvisible = min(Hnatural, 可用工作区高度)`。短菜单不额外铺底，只有溢出才滚动；隐藏项不占位，禁用项仍显示并占位，空分组不保留孤立分隔。宽度测量最长标签与状态/快捷键/箭头列，再受内容下限和工作区上限约束。AppKit的[NSMenu.size](https://developer.apple.com/documentation/appkit/nsmenu/size)为只读尺寸，[minimumWidth](https://developer.apple.com/documentation/appkit/nsmenu/minimumwidth)默认0，系统可为内容留出更多空间；这些接口不意味着应用应硬编码全菜单高度。

正式QML命令菜单已经按可见项implicitHeight求和，但480固定上限仍需结合工作区预算。`CatalogPicker`则是另一类属性选择器，当前至少220且按原始options.length计算，而非搜索后的matches；这会导致少量结果仍留白。其后续改造按§8.7使用实际可见结果、必要搜索/动作区和可用高度，不能把命令菜单的行高规则直接套成整块固定高度。

生产实现沿现有平台端口优先系统菜单；系统字号、行距、键盘和层级由OS管理，不强行把所有平台改成194×149。只有QML回退使用本节密度。原型用HTML顶层实体菜单展示关系与输入，不能据此宣称Win32/Qt原生菜单、DWM瞬态或macOS菜单完成。

#### 宽度与状态门禁

原型导航由204～248范围控制，在1008px主窗样例中约232；工作列约512、净内容约480，详情卡约256。以可读内容预算决定宽窄承载，不将原图27%当恒定比例。普通任务切换保留行高、标题区和详情上沿；只有明确编辑/披露才局部增高。长标题、空分类、选中/多选、已完成、深浅色、320px和粗指针均进入原型验证。

本轮尺寸/菜单组织可作为常用主窗切片的实施输入；日历四尺度、完整时间语义、两级层级和真实账号状态仍按既有队列单独闭合。整体UI-81/ACCOUNT-01不能因本节原型通过而标为完成。

macOS借鉴范围是标题/备注前置、字段轻边界、清楚分组、紧凑菜单与按需选择。来源图和Apple指南不替代Daymark时间语义，不要求增加地点/联系人等字段。原型采用日期/时间原生输入演示局部关系；Qt正式实现继续使用现有选择器。

正式实现沿现有420 DIP上限和可用空间约束，先精修内部排版；原型360仅演示小弹窗关系。高度按内容与工作区限高，保持独立实体边界和轻阴影；不占正文布局槽。宽/窄窗均沿现有Popup定位和选择器链，不自动停靠或铺满；现有PopoverSurface来源箭头/手动移动继续按原逻辑处理。

本轮原型保留两种已有提醒来源的区别：指定提醒在“提醒”，提前提醒在“时段”。移除时段基准会清除依附的提前提醒并说明影响，独立指定提醒保持；撤销恢复整组草稿。该演示不改变正式数据模型，生产仍由原schedule/null与remindAtUtc字段分别处理。

全面评审发现并收敛三类风险：一是原型的“截止与重复”混合折叠偏离已有字段；二是fixed 520/400等选择器预算制造无效底部空白；三是重排过程中易复制草稿、误清独立提醒或将日期投影写回。技术设计将它们列为实施门禁。账号完整能力保留在原队列，本轮不顺带扩展服务端或schema。

## 9 可靠性、隐私与性能

宽窄换位复用编辑器，守住 IME、选中、光标和未保存状态。窗口形态不重建工作区、资料库或任务模型；未打开详情或小窗时不维护隐藏场景树。弹层实体和窗口边框保持独立。桌面锚点、菜单焦点和点击穿透按原原生链路验收。

同步数据、账号会话、本机保留副本分开表达。撤销设备须明确目标；当前设备走退出路径。注销本机副本遵循独立本机确认，云端操作不连带擦除本地草稿；备份保留期限以实际部署政策呈现。找回走频控、统一响应、短期单次挑战、审计脱敏；邮件配置经部署单独启用。沿用用户既有至少 8 字符的产品策略，本轮不把它表述为满足 [NIST 单因子密码要求](https://pages.nist.gov/800-63-4/sp800-63b.html)。

## 10 测试与验收

- 设计稿测卡片网格、字号、图标与完成圈；详情按现有小弹窗验证左右避让、边界夹紧、自然高度、长内容滚动、焦点返回、草稿与窄窗。打开/关闭不能改变正文宽度和起点，不自动进入大面板。加测搜索清除、工具栏/分类新增、日期/标签、浅深和空态。合成原型的验收不计入Qt产品测试。
- 单测：色彩对、布局分段、共享草稿不变、形态禁用/焦点保持、账号状态映射、会话来源绑定、能力回退。服务器测试越权、重复确认、令牌重放/过期、撤销及迁移回滚。
- 集成：Windows `window_chrome`、`title_bar_layout`、`task_list_interaction`、`calendar_interaction`、`desktop_surfaces`、`account_access` 按切片复用。用临时库跑真实 Go TLS 双端：登录、改密、设备撤销、导出校验、注销状态恢复。恢复切片用测试邮件适配器验证失败重试、迁移和撤销。
- 用户链：本地新建 → 收集箱/今天 → 详情宽窄迁移 → 小窗快查 → Mini/球 → 登录后同步。浅深、高对比、键盘与大字回归；记录闲置与操作时内存和帧表现。最终正式 Windows 候选跑一次完整 CTest，再走现行发布门禁。

## 11 自审结论

当前详情以§8.10的现有就近小弹窗为准；此前停靠/覆盖评审已被用户最新要求替代。主窗双列智能范围卡片、字级层级与品牌几何保留，表面为中性浅色/炭灰，蓝色承担操作和选择。账号管理与恢复分批进入实现。原型只验证局部关系；Qt原生焦点、混合DPI、性能和真实账号服务分别验收。

### 前轮精修评审（历史；下方深度复审修订覆盖相应规则）

| 问题 | 修订 | 原型验收 |
|---|---|---|
| 选中任务自动多出五个动作，后续行上下移 | 普通选中仅增加色底、细标识和固定槽位的快编入口；明确快编后展开 | 比较切换选中前后的全部行高；Esc 收起后焦点回快编 |
| 工具栏临界宽度换行影响标题起点 | 常见宽度固定 48 px 工具区，次要日期只在有空间时出现；筛选有持久标签 | 1024 px 视口下实测工具区 48 px，标题/正文起点稳定 |
| 详情长标题与关闭按钮争夺同一行 | 固定详情头负责关闭，标题独立并自然换行，备注与属性分组 | 长中文标题完整换行，箭头与来源完成圈中心误差 1 px |
| 320 px 下完整侧栏挡住首屏正文 | 紧凑导航按钮展开范围；Esc 或选范围后收回 | 操作前标题在首屏，导航返回焦点明确，主窗/组件/账号无横向溢出 |
| 完成任务或退出标签范围后焦点失效 | 完成后转到相邻完成控件；无相邻行时落到新建；关闭详情回来源行 | 完成、恢复、移出当前标签和宽窄切换分别验证 |
| 标签「待评审」与特别关注误共享状态 | 标签和旗标单独存放原型状态，分别编辑与筛选 | 取消关注后标签范围保持；移除标签后详情关闭并落到有效入口 |
| 安排只有时间，日期和当日任务含义不清 | 补日期字段，日期与时间分开；有日期无时间也进入计划 | 测试仅设日期的任务及其日期摘要 |

本轮单代理自审在上轮专门设计 agent 的稿件上执行。原型里的日期使用固定合成样例，日历切换仅展示信息层级，账号动作是具名演示反馈。实际日历、复杂层级、账号服务与原生窗口的验收进入相应实现切片。

### 产品哲学复审

依据 [产品哲学](../product-philosophy.md)、PRD §0.1 与 [体验目标](ui-baseline.md)「安静、清楚、可靠、顺手」复审。macOS 参考图用于建立视觉层级，是否保留某个区域取决于下面的任务链和可读性。三栏比例是宽窗样例，实施时按各区最小可读宽度、用户调整及字号决定实际尺寸。

| 产品目标 | 设计约束与修订 | 验收实例 |
|---|---|---|
| 先记录，再整理 | 收集箱维持优先可达；列表尾有轻量「记录任务」，一行标题即可提交。分类、日期、提醒及账号全部可选。仅浏览时默认不打开详情。 | 访客启动后直接记下一项无日期无分类任务，关闭重开仍存在；取消新建零写入。 |
| 收集→澄清→安排→执行→回顾 | 导航选范围，正文完成与快编，详情澄清属性，日历安排时间，完成/最近删除支持回顾。新增分类不抢过任务入口。 | 一个任务从收集箱补日期后仍在收集箱，切到日历显示相同 ID；完成后可回顾与恢复。 |
| 同一任务，两种视图 | 列表/日历共用范围、筛选、身份与草稿，切换保留原范围和各自位置。日历需明确未安排任务、日期任务与时段任务，支持日/周/月/年，不能用纯任务列表冒充日历验收。 | 分类范围下从列表切周视图，只出现该范围的任务；无日期任务仍可被找到，安排失败返回原任务。 |
| 简约而不简单 | 默认正文用于浏览。单击选中不改变行高，快编与完整详情按意图进入；详情只挂载一份。空态区分无任务、无搜索结果和筛选为空，并提供合适的恢复动作。 | 依次选中任务，后续行不移动；筛选为空可直接清除，不要求去新建。 |
| 时间语义清楚 | 详情完整设计必须保留开始、截止、可选时段、独立提醒和循环规则。原型日期/时间只演示入口位置。识别到时间先提供可解释建议，手动输入优先，未安排不默认算今天。 | 无时刻的日期任务不占满日历；只有标题时不自动安排；跨日和 UTC 提醒沿现有测试。 |
| 本地优先与用户控制 | 账号是可选服务。主窗不放注册营销或同步计数看板；普通离线不阻断任务录入，未上传修改在账号中心解释并可恢复。 | 不登录、断网仍能收集、安排和完成；切账号前保护草稿，退出保留本机资料。 |
| 四种形态各有职责 | 主窗整理与安排；小窗直接查看/快加/完成，保留分类入口；Mini 提供当前桌面范围的计数与首项摘要；球只作可恢复入口。三种桌面形态共享桌面范围，主窗的浏览范围独立保留。 | 主窗切到完成不会把小窗也切成完成；Mini 和小窗摘要一致。球临时展开后只有在无草稿/输入/菜单/拖动等保持状态时才收回，回到原停靠点。 |
| 可靠与可恢复 | 完成反馈绑定成功提交，提供撤销；保存失败原处保留草稿和焦点。需要确认的删除/注销单独表达影响，错误可见且可采取动作。 | 完成后撤销恢复原状态；服务超时不显示已同步，重试不会重复新建。 |
| 品牌清晰、可靠、轻盈 | 小写字标与短笔负责身份；蓝色用于交互，导航分类色局限在图标。内容区保持中性、稳定留白和清楚字体。默认跟随系统浅深色，深色图用于评审对照。 | 浅深色对比、200% 文字、键盘和普通 Windows 窗口边界都可读；品牌图形不作为完成/同步状态。 |

结论以§8.10最新要求为准：详情使用已有就近小弹窗，撤回宽窗停靠/窄窗大面积覆盖。产品职责与其余操作约束保留；日历、完整时间、多选级联、分类和账号服务仍按原功能契约实施验收，不能用局部原型代表全部完成。

### 深度复审修订（替代上面的快编入口与浮动详情规则）

独立设计 agent 只读复审指出与 UX-37 的直接冲突：标题整行打开详情、信息图标只是装饰、「快编→改名称」多一层操作。原型已改标题直接编辑、行空白选择、独立信息按钮、Ctrl/Shift 多选/方向键；完成和撤销仍为合成内存交互。多选时完成圈改为选择方框，信息入口禁用，避免把选择误做完成。合法标题 Esc 提交并退出，放弃修改有明确按钮；空标题阻止切范围。右侧表单固定上沿，来源由任务选中与信息入口表达；导航和详情限制上限，320px 工具区收敛到单行。标签前置、子任务单独披露，未安排不强制时间，独立提醒有自己的入口。复杂重复规则、时间段、父子事务和 Qt 保存失败仍未由该原型验证。以上以 §8.3～8.5及§8.9作为当前规则，不保留互相冲突的旧行为。

实际Chromium鼠标输入发现失焦提交后立即收起编辑行，会让下方目标在按下/松开之间上移而吞掉首次点击。已将数据提交与呈现收敛分开：手势结束前保留目标几何，后续动作稳定接管；键盘离开也保留有效焦点。长范围标题保持单行度量，截断时可查看完整名称；宽窗详情长标题则允许自然换行。§8.9进一步明确停靠详情不用来源箭头，以选中与信息入口表达关联。这些须带入Qt宿主评审，浏览器修订不代表Qt同名故障已修复。
