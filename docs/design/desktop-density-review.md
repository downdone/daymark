# UX-37D：全局桌面密度复审与统一方案

UX-48将本页桌面密度扩展为[统一视觉系统](global-visual-system.md)：实际文字角色/半径/线框与图标源按新系统，紧凑/舒适、功能和输入契约继续保持。

2026-10-26。用户追加截图指出侧栏与任务详情紧凑程度不统一，要求全局分析、偏macOS的紧凑体验。本文扩展[任务列表复审](task-list-interaction-review.md)，为本轮已接受的全局实现契约；代码覆盖与验证边界见文末，真实状态只见PROGRESS。

## 1. 结论与范围

采用一套桌面密度系统：按同一字级、基线、属性行、控件视觉尺寸、命中区域及间距组织导航和内容。内容复杂的面板仍可更高，但同类控件不能在不同页面换一套密度。紧凑首先来自相关信息同排、消除重复说明、按需展开、减少多层padding；文字保持可读，独立操作不互相重叠。

覆盖主窗导航、任务列表/原行编辑/详情、日历及新建面板、日期/时间/分类/标签选择、右键/更多菜单、设置、组织管理、提醒记录、数据工具、桌面日历/小窗/mini条。系统菜单/标题栏使用实际运行平台的机制；Windows保留Segoe UI/系统字体与Ctrl习惯，不复制macOS标题栏或Apple专有资源。

HIG依据：[Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)关于大屏、精确输入、快捷键及舒适信息密度；[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)关于分组、对齐和可适应性；[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)关于命令分组和稳定位置；[Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers/)关于少量相关内容及来源关系。以下所有DIP/毫秒为Daymark候选值，不是Apple官方尺寸，也不承诺Qt具备Liquid Glass原生材质。

## 2. 截图问题与源码根因

| 问题 | 已核实的结构 | 修改方向 |
|---|---|---|
| 左侧信息紧、右侧表单松 | 导航12DIP/32行，SmartViewTile最少60；详情标题16，备注最少40，表单按字段上下排列 | 保留文字层级，统一行节奏和内边距；语义属性同排 |
| 详情日期不能有效并排 | 默认Pane最大420×scale，内部再扣边距；editorDatesGrid要求内部可用宽≥440×scale才双列 | 默认详情使用“标签＋值”的单属性行；展开时按内容最小宽度决定组合，移除不可达断点 |
| 顶部多层标题消耗空间 | 通用“任务”头部、详情/子项分段、可编辑标题分别占层 | 紧凑详情将实际任务标题并入头部；仅有子项或正在管理子项时强调分段，添加子项仍有直接入口 |
| 空备注也形成明显留白 | 备注最少40；外层Control padding12，详情Section padding8/6，字段spacing4/6/8叠加 | 空备注一行占位；只在同一容器边缘保留一次外边距 |
| 大量行先有label再有输入框 | 开始/结束分别Label＋RowLayout，日期时间又有局部容器 | 开始/结束使用固定标签列，日期与时间同排；同日时允许一条完整时段摘要 |
| 日程选项显得像设置表 | 指定时间开关、时区与提醒选项复选框、循环开关及其字段继续堆叠 | “时间/重复/提醒”分别为有值的属性行，点击就近编辑，规则细项按需出现 |
| 紧凑设置不全局生效 | Theme.compact主要改变TaskRow下限及少数fieldGap/controlHeight；大部分32/60/6/8/12等仍局部写定 | 引入语义density token，迁移共享控件及所有宿主，集中验收 |
| 分段条显著重于导航行 | SegmentedPicker直接使用通用Button高度，再加padding3；选择器不区分工具栏/表单角色 | 分段控件共用桌面尺寸；宽度按标签，不无条件拉满可用宽度 |
| 边框密度高 | 文本字段有框、分段选中项有框、详情整体有框，Section还加分隔线 | 分隔只放在一处：控件边界、分组分隔或容器边界按角色选择；不叠加装饰层 |

截图可能经过DPI或图像缩放。以上使用源码逻辑尺寸，不从附件的物理像素直接反推字体或窗口DIP。当前QML使用系统字体，不能把平台字体渲染差别误当为所有字号未定义。

## 3. 统一token与排版规则

以“紧凑桌面”为默认目标，保留舒适密度。密度与文字大小为两个独立维度；200%文字不得被compact压回小字号。

| 角色 | 紧凑目标（100%文字） | 跨页面规则 |
|---|---|---|
| 主工具栏 | 40高；标题16～18 | 同一位置、同一图标/动作分组；页面大标题仅内容需要时使用 |
| 导航普通行 | 32高；正文13、分区12 | 图标16；名称/计数同基线；一级二级共用行高 |
| 六入口智能卡 | UX-41修订56起；名称12、数字16 | 默认两列，大字单列；8～10内边距、4关联间距，名称正常/选中半粗，不改导航语义 |
| 任务列表行 | 单行36起、双行44起 | 舒适为40/48；标题14、摘要12；只一个稳定关系图标槽 |
| 表单/属性行 | 32起；正文13、标签12～13 | 标签和值同排；同组标签列72～88，中文长标签按内容重排 |
| 控件视觉表面 | 26～28高 | 输入/动作所在命中区域至少32，视觉表面与交互区域分开；禁止命中范围互相侵入 |
| 分段按钮 | 视觉26～28，宿主32起 | 表单/工具栏使用同一尺寸角色，按内容宽度；窄窗可换排，不能压文字 |
| 详情头部 | 实际任务标题16，工具图标16 | 关闭/返回、标题、展开/更多同行；不重复通用“任务”大标题 |
| 小面板/菜单正文 | 13；辅助说明12 | 不因为容器小就降到10/11字号；多行错误自然增高 |
| 容器边缘 | 12；密集局部8 | 只扣一次；容器内公共对齐线一致 |
| 间距 | 2/4/8/12/16 | 2局部、4标签关联、8组内、12分组、16主要区域；避免各层都加12 |
| 圆角 | 控件6、行/分组8、浮层10～12 | 由容器层级决定，不能同屏出现随意的多个半径 |
| 图形 | 正文16、工具栏18 | 同角色描边/视觉重量一致；较小图形置于32命中区 |

字号和行高须有统一最小值及根据字体度量增高的规则。截图首版按这些候选值验证，实际几何优先于表内数字。现有紧凑偏好全局化时保留用户已选择的舒适模式，不无提示覆盖保存值。

色彩继续使用集中Theme，优先调整用途关系：背景轻中性、内容面实色、选中浅强调、主动作实强调、危险动作独立红；边界只在必要处增强。普通图标不用每个都带彩色圆底，语义色只在导航类别/状态等确有信息的位置出现。父子任务不能只靠颜色区分。

## 4. 这张图的详情目标

拟定紧凑首屏骨架：

```text
┌────────────────────────────────────────┐
│ ×  讨论方案                        ↗ ⋯ │
│    添加备注…                           │
│ [详情] [子任务 2]（有关系内容时强调）      │
│ ────────────────────────────────────── │
│ 时间    10月26日  09:00 — 10:00      › │
│ 提醒    无                            › │
│ 重复    不重复                        › │
│ 分类    时间工作区验收                 › │
│ 标签    添加标签…                     ＋ │
└────────────────────────────────────────┘
```

“时间”行显示完整同日时段；跨天显示完整起止日期，不能为了短而隐去关键日。点击展开同一容器中的开始/结束两行：`开始 [日期] [时间]`、`结束 [日期] [时间]`；全天/指定时间选择就近提供，不再将“指定时间”和字段铺成分散的表单层。提醒、重复亦先显示值，点击直接选；自定义时才展示更多参数，时区入口保留在时间编辑中。

简单任务目标约300～360高，有时段/子项的常见任务约360～420；这是待测目标，不是固定height或隐藏字段的借口。长备注/子任务/错误仍允许自然增高，容器受窗口约束，正文单一滚动。键盘焦点进入时不得切断必要信息；展开仍为同一草稿，不重新加载或改变保存协议。

## 5. 全局表面迁移矩阵

| 表面 | 要收紧或统一的内容 | 要保留的行为 |
|---|---|---|
| 侧栏 | 卡高度/内边距、分区间距、分类标签行的文字图标基线 | 六入口/两级分类/分区折叠、拖放、窄轨恢复 |
| 列表/原行编辑 | 同一标题/摘要字级、固定图标列、常用属性小按钮同高度 | 多选模型、父子联动、完成反馈、文本选择/IME |
| 任务详情 | 实际标题合并头部、空备注一行、属性和值同排、按需编辑 | 同会话、失败草稿、父子返回、原子保存 |
| 日历主窗 | 主栏/日历栏的高度和动作分组；周标题/全天区按内容占高 | 时间轴尺度、跨日条及冲突泳道不能靠压缩来省空间 |
| 日历新建/日期时间选择 | 与详情共用属性行；日期/时间/提醒只一层编辑 | 新建不预写空任务、事务提交、取消零残留 |
| 菜单/分类标签选择 | 同一字级、32起行高、统一图标槽/分隔/选中反馈 | 键盘导航、当前值、滚动/边界避让、立即打开 |
| 设置/组织/提醒记录 | 统一标签列和组内行高；说明按需，长内容自然布局 | 立即保存状态、错误修复、真实历史/恢复路径 |
| 数据工具/确认 | 按操作分组，主次按钮同尺寸，危险说明充分 | 数据丢失影响必须明确，不为紧凑缩短确认链 |
| 小窗/mini/独立日历 | 标题栏与正文使用相同字级/图形角色，控件边缘一致 | 置顶/穿透恢复、透明度、mini可读性与独立窗口身份 |

相同密度不等于所有容器高度一致。日历空白表示时间，正文留白表示阅读；必须保留的空间不按“控件越多越好”的标准压缩。可折叠功能不可为了减少首屏高度完全消失，仍需可发现入口。

## 6. 实施顺序及验收

这是UX-37的全局约束；选择/关系/响应三片保留，UX-37D不单独变成一次性全UI重写。

1. **D0 标准件与基线**：DesignTokens/Theme定义density角色，记录现有屏幕几何，调整共享按钮/字段/分段/属性行，先在列表与详情连通一个样板。
2. **D1 同屏统一**：侧栏、列表和紧凑详情同屏比较；同步UX-37A/B选择与父子图标，核查数量/摘要/焦点，避免两次返工。
3. **D2 全表面迁移**：日历/新建/选择器，再设置/组织/数据/提醒及桌面窗口；每次一条用户操作链，可构建可回归。
4. **D3 响应与平台验收**：与UX-37C的直接呈现/首帧测量一起检查，不能用动画掩盖多余布局或渲染等待。

对比矩阵：1280×800、880×580；100/150/200%文字；浅/深/高对比；紧凑/舒适；Windows/macOS单独记录。相同语义控件在同尺度下高度/基线误差目标≤1DIP；文本不裁切、命中不重叠、Tab顺序稳定。常用短任务首屏应见标题、时间、提醒、重复、分类/标签或其明确入口，且没有无内容滚动条；复杂任务验证完整滚动与错误可见。

密度用代表性任务的总高度、同屏可读条目数、展开/关闭次数、命中失误及首帧响应联合评估。既有本地/发布门禁不变：Debug/Release、Qt Test/QML lint、临时库、截图/合成与物理操作分开；不因“像macOS”宣称平台特性已通过。菜单/对话框不能省略可访问名称，200%与IMEs不能用100%的截图替代。

## 7. 本轮代码映射及设计取舍

- `DesignTokens/Theme`集中定义紧凑/舒适密度、字级、属性标签列、视觉表面及命中尺寸。新安装默认紧凑；已有明确的舒适偏好保留，文字缩放独立。设置入口改为“紧凑界面”，应用至所有共享控件。
- `NavRow/SmartViewTile/TaskRow`使用语义行高。列表有独立父/子关系图标槽；关系按钮与树展开箭头分工，摘要按时段、父任务、状态、分类/标签组织，单行省略且tooltip/可访问名称保留全文；当前分类不重复。
- `FormRow/FormGroup/DetailSection`统一标签列及边缘；`Button/FieldSurface/CheckBox/SegmentedPicker/MenuItem`统一文字与视觉尺寸，保持32起命中，禁用菜单不绘制活动填色。无需修改运行平台的原生菜单栏/标题栏。
- `Main`的列表与日历页头共用桌面标题层级；详情默认使用真实任务标题头部、单行空备注、时段摘要。日期展开后“开始/结束＋日期＋时间”同行，空间不足重排。重复默认显示当前值，预设直接选择、自定义再展开；提醒保持一次完成的原保存协议。
- `TaskDetailsFields`的分类/分组/标签/父任务共用属性行；有子项才常驻分段，无子项保留直接添加入口。`CalendarCreatePopup`同步日期/时间属性行和完整新增表单，保留创建前零写入。
- `SettingsDialog/OrganizationPage/ReminderPage/DataToolsDialog`透过共享属性行/分组和控件继承密度；设置、选择器、数据面板不各建一套尺寸。`WidgetWindow/DesktopCalendarWindow`使用相同面板边缘及字段间距；mini条保持其单行用途，日历时间轴刻度及全天内容不压缩。

默认短时段详情约380～420DIP高，展开时间参数后可增高至内容上限并单轴滚动；并非固定高度。默认420宽不强求所有200%字段同排，保留可读性。鼠标命中和文字缩放比候选像素值优先。

本轮移除原行编辑“先打开完整面板再关闭”的呈现/焦点往返；没有声称已完成UX-37C全部会话数据解耦。首帧只记录真实`frameSwapped`，无信号时记未测，不能将offscreen截图或visible布尔值当延迟通过。具体构建、缩放截图、原生/物理验证差异见PROGRESS；macOS当前源码需另机复验。
