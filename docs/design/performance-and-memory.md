# 性能与内存优化策略

2026-11-04，PERF-01。先测量、逐层分析、单项实现，再测量。适用于Qt6.10.2桌面客户端及可选Go/SQLite服务，不扩展产品范围，不自动发布。

分层实施和实际结果见[PERF-01记录](../performance-report-2026-11.md)，完成度以PROGRESS及已测范围为准；本策略不是整应用SLA通过声明。

## 目标与边界

沿用NFR-01～05：1万任务冷启动可交互2秒、列表切换200ms、操作反馈100ms、闲置CPU接近零；内存先测实际基线，150～250MB只是首轮目标量级，不是承诺。分别报告小型资料、1万根任务、1万根+3万子任务及长备注/标签/时段/提醒数据。50k只作压力点，不能用简化空记录冒充真实资料。

正确性门禁优先：查询唯一语义、QDate/UTC/DST、CAS、事务/软删/备份、账号资料隔离、错误与撤销均保留。禁止缩短可见数据范围来伪装提速；不得降低刷新/提醒可靠性、移除动画/可访问性或加大测试阈值。只使用QTemporaryDir合成资料，不读用户数据库，不上传诊断。

## 测量方法

1. 固定源码、Qt/编译类型、数据种子、时区及窗口状态；记录真实机器/后端和未验证平台。Release与Debug结果分开。
2. CPU时间拆开数据库加载、查询/排序、模型提交、QML布局/首帧、磁盘提交；UI可交互和后台工作完成是不同指标。记录SQL次数/行数、model reset/dataChanged/rowsMoved次数、对象数量和队列积压，不把端到端耗时全归给SQL。
3. 微基准先预热，再在同一进程采5～9次，报告中位数和范围；足够样本才报P95。比较前后同一数据和输出，保留原日志，不重复全量测试求最好成绩。绝对SLA只在目标硬件验收，CI优先检验复杂度/通知数量/缓存容量等确定性不变量。
4. 内存分别记录进程私有提交、工作集/峰值，Qt对象/任务结构数量和临时投影容量；GPU/纹理与共享DLL不混算。RSS下降不等于已修泄漏，分配器保留不等于泄漏。重复导航/编辑/开关窗后看稳定平台与净增长，分析对象持有链，不能靠定时清缓存或强制回收掩盖。
5. 可控短基准与数据正确性进入Qt Test；真实GUI帧/输入、原生窗口和进程内存为独立探针。QML Profiler、系统采样、SQL EXPLAIN和Go基准按已定位问题使用，不默认增加遥测/持续采样或第三方依赖。

## 分层分析与实施队列

| 切片 | 层/候选热点 | 方法和验收 |
|---|---|---|
| P0 | 基线与测量盲区 | 现有PerformanceTest只测一次仓库/搜索/月历；增加离屏日期、模型不变/重排基准，记录数据/样本/真实结果 |
| P1 | CalendarService范围索引 | 日历端点只进入可见7/42天，跨范围条照常；混合无效/边界日期及跨月输出一致，比较分散日期基准 |
| P2 | TaskWorkspace任务索引 | 索引只保存id→行号，不复制完整Task；从唯一快照安全读取，重载/插删/切账号后不能保留旧索引，详情/提醒/日历/排序回归 |
| P3 | 提醒闲置扫描 | 缓存下一有效UTC提醒时刻，在快照/状态变化时重建；每秒到期判断O(1)，本地日历/时钟回拨/过期提醒/重复/取消/交互保持仍正确 |
| P4 | TaskListModel通知与重排 | 不变输入不发无意义countChanged；单行变更保留增量，必要大重排保持持久索引/选中与滚动，不用reset遮掩；先测后选择算法 |
| P5 | 刷新图与读写链路 | 分离快照变更和筛选变更，失效键覆盖任务/分类/日期/时区/偏好；消除无写入maintenance后的全图加载，先证明无遗漏再按脏域刷新 |
| P6 | Repository/SQLite | 计量all/loadDetails和写后读取、N+1、查询计划与WAL；只对实测查询添新迁移/索引，不覆盖历史迁移或盲调SQLite缓存 |
| P7 | QueryService/日历投影 | 树索引复用、排序键和QVariant转换、重复日期转换；边界/树折叠/筛选/排序同序输出，缓存必须有容量和失效契约 |
| P8 | QML/窗口/GPU | 检查隐藏页面实例、Repeater/Loader/委托复用、绑定扇出及稳定画布占用；HIG连续性/用户控制/稳定布局映射UX-09～13，键盘/草稿/缩放/菜单和恢复不退化 |
| P9 | 同步与Go服务 | 检查客户端图快照/队列/响应上限和后台线程；服务端EXPLAIN、分页、JSON复制、连接池/锁等待与分配。维持HTTP v1、幂等/冲突/鉴权与限流，测试只用临时服务数据 |
| P10 | 集成与内存稳定性 | 代表性长流程/重复导航、前后台/球/小窗、离线同步及恢复；汇总前后结果、残余热点/风险，再决定是否升级结构 |

候选热点是代码审查结果，不等于已测瓶颈；不要求每层为了“优化覆盖率”都改代码。先实施收益证据充分且风险可控的切片；没有收益或无法保证正确性的变更撤回。每项记录输入/输出、复杂度/容量、失效、错误、对应测试与前后数值。

## 本轮验证命令

Windows先设置DAYMARK_QT/DAYMARK_MINGW，按仓库入口构建；定向执行test_performance和test_task_workspace后只在必要时扩大相关CTest。macOS使用`bash scripts/build-macos.sh`或已有构建中的`ctest -R 'performance|task_workspace'`，平台未运行则UNVERIFIED。原发布候选留独立工作树，性能变更不得悄悄进入未完成的1.8.1标签。

## 分层评审后的实现选择

| 层 | 本轮决定 | 正确性与剩余风险 |
|---|---|---|
| 仓库/数据库 | 未到期提醒先解析UTC再构造Task；无活动重复规则不读取任务全图 | 原SQL/CAS/事务/去重不变；不添加未经查询计划证明的索引，不修改schema |
| 快照/刷新 | id→行号索引；明确区分快照刷新与主视图刷新 | 只读指针在调用内使用，索引校验行号及id；写入/重载/同步/日期仍全刷新。筛选/折叠/搜索只改主投影，独立今天/截止列表及全局计数不随主筛选变化 |
| 提醒 | 快照更新时计算下一个有效UTC提醒，到期检查O(1) | 仍每秒比较真实时钟，回拨/前跳无需重建相对定时器；重复/过期/已投递/取消/归档/远端删除按旧语义，弹窗延后状态仍按时间刷新 |
| 模型 | 首次批量插入；相同集合排序用layout及持久索引映射；无变化不发countChanged | 整体重排从逐项搜索/搬移改为O(n)映射，成员新增/删除保留原增量路径。layoutAboutToBeChanged后才采持久索引，含观察者新建索引；不以reset丢选中/滚动。混合大量插删仍可能二次复杂度，留作实测后续 |
| 查询 | 按行号排序，父子表/根/栈只存行号，最终输出才拥有Task；无时段谓词直接只读原任务 | 比较器、稳定顺序、树折叠/跨分类根/垃圾组及统一时间语义不变，输入快照不可被移动破坏；有时段仍调用统一日期规范化 |
| 日历 | 起止端点进入当前7/42天内才建索引 | 跨范围内部日、无效日期、完成显示与周起始独立对照逐日查询；未改变可浏览时间跨度 |
| QML/窗口 | 本轮不改视觉/动效/缓存策略，只验证模型变更在真实QML中的输入/布局 | 连续月历已有有限视口和reuseItems；任务委托含草稿/拖动/移除状态，不能未建复用契约就开启reuseItems。稳定原生画布用于避免末帧闪烁，不为省纹理而重新缩窗 |
| 同步 | 保持协议与图快照/冲突事务 | 已有64MiB传输上限、256KiB分块、退出代次栅栏、超时与reply释放。大图JSON及账号变更前后capture仍是待专项测量热点；不凭静态审查改成增量日志或流式协议 |
| Go服务 | 本轮审查，不改代码/连接池/安全参数 | 已有单writer、受限reader池、1MiB请求上限、64并发入口、4096键限流表、工件流式I/O；降低鉴权KDF或放宽限流不是性能优化。服务端负载/分配与并发长测未运行，不宣称通过 |

### 读写链与失效接口

`refresh(snapshotChanged=true)`保守默认为全量；只有已知不改数据/日期/分类的导航、筛选、搜索、折叠和列表显示偏好显式传false。这样无需新增可遗漏的跨模块脏位协议；后台写、快照/资料切换、账号同步、日期/时区恢复走原全量路径。`cachedTask(id)`只返回当前m_cache内的短生命周期指针，异步命令发出前复制单任务，不保存跨重载裸指针。提醒呈现的lookup回调只在同步计算期间读取快照，不另建完整任务字典。

重复规则无操作测试使用临时SQLite连接的TEMP视图故障注入：无活动规则仍返回0，启用规则后须真实读失败，证明没有静默吞掉必要的读取错误。模型使用QAbstractItemModelTester和QPersistentModelIndex验证重排/插删；UI回归检查草稿、选中/键盘、菜单、拖动和缩放。

### 结果使用规则

旧开发目录的CMAKE_BUILD_TYPE虽为Release，但CMAKE_CXX_FLAGS_RELEASE为空。其所有同配置前后对比统一标为“未启用编译优化的开发基准”，不能作为NFR验收。最终另以`-O3 -DNDEBUG`重建，真实Release数据单列，不能用新Release除以旧无优化数据宣称算法加速倍数。

内存数据来自Windows的进程私有提交/工作集；索引对比为独立测试进程里的同一40000任务夹具。树投影峰值为测试进程峰值，包含运行库/输入/输出及分配器，不能相加为完整应用节省量。GPU内存、整机冷启动、物理帧延迟和长时间增长斜率未测时始终UNVERIFIED。
