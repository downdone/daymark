# 高频任务面板交互详设

对应 FR-002/015、UX-09/11/53/75/77。用于实现[日常工作流精修 §10](task-workflow-refinement.md#10-高频面板逐项走查)。下文是目标行为。首轮只改 Windows 客户端编辑与菜单交互，复用 Qt Quick、现有任务命令和原生托盘菜单。布局单位为逻辑像素，实际尺寸从 Theme 派生。

## 一、简易编辑：在原行完成一次小修改

以「发会议纪要」为例，刚展开时标题光标位于点击处；键盘进入则使用现有标题焦点。行左缘与浏览态对齐，其他行保持浏览态。

```text
○  发会议纪要                              ⓘ   保存
   补上预算数字
   [周五 09:30]  [项目组 / 周会]  [客户 +1]  [⚑]
```

「保存」只在有改动时显露，右侧保留位置；完成圆始终表示改变任务状态。无值时安排显示「安排」，分类和标签保留带名称提示的图标。宽度分配优先级为标题、安排、分类、标签。窄时先缩短摘要，再让工具区换行；200% 文字下允许行高随内容增长。空备注只占一行，已有多行备注整段只读预览，激活后详情直接定位备注字段。Tab 顺序跟随视觉顺序；屏幕阅读器读出用途、当前值、选中状态。

| 控件 | 打开与更改 | 应用、取消及焦点 |
|---|---|---|
| 安排 | 打开时复制外层时间草稿。按日期、可选时段、周期、提醒排序。改起点时同步预览相对提醒；手设绝对提醒保持原时刻。结束早于开始，在结束字段下说明修正方法 | 「应用」只改外层草稿；独立打开的安排使用「保存」。取消、Esc 或点外部收起选择器时还原打开时值。只预览零写入 |
| 分类 | 单选列表先定位当前项；一级和二级用缩进，重名显示完整路径。可选「收集箱（无分类）」；搜索为空显示「无匹配分类」及清除搜索 | 单击或 Enter 选择即写入外层草稿并返回，Esc 原样返回。若原分类被归档，保留旧值并标明状态，主动选择后才替换 |
| 标签 | 弹层维护标签 ID 集合的工作副本，Space 切换当前项，可连续勾选，列表保持打开；搜索仅过滤可见选项，已选集合完整保留 | 「应用」一次替换草稿标签集合，取消恢复原集合。新建标签独立保存后加入工作副本，取消任务时仅取消关联。列表为空仍能新建 |
| 特别关注 | 单击即翻转草稿，按下态与已选态可区分 | 焦点留在按钮；外层放弃能撤销本次翻转 |
| 详情、完成圆 | 详情继承同任务草稿；完成圆遇到已改字段，先保存，成功后以最新版本完成 | 任一步失败停止后续动作。已保存但完成失败时说明「修改已保存，任务尚未完成」，重试仅重做完成动作 |

弹层相对触发控件定位：能在下方完整展示就向下，其次向上；两侧都放不下时选空间较大的一侧，扣除标题和操作区后只滚动选项区。窗口内嵌弹层以可渲染的客户区为边界，独立弹窗以所在屏幕可用区为边界。隐藏的空态、分隔符不参与高度计算。点外先消费该次指针事件，避免同时完成底层任务；关闭后以控件标识恢复焦点，来源行被回收时按任务 ID 回到行。

## 二、详情：读全任务，集中提交

```text
发会议纪要                          更多   保存   ×
补上预算数字，并附上最新报价……
安排       周五 09:30 · 提前 10 分钟提醒
分类       项目组 / 周会
标签       客户、内部
子任务（2）
```

上述为信息顺序，继续使用现有附着弹窗和详情／子任务页签。标题、保存和错误反馈保持可达；内容过高只滚动正文。只读历史轮次标明实际完成时间，切换到当前任务才提供当前轮编辑。根任务的子任务页可连续添加；子项详情显示父名，返回还原父项页签及滚动位置。

**保存边界**：标题、备注、安排、分类、标签、关注等随任务草稿统一提交。新增子任务、创建分类、完成任务是独立命令。子任务已创建后即使放弃父任务备注，也保留该子项。单行标题 Enter 按现有保存约定，多行备注 Enter 换行；Ctrl/Cmd+Enter 提交。输入法候选尚未提交时，Enter、Esc 先交输入法处理。

| 离开方式 | 干净状态 | 有草稿 |
|---|---|---|
| 主动点保存、关闭、切任务 | 关闭或执行目标动作 | 保存成功再执行目标；失败留在出错字段。关闭按钮名称随状态显示为「保存并关闭」 |
| Esc | 先关最深弹层，再回到来源 | 最外层给「继续编辑」「放弃本次修改」，继续编辑为默认，取消确认返回原字段 |
| 切到其他应用、打开子菜单 | 保持状态 | 保留文本、选区和弹窗，回来继续 |
| 服务端快照到达 | 刷新已提交值 | 未编辑字段更新；同一字段有分歧时就地显示「我的修改」「最新值」。选择后用最新版本重新校验并提交。任务已删除则保留可复制文本并停写 |

## 三、小窗：从桌面进入，再回到桌面

标题栏菜单面向组件，正文菜单绑定命中任务 ID，底部快添绑定当前分类或今天范围。最多一个任务详情；安排在同一详情内换页。保持原有可调小窗宽度，分类栏收起后表头保留分类切换入口。使用同一字号和可点击面积，先压缩摘要，随后换行；不按窗口宽度整体缩放面板。

| 场景 | 面板与返回结果 |
|---|---|
| 单击任务 A → 安排 → 应用 | 详情内显示安排页，应用后回 A 的原页签；外层显示已修改。按返回或取消仅撤销本次安排调整 |
| A 的子任务页 → 打开子项 B → 返回 | 有父项修改先保存；成功后记录父 ID、页签、焦点来源。返回时重新读父项，原子项仍在则定位它，已移走则定位相邻项或添加框 |
| 编辑状态碰上定时刷新、菜单或收球计时 | 编辑器或其弹层活跃即暂停自动收球；模型只刷新受影响项。最后一层关闭后重新开始完整空闲计时 |
| 用户主动收球、隐藏或转主窗 | 先走保存保护；无效标题或写入失败则留在原窗口。转主窗成功后以相同任务 ID 打开，主窗已存在时复用 |
| 对 B 右击，此前选中 A | 菜单捕获 B 的 ID；选择命令时复查 B 仍存在。空白右击不出现组件菜单，组件透明度不影响菜单可读性 |

## 四、托盘：在主窗之外可靠地开始或恢复

```text
打开主窗口
在收集箱新建…
────────────
显示任务组件                  ← 已显示时为「隐藏任务组件」
启用鼠标穿透                  ← 已开启时为「恢复组件点击」
重置位置并显示组件
────────────
设置…
────────────
退出 Daymark
```

复用 DesktopTray 的 QMenu/QAction，每次 aboutToShow 从 WidgetViewModel 读取真实状态。隐藏且穿透时仍可直接解除穿透；「恢复组件点击」只改穿透状态，「重置位置并显示组件」只改变位置与可见性，连续执行均幂等。显示／隐藏、启用／解除按菜单当前显示的目标执行；若菜单开着时设置已切换，不按旧动作再次取反。托盘不可用时已有主窗设置承担恢复入口。

左击恢复原主窗；「在收集箱新建…」先保护已编辑任务，再打开一个收集箱草稿，空标题取消零写入。「退出 Daymark」是全程序退出意图：先收集主窗和小窗编辑状态；无改动沿现有退出路径，有改动提供「保存并退出」「继续使用」「放弃修改并退出」，默认继续使用。按稳定顺序保存，任何失败均中止退出，定位失败的编辑器；先前保存成功的任务标为已保存。全部完成或显式放弃后才设置 forceQuit。正常关闭主窗到托盘仍遵循原偏好。

## 五、模块、提交与验证契约

| 模块 | 实施边界 |
|---|---|
| Main.qml、TaskEditorSession、TaskSnapshotObserver | 复用已有导航与保存会话，补资料代次、任务 ID、基准版本、脏字段和该次提交序号的校验。提交中禁重复保存，保留第一个明确的后续动作；迟到回执不关闭后来打开的面板 |
| TaskQuickEditor、TagMenu、CatalogPicker、TaskDetailsFields | 复用现有主题与选择模型；任务标签多选的草稿集合只在任务编辑场景启用，核查其他 TagMenu 调用者的旧交互 |
| WidgetTaskInspector、组件形态控制 | 将切应用导致的失焦与显式离开分开；记录父项返回位置；沿用保存成功后的动作分派 |
| DesktopTray、主窗退出路由 | 托盘只发出目标意图，主窗协调小窗和主窗的未提交工作。如果两个编辑器改的是同一任务，先保存的一份引发第二份版本校验，冲突时恢复编辑，不自动覆盖 |

技术边界：本轮不新增网络请求、服务、依赖或数据库字段。任务更新经既有服务校验、事务及同步队列；子面板快照仅在内存中，关面板即释放。日志只记操作类型、结果和错误码，不记录输入内容。QML 不推导下一轮日期，不重复维护业务事实。

| 交付顺序 | 验收入口与可判定结果 |
|---|---|
| 1 草稿与返回 | task_list_interaction：使用临时资料，原位改标题、开详情、取消安排、改多行备注，断言最终字段、一次任务更新、来源焦点。注入写失败及重复保存，检查后续动作未提前执行 |
| 2 按钮弹层 | picker_lifecycle：分类同名定位、选中两标签后取消／应用、空列表零空行、屏幕边缘最后一项可选、Esc 逐层退回；浅深与 200% 检查正文和底部操作可达 |
| 3 小窗与托盘 | desktop_surfaces 验证状态组合和路由；Windows 原生窗口实测中文组字、外部切窗、透明小窗菜单、层级返回及托盘恢复。两窗均有草稿时从托盘退出，分别验证继续使用、保存失败、成功退出 |

自审结论：主窗同行和详情复用草稿；跨窗口按已提交任务交接；批量退出可能部分保存，明确逐项反馈且不宣称整体原子提交。实施前在目标发行源码复核以上入口。自动化与 Windows 实机各自记录结果。
