## 1. 定位

**Daymark是一套任务数据、两种工作方式：列表组织与执行行动，日历查看与调整这些行动的时间安排。** 日历不是装饰性日期索引，也不是另一套独立日程数据库。

一个任务可以没有日期、只指定日期，或指定起止时刻；可以循环，有父子关系和分类标签。列表、日历、详情和桌面组件操作同一taskId与版本。父任务完成/删除/分类移动仍按既定规则联动；日期和具体时段不自动继承给子任务。

借鉴用户截图中的时间层级、全天栏、细网格、集中尺度切换和就近详情；不复制iCloud账号、订阅日历、Siri、图标资源、农历、会议邀请等未授权能力。文件夹分类仍是唯一归属，标签仍是横向标记。

## 2. 四种尺度的职责

| 尺度 | 主要问题 | 默认内容与交互 | 不承担的内容 |
|---|---|---|---|
| 日 | 今天/选定日期具体怎样安排 | 日期任务栏＋小时轴；定时任务按起止位置绘制；当前时间线；点击任务就近查看；拖动创建/改期、边缘调整时长 | 不把一整页空白当作唯一空态，不用位置表达未指定的时间 |
| 周 | 一周的安排是否拥挤、哪些时段重叠 | 七列日期、共享小时轴和滚动；日期任务/跨天条置顶；重叠任务并排；保留选定日期 | 不把当前七日缩小月格继续命名为时间规划周视图 |
| 月 | 日期分布、跨天安排、需要关注的日子 | 细网格、日期右上、周末弱背景；日期范围条、定时任务的时间＋标题；有限可见行与明确溢出；单击日期打开当天议程 | 不呈现小时高度；不声称日期任务占用了每天全部时间 |
| 年 | 快速定位月份与日期 | 十二个小月，今天/选择/键盘焦点有区别；单击日进入该日，选择月进入该月；共享筛选和时间锚点 | 首版不提供不完整的忙闲/热力图，不用仅已生成的循环实例数量冒充全年负荷 |

保留当前首次进入月视图的习惯，之后记住用户最近尺度。日/周不能在没有小时轴时显示为已交付。年视图先交付可靠导航；全年负荷与循环预测另行设计，不以空的年按钮占位。

## 3. 同一任务怎样显示

| 任务事实 | 列表摘要 | 日/周 | 月 | 年 |
|---|---|---|---|---|
| 没有日期/时刻 | 不显示虚构时间 | 不放入任何小时；“未安排”入口列出当前范围任务 | 同左，不自动放今天 | 不制造日期点 |
| 只有一个日期 | 一条日期摘要 | 顶部“日期任务”栏，可完成与查看 | 当天任务条 | 仅用于导航；完整统计前不承诺负荷标记 |
| 只有结束日期 | 明确“结束于…” | 结束日的日期任务，不能当作有开始时刻 | 结束日标记 | 同上 |
| 有开始、结束日期，无具体时间 | 一条日期范围摘要 | 日期任务栏跨日续接，包含界面两端；不铺满小时轴 | 连续范围条，跨周续接 | 同上 |
| 有具体起止时刻 | 开始时分＋必要的结束/日期范围 | 真正的时间块，长度对应时间；跨午夜分段且标明延续 | 时间＋标题，跨日续接 | 同上 |
| 已完成 | 完成状态与完成时间 | 默认隐藏；打开显示后保留可读的勾选/删除线，不以低透明度唯一表示 | 同左 | 不纳入待办负荷 |
| 循环任务实例 | 任务身份＋必要的重复标识 | 本次实例，与普通任务同样可编辑/完成；操作系列前明确作用范围 | 同左 | 不因打开年视图向数据库写入全年实例 |

当前实现的蓝/绿区别来自旧date列与schedule投影，不能继续暗示两类实体。建议统一任务色彩语义，日期任务与定时任务主要靠位置、时间文字和形状区分。若未来支持分类颜色，来源于同一分类属性，不引入另一套日历颜色资料；本轮不新增该功能。

## 4. 范围与时间尺度分开

范围回答“看哪些任务”，尺度回答“怎样看时间”。建议采用明确的上下文结构：

```text
TaskViewContext
  scope：收集箱 / 今天 / 计划 / 全部 / 特别关注 / 完成 / 分类 / 标签 / 搜索
  filters：已有分类、标签、完成状态条件
  presentation：list / calendar
  calendarScale：day / week / month / year
  anchorDate、selectedDate、displayTimeZone
  selectedTaskId、scrollAnchor
```

该结构是设计接口，不要求创建通用框架。QueryService决定范围，CalendarService只对相同任务集合做时间投影，QML不再筛一次业务规则。

推荐规则：

1. 从“分类A”列表切日历，仍为分类A；其二级包含规则与列表一致。标题/范围摘要明确为“分类A · 日历”。从标签或搜索切换同理。
2. 进入日历后点击侧栏分类/标签只改范围，保留日历尺度与锚点，不强制回列表。
3. 今天/计划/特别关注保持自己的精确范围；需要完整时间分布时选择已有“全部”。不为了让月格更热闹而偷偷扩大范围。
4. 无日期任务不消失：未安排入口显示当前范围数量，并能拖到日期或时段；只操作放下的任务，父子日期不隐式联动。
5. 最近删除、提醒记录等没有合理日历表现的页面，不提供看似可用的切换。保持工具栏槽位稳定，以明确可访问说明表达能力边界。
6. 主窗与桌面日历各有独立的尺度、锚点和筛选状态；共享任务事实，不共享用户正在浏览的位置。

不直接把截图的日历来源复选框再复制一遍：Daymark已有两级分类。首片保留侧栏单范围导航；多分类叠加如确有需要，在一个明确“显示范围”入口中实现，不让同一行有时导航、有时切可见性而无提示。单一任务、两种视图并不要求所有页面有完全相同控件，但要求范围变化可见、操作身份一致。

## 5. 布局与信息层级

```text
侧栏：任务范围/分类/标签        主工具栏：列表·日历  当前范围       搜索/新增/显示
                              时间导航：日期标题  日·周·月·年  上一页·今天·下一页
                              ─ 日期任务/全天安排 ─
                              日/周小时轴 或 月格 或 十二小月
                              按需当天议程 / 就近任务小面板
```

采用一个稳定工具栏和一个时间导航行，减少当前“日历标题＋Flow工具串＋月份标题”三层竞争。日/周/月/年切换位置固定，翻页单位随尺度改变，Accessible.name使用“上一天/周/月/年”。“今天”统一回当前日并定位时间，不同时充当“给选中任务安排今天”。

日期导航可选小月历，只出现一处；日/周宽窗可作为辅助导航，窄窗从日期标题展开。用户截图中的左右两份小月历不应照搬。议程与任务小面板按需打开，不默认固定占用一整列空白；无选中任务时也不保留大块“未选定日程”占位。月格不因为打开某一天而突然被滚动到其他周。

日/周时间轴建议初始定位工作时段，但全天24小时可达；不新增强迫设置“工作时间”的步骤。当前时间线只在今天绘制；选中日、今天、周末、焦点四个状态不能共用一个底色。重叠代表并行安排，不能自动拒绝或悄悄挪开；并排区块不能窄到只剩不可点击色线，必要时合并为可展开的重叠组。

## 6. 操作契约

| 操作 | 预期结果 |
|---|---|
| 单击任务块/日期任务；信息/双击/Enter | 单击选择；信息按钮、双击或任务焦点Enter锚定打开同一就近任务面板，先看标题/时间/状态；长内容展开同一编辑器，不跳另一套详情页 |
| 单击空白日期 | 选择日期，必要时显示议程；不自动进入新建输入、抢走日期键盘焦点 |
| 新增按钮/双击空白时段 | 在选定日期/时段附近输入标题；未保存内容有清楚状态；Enter创建成功后可继续，失败保留 |
| 从未安排拖到某日 | 预览“安排到10月27日”，释放仅提交该任务开始日期；已有结束日期按统一改期规则校验 |
| 从未安排拖到小时轴 | 预览日期和时段；时长采用明确默认值，可在提交前调整；不把提醒瞬间冒充任务时段 |
| 拖动整个时间块 | 清楚的目标轮廓和起止文字；提交同一任务的新时段，保持身份与系列范围；失败原位恢复 |
| 拖动块的起/止边缘 | 仅调整该边界，显示新时长；不能反向成为负时长；精确时间仍可键盘输入 |
| 拖动日期范围条 | 移动整个日期范围；边缘是调整单边，二者命中区域和指针不同 |
| Esc/放到非法区域 | 取消预览，零修改；非法原因可见，不能显示已接受拖放后再静默无效 |
| Enter / 信息按钮 | 打开同一任务面板，双击不是唯一入口；完成快捷键只在任务选中而非输入时生效；菜单为所有拖动提供替代命令 |
| 编辑循环实例 | 显式区分“仅本次 / 后续未修改实例”；不在单击或拖动时擅自改整个系列 |

最小日/周对齐步长建议15分钟；精确输入不受该步长限制。步长与默认时长为Daymark设计建议，不是Apple数值要求。不能通过拖动把任务变成子任务，移动时间也不能顺带改分类。

任务面板及展开容器采用目标中的离开保存原则：关闭前必须提交成功，失败保持面板/草稿；明确“放弃修改”才丢弃。现有完整详情仍显式保存，新目标按[就近任务面板方案](contextual-task-inspector.md)补齐契约/失败测试后迁移，不直接改所有表单。非模态选择器同时只显示一层内容；提醒编辑里再选日期应切换面板内部状态或先关闭前层，避免多层浮窗堆叠。

## 7. 时间与数据边界

日期是本地日历日；时刻是UTC瞬间；显示时区明确，不用固定86400秒代替下一天。当前系统时区作为默认显示时区，原任务时区保留且在详情可查看。

必须先形成时间命令契约再实现拖动：日/周坐标对应显示时区中的瞬间；任务日期编辑按字段标明的时区解释。移动整个定时时段保留真实时长，单边调整改变时长；按日改期保留约定墙钟时间，遇DST缺失/重复时刻明确拒绝或让用户选择，不允许JS自动纠偏。相对提醒按新开始重算，绝对提醒保持其瞬间；界面在改期预览中表达区别。与UI-33原时区墙钟命令有差异的地方先新增ADR与回归，不悄悄重写既有历史。

午夜结束使用排除式时段投影，不能多占一天。跨日任务每段显示同一身份，点击不新建副本。父子日期独立、删除/完成整树联动的约定不变。所有命令带rowVersion；列表、主/桌面日历同步，版本冲突保留用户输入和旧位置，不用覆盖写恢复视觉。

年视图不触发全年物化，不将打开视图变成大量写库。若以后做全年循环负荷，需由C++提供只读规则投影、明确统计范围与实例身份策略，另写ADR；不能由QML推算或把预览当成已经创建并提醒的任务。

## 9. 依据与限制

Apple HIG：[macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[工具栏](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[小面板](https://developer.apple.com/design/human-interface-guidelines/popovers/)、[反馈](https://developer.apple.com/design/human-interface-guidelines/feedback)、[可访问性](https://developer.apple.com/design/human-interface-guidelines/accessibility)。采用内容优先、合理密度、就近上下文和可恢复操作，Qt样式与资源独立实现；不承诺原生Liquid Glass。

本文件提炼用户截图的结构，不抓取其日程、账号或订阅数据。日/周小时轴和年导航是新的目标能力，覆盖旧设计“周无小时轴、不提供日/年”的目标限制；实际交付状态只在PROGRESS维护，未因本文件建立自动变成已实现。
