# 日常任务工作流：开发与验收总表

适用 FR-002/015/042、TIME-02、CONS-01。本文是本轮开发入口。[动线评审](task-workflow-refinement.md)说明问题和取舍，[面板详设](frequent-panel-interactions.md)定义逐按钮行为。以下以同一组测试资料贯穿各模块，条目编号同时用于开发记录和验收。当前工作树与目标发行源码有差异，实施先重放用例；在目标版本已满足的条目记录证据即可。

## 验收资料与观察方法

两份隔离客户端资料 A/B，临时 SQLite 库和可控测试服务；固定时区 Asia/Shanghai，初始本地时间 2026-12-01 16:00。分类「客户／周会」「内部／周会」用于区分重名。建立以下任务，记录创建结果的真实 ID：

| 代号 | 标题、归属与初态 |
|---|---|
| T1 | 发会议纪要，未分类、无日期、未完成 |
| T2 | 月度清洗，内部／周会，12 月 2 日 09:30–10:30，每月，提前 10 分钟提醒 |
| T3、T4 | 内部／周会中的两个父任务，各有一个标题为「准备材料」的子任务 |

每例从独立快照开始，记录资料代次、任务及轮次 ID、写入前后版本、队列状态、当前范围与焦点。只在临时测试资料中核对业务字段。产品日志不记录任务原文。所有时间均写明测试时区；跨时区、月末和夏令时规则另由领域测试覆盖。

## A. 第一次使用与快速添加

**开发入口**：主窗及小窗快添、日历创建入口 → TaskTimeRecognition → TaskWorkspace 创建命令。三个入口共用候选计算和提交校验。输入草稿保存原文、来源范围、选中分类和日期、识别候选、用户覆盖值；提交时绑定原资料，成功回执到达才清空。

| 来源 | 标题之外的默认值 | 需要向用户交代的情况 |
|---|---|---|
| 首次收集箱或托盘新建 | 未分类、无日期、按设置识别时间 | 空态“收集箱为空”，主动作聚焦既有输入。离线、未登录也可保存 |
| 今天／分类小窗 | 今天入口带本地今天；分类入口带分类。分类的“全部未完成”不自带日期 | 在提交前展示实际归属和日期；分类范围选“今天”时明确显示今天默认值 |
| 日历某日或时段 | 选中日期或时段，以及来源分类（如有） | 标题识别结果若与日期锚点冲突，展示两个**绝对日期**供选择。手工改过的值优先，识别不覆盖 |

只有日期时默认只安排，用户启用日期默认提醒时显示将采用的时刻；明确“不提醒”覆盖本条建议。有多个候选、无效日期或已过时刻，提供手选或忽略，保留标题原文。IME 确认候选不触发创建。成功后当前范围匹配则显示新增行；不匹配则显示去向和「查看」，保留筛选及录入焦点。失败保留原文、覆盖值和分类。

**A1** 空库断网新建 T1，断言一次创建、在收集箱可见、重启后可找回。**A2** 在 12 月 3 日日历输入「明天 9 点联系」，测试日期固定为 12 月 1 日；确认看到 12 月 2 日、12 月 3 日两项，选择前零写入。**A3** 在有关键词筛选的分类创建不匹配任务，「查看」能按 ID 定位；再连续新增时无上条的时间覆盖。测试入口：time_recognition、task_workspace、calendar_interaction。

## B. 找回任务、视图范围与阅读位置

范围和呈现方式分别保存。TaskWorkspace／现有查询层给出匹配 ID、数量和父子上下文；Main.qml、CalendarPanel 和 WidgetViewModel 只消费结果。收集箱按未分类，今天按已到的日期、时段或提醒等既有规则，计划含有日期的未完成项，分类与标签可叠加过滤条件。清除搜索只清搜索，清除筛选只清对应条件，均保留当前资料与导航范围。

| 页面事实（按优先顺序识别） | 标题／主操作 |
|---|---|
| 初次读取中；读取失败 | “正在读取任务”；失败显示可重试原因。已有结果刷新失败时保留旧列表 |
| 查询成功，搜索或过滤后零条 | “没有匹配的任务”，就近展示生效条件和清除动作；已完成、最近删除同样遵守 |
| 查询成功，范围本身为空 | 收集箱可录入；今天说明暂无待办；历史页说明记录来源，使用已有导航返回 |
| 有匹配项 | 标题是当前范围，小窗副标题是时间过滤；显示的上下文父名不计入匹配数。导航总数与过滤结果不同时分别标清，正文避免重复计数 |

列表转日历保留范围和选中身份，有日期且落在范围内则定位，无日期提供未安排入口。返回恢复原滚动锚点；保存后移出范围则落到相邻行。视觉顺序始终是标题、父子归属、时间摘要，再到操作。浅深模式与增强对比使用现有 token，焦点、选择和完成各有独立反馈。

**B1** T1 归类后退出收集箱，同一 ID 可在分类找到。**B2** 在已完成页搜索不存在的词，显示无匹配及清除；清除后恢复真实历史。模拟读取失败，不显示“已清空”。**B3** 从 T2 所属分类切到日历再回列表，分类、身份与滚动锚点一致；只匹配子项时父名可读、匹配数量不翻倍。测试入口：unified_tasks、task_list_interaction、calendar_interaction。

## C. 小窗、Mini 条、悬浮球与跨窗编辑

三形态只改变呈现。球负责唤回，Mini 显示一条任务摘要，小窗可浏览与编辑。窗口控制器负责常驻形态、临时展开、各形态启用状态及返回锚点。仅在临时展开、无菜单／编辑／拖动且返回形态仍启用时启动空闲计时；用户显式选常驻小窗后不自动收回。形态被禁用时回退到已启用形态，按已有偏好规则处理。原生区域、视觉动画和鼠标命中区的终点一致；减少动态效果时直接到终态。形态变化不改变分类、排序或任务。

小窗左侧复用分类树：今天固定、全部有效分类按主窗同级顺序显示；同级上移下移（含键盘）不改父级。截断项有完整路径提示，窄窗收起左列后标题仍可打开分类。右侧以父任务 ID 分组；主窗新增／改名／排序后通过既有提交通知刷新对应行。编辑器以资料代次、任务及父项身份定位，避免复用 delegate 导致草稿转移。面板保存、取消、并发修改及托盘恢复见[面板详设](frequent-panel-interactions.md)。

**C1** 主窗新建和排序二级分类，小窗无需重开即显示；折叠后能通过完整路径找回。**C2** 在 T4 下输入「01、准备材料」，期间触发一分钟计时、T3 刷新和输入法选词，最终仅新增到 T4，光标仍在同一框。**C3** 从球临时展开，菜单未关时跨过收回期限，关闭菜单后等待完整期限才返回；缩回后的空白区域可点击底层，逐帧观察边缘残影。对所有已启用形态验证两两切换、托盘找回。**C4** 原行→详情→子弹层→保存回原行，断言一次任务提交；同字段跨窗修改须显式解决。测试入口：widget_workflow、widget_window、widget_pointer_ui、picker_lifecycle、task_list_interaction。IME、透明窗口闪动和系统托盘另做 Windows 实机。

## D. 安排、到期处理与完成历史

TaskTemporalFields 编辑统一草稿，TaskCycleService 判定轮次，ReminderSchedule／TaskWorkspaceReminders 管预约与处置。只填本地日期不隐含时刻；相对提醒依赖明确的开始时刻，绝对提醒保留指定瞬间。安排、下次执行和下次有效提醒分别取自对应业务事实。仅对当前轮有固定提醒时，不给下一轮展示虚构预约。

| 动作 | 必须改变 | 必须保留 |
|---|---|---|
| 延后本次提醒 | 当前提醒的下次提示时刻；反馈显示新时刻 | 原安排、周期、待办状态 |
| 关闭本次提示 | 本次提醒的处置记录 | 任务待办、后续轮次 |
| 完成本轮 | 原任务进入等待下轮，按轮次登记一次完成，撤销本轮待提示预约 | taskId、历史、原规则；到下一轮开始再恢复待办 |
| 迟到完成或停止周期 | 迟到完成取完成时刻之后首个有效轮次；停止后不再推进 | 漏做不自动登记完成；停止不抹除旧记录 |

**D1** 对 T2 将时钟推进到 09:20，延后十分钟，09:30 仍见原安排；完成后历史有且仅有一条，下一轮为 1 月 2 日 09:30。重启和重复投递不得重复完成或再次弹出已处理提醒。**D2** 改为固定提醒再移动开始时刻，固定提醒不随之移动；相对提醒例须重算。**D3** 从已完成页定位原轮；下轮已开始后拒绝以旧轮撤销覆盖新轮。测试入口：reminders、task_service、task_workspace；跨端另跑 E2。业务边界详见[周期契约](task-cycle-and-cross-surface-consistency.md)。

## E. 保存、账号同步与升级中断

区分本地事务、账号队列和软件更新三条状态。保存回执只证明本地成功；收到服务确认才更新上传状态。普通成功保持安静，出错时先说明数据位置，再给唯一可执行的下一步；技术错误码留在诊断入口。使用现有账号同步协议、数据库迁移、签名验证与更新事务，不新建通知中心或服务。

| 状态／触发 | 界面和执行契约 |
|---|---|
| 写入失败／离线待传 | 前者提示“未保存”并保留输入；后者显示“已保存在此设备，等待同步”，网络恢复继续原队列 |
| 凭据过期／两端改同字段 | 原资料队列保留，登录后继续；冲突显示两份字段值，取消解决不丢草稿或覆盖远端 |
| 协议变更 | 按真实版本及能力信息选择兼容路径。无损时校验签名目标及可恢复备份后走升级；有损时预览具体任务、字段、数量，确认前零迁移写入。没有可验证目标时保留资料、说明恢复动作 |
| 取消检查／下载，重新检查 | UpdateController 按现有可取消阶段撤销并释放本次请求；旧异步回调不得覆盖新状态。手动检查绕过每日自动检查间隔；进入原子提交后按事务恢复 |
| 安装、重启 | 用户确认正在运行实例的关闭策略，使用既有安装范围限制。校验新版本与资料可读后按现有更新契约清理旧版，失败保留可恢复路径 |

**E1** 断网编辑 A、使登录失效、重启，验证已保存字段和待传仍在；恢复登录后 B 收到同一任务。**E2** A/B 完成 T2 同一轮，服务端和两设备最终仅有一条该轮记录；再让两端分别把同一字段改成不同值，验证冲突选择与取消。**E3** 分别模拟无损、需丢字段、目标不可验证三类升级，核对确认时机、备份与数据。**E4** Windows 隔离安装执行取消→再检查→更新→重启，核对版本、T1/T2 身份、记录数与待传修改；不得用只读健康检查代替。入口：tests/integration/AccountSyncTest.cpp、update_qt_controller、update_windows_flow、setup_windows_flow。

## 实施与交接

1. 先在目标源码重放 A1、B2、C2、D1、E4，记复现版本与最小条件。修改按依赖提交：A/B 的上下文与查询 → C 和四个面板的草稿与焦点 → D 的摘要与历史 → E 的跨设备和发行链验证。各模块已有等价实现时复用，只补缺失行为或验收。
2. 业务事实由 Repository 与事务负责；提交后经已有信号刷新受影响 ID。单纯分钟刷新不得重建正在编辑的行，也不得触发全表重查。用模型重置计数、窗口对象数及 10k 临时任务基准比较变更前后；明显回退需定位原因并记录。账号／编辑／更新回执携带所属资料或事务身份，过期结果不写入当前会话。
3. 每个用例记录源码版本、环境、输入夹具、预期、实测、证据位置及 PASS／FAIL／UNVERIFIED。截图核信息层级与裁切；数据断言核版本与记录；真实指针、中文输入法和录屏核焦点、命中及闪烁。浅深、最窄宽度、100%／200% 文字各覆盖代表路径。首次使用者在无讲解下回答“存在哪、几点响、完成后去哪找”，记录误判和额外页面往返。
4. 设计不改存储或网络格式。实施中若现有事实无法支撑某用例，先记录缺失字段及兼容影响，再单列迁移。每片通过仓库 Windows 构建及对应测试后更新 PROGRESS；公开安装、物理设备和其他平台分别记录实际证据。
