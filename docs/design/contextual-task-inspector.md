# 就近任务面板：替代默认详情跳页（UX-34）

日期：2026-10-25。用户补充macOS日历双击提醒事项的小面板截图，提出列表是否也能就近打开详情。本文推荐**默认就近面板、按需展开同一个编辑器**，纳入[系统评估](system-ux-review-2026-10.md)，并与[日历v2](calendar-workspace-v2.md)配套。用户要求完整实现后，已迁入共享面板与离开前保存；实现及验证映射见[UX-34索引](ux34-implementation.md)，实际平台证据只见PROGRESS。

## 1. 为什么默认不需要单独页面

当前详情跳页容易丢失原任务的上下文，也让简单修改承担标题、返回、分段和大表单的成本。列表和日历实际上编辑同一任务，应使用相同的任务面板。只换成一个缩小后的全页表单也不够：要重新组织内容，保留任务身份、关系、完整能力、草稿及失败恢复。

推荐三个呈现层级，但**只有一个编辑会话**：

| 入口/形态 | 责任 | 编辑范围 |
|---|---|---|
| 原行快速编辑 | 连续整理，减少视线和鼠标移动 | 标题、备注摘要、常用日期/标签等快捷入口 |
| 就近任务面板（默认详情） | 一次看清和修改某任务，列表/日历共用 | 全部任务属性；根任务含详情/子任务tab，编辑记录按需进入 |
| 展开同一个面板 | 长备注、大量子任务、大字号或窄屏 | 相同字段/草稿/保存规则，仅容器与可用空间改变 |

不再把“简单详情”“完整页面”实现成两个对象或两套表单。展开不是新的导航目的地，没有另一套保存状态；收起回原任务附近。普通子项仍无新增下级入口，旧深层资料仍按兼容规则可访问。

## 2. 入口与指针/键盘

| 场景 | 单击 | 信息按钮 / 双击 / Enter |
|---|---|---|
| 列表任务 | 延续原行简易编辑；完成圆只完成 | 打开该任务的就近面板，承接同一草稿 |
| 日历任务/横条 | 选择该任务，不自动新增 | 信息按钮、双击或任务焦点Enter打开同一面板 |
| 子任务列表 | 点击标题直接打开子任务面板内容 | 同上；完成按钮与打开分离 |
| 桌面组件 | 保留完成；标题打开主窗定位 | 主窗呈现同一taskId面板，不另造组件专用详情 |

双击不是唯一入口，不能要求用户猜手势。不得拦截文本字段中的双击选词或输入法Enter。列表的第一次点击即使已经展开原行，第二次也只迁移现有会话，不先保存一份旧值再打开另一份。右键/Control-click不进入简易编辑；先保护已有草稿再执行命令。

## 3. 内容骨架

```text
┌─ 完成圆  可编辑标题                 特别关注  更多 ─┐
│ [详情] [子任务 N]                 展开 / 关闭       │
│ 备注（自然增高，有上限后正文滚动）                   │
│ ───────────────────────────────────────────────  │
│ 日期与时间    开始日期 [时分] → 结束日期 [时分]      │
│ 提醒          开始前10分钟 / 指定时刻 / 添加        │
│ 循环          不重复 / 每周二…                     │
│ ───────────────────────────────────────────────  │
│ 分类          文件夹路径                          │
│ 标签          已选chips ＋                         │
│ 关系          父任务（子项时）/ 按需选择            │
│                       保存中 / 失败及重试（有事才出现）│
└─────────────────────────────────────────────────┘
```

不是每个任务都常驻这些输入框。无日期时是“添加日期”，指定时间后才出现时分和时区入口；无循环时只一行；标签先显示已选项，点击才搜索。置顶、取消、删除、编辑记录等放更多菜单；特别关注可在标题旁直接切换。不能删掉未常用能力来换小窗。

根任务的子任务tab只列直接子项，支持连续新增、圆形完成和点击进入。打开子项在**同一面板**切换内容，头部显示“返回父任务”；返回恢复tab、滚动和未提交新增标题，不叠第二个任务popover。子项自己的日期/提醒/标签不隐式继承，完成/删除/分类移动按已接受整树契约。

编辑记录在面板内部作为可返回的只读子视图；不是第三个常驻tab，也不是自动回滚任意历史。危险动作的明确确认仍可用模态确认框，不能让就近面板默默替用户删除整树。

## 4. 保存和关闭：目标修订与现有行为分开

UI-33历史规则为“原行退出保存，完整详情显式保存”。本轮按ADR-020将任务面板及展开形态统一为**结束编辑前保存**，保留原子提交、失败草稿与明确放弃。

- 点击外部、Esc、关闭、切任务/视图：若有合法修改，先提交成功再关闭/切换；无修改立即结束。外部动作先排队，失败时不执行目的动作、不先切中导航。
- 写入中：面板显示短暂状态，避免重复提交；浏览滚动仍可用。不把“保存中”当作成功，不让延迟回调关闭后来打开的另一个任务。
- 无效字段、磁盘错误、CAS冲突：保留面板、所有输入及可修复提示，焦点进入出错字段或冲突处理；有明确重试。不能只在全局toast报错然后关闭。
- Esc表示结束本次编辑，并走同一保存门；明确“放弃本次修改”才丢弃未提交草稿。删除确认的Esc仅取消删除，不能顺带关闭任务面板。快捷键语义必须显示并测试。
- 新建但标题仍空：关闭取消未落库的新任务；其余字段不能凭空创建空任务。保存后按taskId继续同一会话。创建子项前先确保父任务合法持久化，失败不得产生孤儿。
- 完成/删除/移动属于独立命令：先解决当前草稿，再计算影响和提交；整树确认、撤销和恢复保持。没有“关闭小窗”顺便执行完成的设计。

可在更多中提供“立即保存”作为键盘/可恢复动作，默认不放常驻大保存按钮；Cmd/Ctrl+S仍可手动提交并保持面板。正文文字编辑撤销和已提交业务撤销不同，不能宣称存在完整跨会话撤销。自动保存对日志频率的影响需随命令合并策略测试，避免每个字形成一条记录。

实施迁移期间，旧完整详情仍显式保存；新面板未通过失败门禁前不移除旧入口。新旧容器不得同时编辑同一任务。全部入口迁入共享编辑器后，默认跳页才正式退场，旧全页仅作为同会话展开呈现，不留下另一种保存规则。

## 5. 浮层、日期选择与空间

默认宽度建议360～440 DIP，按任务内容自然增高并受窗口边界限制；是Daymark候选值，需要880×580和200%实测，不是Apple硬性标准。优先在条目右侧，靠边时左右/上下避让，箭头/锚点仍指向来源。不能覆盖正在编辑的必要内容或落到屏外。

长备注/大量子项可以“展开”，窄窗或200%时转为主内容区域内的宽面板/覆盖式容器。保留同一个editorSession、字段焦点、选择区和滚动锚点，关闭后回到任务；不是另一次路由跳页。窗口/来源滚动导致锚点不可见时，明确退为有任务标题的展开容器或完成保存后关闭，不销毁仍有草稿的delegate。

同一时刻只一个非模态小面板。日期、时间、提醒、分类、标签的选择在面板内部切换内容并有返回，或使用明确内嵌区域，不继续popup套popup。模态危险确认独立处理，取消后回原面板。内容过长时只有正文滚动，标题/关闭/必要错误入口可达。

## 6. 设计接口和实现约束

`TaskEditorSession`持有taskId、rowVersion、原值、草稿、脏字段、校验/提交状态、待离开动作、父任务返回上下文和操作序号。字段组件只改草稿，C++命令决定业务、时间和树联动，Repository事务落库。

`TaskInspectorHost`只决定anchor、popover/expanded容器和可用尺寸。原行、列表、日历、子项/组件入口都请求同一会话；展开/收起不能复制第二个编辑器。异步结果按会话/命令身份消费，不能只判断全局busy变false。这里是最小职责分工，不要求引入通用表单框架。

样式复用现有DaymarkStyle和token，自有图标。HIG依据：[内容与桌面上下文](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[小面板](https://developer.apple.com/design/human-interface-guidelines/popovers/)、[键盘与辅助技术](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[反馈](https://developer.apple.com/design/human-interface-guidelines/feedback)。用户截图用于提取结构，不把Apple应用所有隐含行为当作Daymark既定规则。

## 7. 实施顺序与验收

1. 先建立共享editorSession和提交/关闭门，保留现有全页容器；补切任务、CAS、写失败、输入法、未完成异步和子项返回测试。
2. 列表信息按钮/键盘入口接入就近面板；验证一次草稿迁移、失焦保存、展开/收起状态和底部避让。
3. 子项、日历、组件复用同一面板；日历单击选择/双击打开按新目标更新，所有入口有单次点击或键盘替代。
4. 采用新面板统一保存规则，逐一迁出默认跳页。日历小时轴可以后续做，不让面板改造依赖整套日历完成。
