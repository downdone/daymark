# 独立账号窗口与登录体验（SYNC-07）

UX-68更新主窗入口：展开侧栏底部单行用账号图标加“登录”，已认证时显示login_label；长名省略且辅助名称保留完整内容。折叠侧栏保留账号图标入口，辅助名称同步当前账号；账号操作继续使用本独立窗口，不移回设置。退出或失效保留ACCOUNT资料时仍显示“登录”，与本窗口connected共用authenticated状态。最近删除与账号均收到底部工具区，侧栏备份快捷按钮移除、入口归入设置通用，详见[侧栏契约](sidebar-and-wordmark.md)。

2026-10-29。用户要求客户端专门设计登录UI、从设置移出，按“设计→评审→实现”推进。需求FR-042；取代sync-client-implementation中旧设置承载方案，服务与协议不变。实际状态只见PROGRESS。

## 1. 信息架构与操作链

主窗侧栏底部保留任务/工具分工，在最近删除与工具行之间增加“登录账号”入口；已有资料时显示“账号与同步”。入口不带任务计数、不接收任务拖放，图形和可访问名称始终可辨。侧栏折叠时在侧栏底部提供同一个账号图标入口（不与折叠按钮挤在同一窄行）；不新增主内容工具栏常驻动作。点击一次打开独立的原生拥有者窗口，主窗草稿先经navigateSafely保存；失败留在草稿，不能偷偷开始登录。

账号窗口是主窗所属的WindowModal工具窗口，原生标题“账号 · Daymark”，独立objectName accountWindow，不复用SettingsDialog的页、导航或分组。设置只保留外观、桌面、通用和关于；移除账号输入、冲突和资料切换。登录从不在启动时强制出现，关闭即可继续本地工作。

未登录：Daymark自主字标→“登录 Daymark”/“创建账号”→一句用途说明→同步服务器→账号→密码→注册时确认密码→错误/条件提示→唯一主按钮→登录/注册切换。窗口底部独立提供“继续本地使用”；连接中改为“在后台继续”，明确关闭仅收起窗口、已提交的连接继续，不能把注册取消伪装成服务端回滚。密码关闭/切换/发送即清空，显示密码开关也复位；服务器与账号首次打开/资料身份改变时预填，同一资料关闭重开保留输入；连接成功可更新隐藏表单中的规范身份，后台状态变化不覆盖正在输入的内容。

登录成功后窗口保留并转为账号概览：身份、服务器、实际连接状态、待传修改、立即同步；需要时出现恢复动作和完整冲突组；本地账号资料位于其后，退出作为次级动作并说明本机修改保留。冲突显示两版摘要，按钮明确“保留此设备”/“使用服务器版本”，沿既有原子决定。资料切换、恢复、冲突继续经过Main保存门，QML不操作SQL或重解释同步事实。

服务器无内置默认服务。未配置时展示输入及HTTPS占位；已有值折叠为可读地址和“更改”入口，不能让用户不知道资料将发送到哪里。切换注册保留服务器和账号，清空两次口令；不能承诺邮箱验证、邮件找回或第三方登录。

## 2. 视觉与布局契约

单一content表面，不把原设置卡片搬入弹窗。品牌作为轻量页首，标题使用Theme.headingSize，正文/字段标签/状态分别使用body/caption；只有主按钮使用accent，错误用danger且附文字。表单始终一列；输入有持久标签，账号不靠消失的placeholder识别，密码提供具名显示开关。

| 区域 | Daymark尺寸/关系（非Apple规定值） | 适应规则 |
|---|---|---|
| 窗口 | 初始560×680 DIP，最低420×440；夹紧可用屏幕 | 原生边框/关闭、可调整；超出可用高度时正文滚动 |
| 内容列 | 默认最大440 DIP，随文字适度增长，上下24/左右24 DIP起 | 列居中，不横向拉满宽窗；大字仍保持一个字段/行 |
| 表单 | 标签在上，值在下；字段间Theme.fieldGap/区域Theme.blockGap | 所有字段同一文字轴，不加嵌套卡片或装饰分隔 |
| 主按钮 | 整列表单宽，至少40 DIP且随字号增高 | 登录/注册位置随确认字段自然增加，禁止浮层覆盖正文 |
| 正文与页脚 | 正文只有一条纵向滚动；页脚独占自然高度 | 独立scrollGutter，键盘焦点自动揭示；200%仍可触达关闭/继续 |
| 账号概览 | 身份→状态→动作→条件冲突→本地资料→退出 | 无“上次同步”伪造时间，无空白未实现入口 |

## 3. 状态、键盘与可访问性

| 状态/操作 | 结果/约束 |
|---|---|
| 空表单 | 主按钮禁用，字段标签/服务器说明可读，首个缺失字段获焦点 |
| 注册条件 | 至少15个Unicode字符，两次密码一致；不一致显示文字，Enter不发请求 |
| 连接中 | 禁止重复提交、编辑字段或切换模式；BusyIndicator与实际状态文字；可后台继续 |
| 登录/网络/注册关闭错误 | 原账号/服务器保留，密码不缓存；显示服务端安全提示并允许重试 |
| 输入与显示密码 | 支持粘贴、密码管理器常见输入；不抢文本快捷键；开关具名且默认关闭 |
| Tab | 服务器更改/输入→账号→密码→显示开关→确认→主按钮→模式切换→页脚；隐藏控件跳过 |
| Enter/Esc | 最后字段Enter走同一提交校验；Esc关闭窗口且回到原入口；不触发主窗任务快捷键 |
| 成功/退出 | 自动展示真实账号状态；退出停止同步但保留本地资料及队列；不自动清空任务 |
| 关闭 | 清空密码/确认/显示状态，主窗恢复焦点；连接继续时标明后台语义 |
| 浅深/200%/窄窗 | 不依赖颜色；文本自然换行，主动作和页脚不重叠，滚动可达 |

## 4. HIG映射与实现前评审

依据项目强制P-13，映射[账号管理](https://developer.apple.com/design/human-interface-guidelines/managing-accounts)、[文本框](https://developer.apple.com/design/human-interface-guidelines/text-fields)、[可访问性](https://developer.apple.com/design/human-interface-guidelines/accessibility)与本仓库ui-baseline/ui-acceptance（UX-01/02/07/09/10/11）。采用清晰身份/可选登录、标签/键盘、可恢复反馈和字号适应；Qt与尺寸为独立实现，不声明Apple认证或原生能力已通过。

评审在实现前完成；以下是设计结论，不是测试结果。

| 评审问题 | 发现/结论 | 落实 |
|---|---|---|
| 入口是否可发现 | 设置中登录层级过深、与偏好混杂 | 独立账号入口，一次到登录；折叠侧栏保留图标 |
| 是否只是搬动旧设置 | 原布局将登录和大量同步管理同时堆叠 | 按未登录/已登录两种信息结构，登录只保留必要输入 |
| 自托管服务器是否被弱化 | 无默认域名，隐藏必填项会无法提交 | 首次展开；以后摘要+更改，始终能辨目的地 |
| 关闭与注册能否安全取消 | 请求发出后无法保证未创建账号 | 不假装回滚；连接中关闭明确为后台继续，数据保留 |
| 是否破坏草稿或本地模式 | 身份切换涉及资料库 | 开窗和身份操作均走保存门，本地使用始终可继续 |
| 状态是否真实 | 不能用队列为空推断已在所有设备同步 | 显示现有status/busy/pending/conflicts，不制造成功时间 |
| 键盘/大字是否完整 | 旧表单无持久标签，设置导航分走宽度 | 独立一列表单、可达页脚、焦点揭示及完整渲染验收 |

结论：采用此方案进入实现；不引入新的认证方式、产品注册政策或服务器接口。测试必须覆盖入口/设置移除、登录注册、隐藏控件跳过、错误/忙碌/成功/退出、身份切换与冲突保留、草稿门、浅深100/200%与窄窗。Go/双端既有用例保持，新增UI探针复用同一Ux38SmokeProbe实现，注册为独立account_access，原desktop_surfaces恢复到97，保留原预算；独立注册切片继续可执行并保留原断言对应风险。

## 5. 实现后的视觉与交互复核

复核生产QML的浅色登录/注册、错误/连接中、账号概览及深色200%窄窗；与设计对照后修正了以下问题：焦点滚动改为使用真实Flickable内容坐标（包括内容顶部留白）；页脚动作整行居中；同一资料关闭重开保留账号与服务器，密码/显示开关清空，身份改变才重新预填；账号概览顺序调整为冲突→本地资料→退出。连接中主动作提供进度提示，不能重复提交；资料选择返回任务，原资料保留。

账号图形独立绘制并追加在原图标词表末尾；预览裁剪探针改为定位实际被测图形，不再依赖其在Flow第一行，原裁剪/像素断言保留。设置页连旧“无需账号”页脚也已移除，以免与已登录状态矛盾。

展示状态用合成syncState覆盖错误/忙碌/身份/冲突/本地资料/恢复；这只是UI状态测试，不代表真正登录。另有真实窗口信号→Main保存门→TaskWorkspace/Coordinator的两次提交观察：使用关闭的loopback端口，不发送真实账号，验证命令种类/临时值和口令清理、失败后仍可本地使用。成功认证/同步仍由独立真实Qt↔Go可信TLS联调验证，不能用UI注入替代。实际测试数字和最终PASS/FAIL只在PROGRESS维护。
