# 提醒汇总与辅助录入：竞品观察及改进方案

2026-11-15；基于用户提供的敬业签三张截图及文字描述，对照Daymark 3.1.0（878fd3c）。本轮仅形成方案，不实现、不部署、不启用模型或上传内容。设计评审边界和实际状态见PROGRESS。遵循[新增能力标准](new-capability-standard.md)、[产品哲学](../product-philosophy.md)、P-01～05/13～22；关联FR-001/012/014/026/035及UX-01/04/07/09/11/13。

## 1 功能定义与实例

目标是缩短“随手记下 → 看懂时间 → 安排 → 到期集中处理”的操作链。维持统一任务、两级分类、可选标签、列表/日历同源；不引入另一种活动实体，也不增加常驻AI工作台。

### 竞品优势及证据边界

| 观察 | 用户价值 | Daymark取舍 |
|---|---|---|
| 桌面常驻、原位录入 | 不用离开当前工作就能记下和处理 | 沿用已有小窗/Mini/球及小窗原位录入，重点打磨连续输入和错误恢复 |
| 分类入口直接可见 | 快速切换不同工作上下文 | 综合原型改为可收起的左侧常用分类栏，替代顶部常用入口；沿用UX-77分类身份、搜索与上下文契约，不并存两套快捷导航 |
| 任务旁有日期、循环符号和剩余天数 | 快速看出时间压力 | 提炼成统一时间摘要，日期/具体时刻优先，临近时才增加倒计时；不为同一含义堆叠标识 |
| 通知入口显示数量，点击展开多张提醒（用户描述） | 一次看清积压、就地处理 | 建议一个“待处理提醒”汇总面板；全部数据可达，大量提醒使用单一列表，不创建很多顶层窗口 |
| 提醒卡能关闭、延时、完成（图中圆形控件用途需以实际交互为准） | 到期后马上采取行动 | 明确区分收起、此次忽略、稍后提醒和完成任务，避免按钮语义混淆 |
| 输入时出现可移除的日期标签 | 识别结果可见、可修正、可撤销 | 升级已有离线时间预览，不将“智能时间识别”全部包装成AI |
| 用户指出有AI自动活动识别 | 减少从自然语言提取安排的操作 | 设计为可选长文本提取；截图只能证实时间标签，不能据此确定竞品模型、准确率、是否联网或数据政策 |

截图里右侧文件图标可能来自桌面，不能据此认定产品支持附件。透明背景会影响文字对比，不作为本方案默认样式；账户推广、底部多工具和不明红点也不照搬。

### 三项建议能力

- **REM-02 待处理提醒汇总**：主窗和小窗的提醒入口显示同源待处理数量。点击展开所有当前待处理提醒；每项可查看、完成、稍后提醒或忽略本次。收起面板不改变提醒状态。
- **CAP-02 时间标签与直接修正**：沿TIME-01离线识别，输入旁显示可点击的时间摘要；仅日期不猜09:00，单时刻不猜时长，手工选择优先，移除标签只忽略本条识别。明确的起止范围/循环作为后续规则扩展。
- **CAP-03 辅助提取活动**：用户主动粘贴一段活动通知并选择“提取任务”，得到一项或多项可编辑草稿，确认后才创建。可选AI用于规则难覆盖的文本；图片识别另排后续阶段。

例：在2026-11-15输入“下周一交复盘”，沿现有规则预览“2026-11-16 · 计划日期”，不自动加提醒。粘贴“11月18日14:00—15:30在A会议室做活动复盘，17日18:00前提交材料”，预览两个候选任务；会议和材料截止分别展示原文依据，提醒由用户决定。标题优化与原文保存分别呈现，不静默改写原始内容。

## 2 现状与技术选型

| 基础 | 3.1.0已存在 | 本方案差量 |
|---|---|---|
| 时间识别 | TaskTimeRecognition、InputTimePreview；离线日期/时刻/中文表达，忽略、手选和歧义处理 | 改善标签表达；范围/循环扩展独立切片，不重复造解析器 |
| 提醒 | ReminderPresentation、reminderAlerts/pendingReminderCount；首项弹窗、完成/关闭/延后10分钟 | 从逐项弹窗升级同源汇总，解耦数据可见性与自动弹窗开关 |
| 提醒记录 | ReminderPage最近50条触发记录 | 保留审计/历史职责，不把记录条数当未处理数 |
| 小窗分类 | UX-77常用分类、分类搜索与稳定上下文 | 原型评估左侧常用栏替代顶部横排；不是已经实施的垂直导航 |
| 可选AI | 没有本方案的模型提取实现 | 新增显式触发、可撤销草稿；供应商/本地模型选型尚待闭合 |

推荐“确定性规则优先，可选模型补充”。单句时间输入继续离线自动解析；长文本由用户调用辅助提取。AI失败不阻塞普通任务录入，也不将账户同步登录视为AI数据授权。第一版不引入常驻本地大模型、自动监听剪贴板或后台截图。

## 3 架构与调用数据流

### 小窗综合原型修订

后续按用户要求以小窗为主要设计对象：一个小窗串起分类切换、原位录入、提醒汇总和提取确认。HIG内容优先/一致性落实为正文稳定宽度及共享弹层，用户控制落实为可收起分类栏、可改时间标签、确认后创建和提醒操作撤销；对应UX-09～13、UX-77及P-13/15。

- 左栏只放“今天”和常用分类；完整分类搜索及设为常用在同窗选择页。两级归属在完整列表缩进与正文路径明确，不将常用快捷项误画成完整分类树。取消顶部重复分类栏。
- 初始原型正文360、常用栏96、控件13、任务标题14 DIP；展开栏增加外框宽度，不挤压正文。窄空间收起栏，标题仍可选分类；这些是Daymark评估数值，不是Apple强制尺寸。
- 录入固定在底部；普通非空输入切分类前保存到原上下文，歧义日期待确认或忽略。未来任务保持各自日期，“今天”不为确认反馈临时混入未来任务。
- 铃铛展开一个全部待处理列表；任务详情、日期修改共用一个就近面板。关闭面板不确认提醒，撤销不关闭提醒列表；Esc关闭当前层并恢复来源焦点。滚动槽独立于正文。
- 文本提取使用正文内的原文/候选两步，候选默认摘要，点击日期就近编辑；选中项确认后创建，原文/未提交候选在切换时保留。原型仅使用预置合成结果，无模型请求。
- 原型含展开/收起两种可操作布局；以浏览器验证分类切换、歧义修正、12条提醒全可达、忽略/延后/完成/撤销、候选编辑及部分创建、窄宽无横向溢出。Qt原生窗口、系统提醒、物理输入和200%可访问性仍待实施后验收。

提醒：既有ReminderSchedule/TaskService认领事实 → ReminderPresentation筛选 → 分页ReminderInboxModel → 主窗/小窗共用ReminderInboxPanel。自动弹窗和手动入口读取相同集合；单项操作回到原服务/本机呈现状态，不在QML重新筛选Today或触发提醒。

录入：原始文本及打开时上下文 → 规则建议；用户主动请求时 → ActivityExtractionCoordinator → 可选provider → 结构/原文证据校验 → 候选草稿 → 用户确认 → TaskService批量事务 → Repository及原有日历/提醒/同步。模型不直接调用业务命令或生成SQL。

## 4 模块和生命周期

- ReminderInboxModel：按提醒发生身份管理稳定行、总数和分页；切资料清空旧投影。面板关闭释放视图，不销毁尚待处理的提醒状态。
- ReminderInboxPanel：同一时刻只有一个手动汇总面板，锚定最近点击入口；主窗与小窗不各弹一份。无活动窗口时继续沿既有独立到期提示能力。
- ActivityExtractionCoordinator：异步请求、取消、超时、去重及草稿世代。返回绑定原资料ID、输入摘要、时区和上下文；资料切换或文本已改时拒绝覆盖当前草稿。
- ActivityDraftValidator：检查字段、原文依据、时间/DST和两层父子限制，随后仍由TaskService最终裁决。
- provider：只承担一次提取，不写任务/偏好。供应商适配与平台密钥存储分离；不预建通用Agent、对话系统或工具执行框架。

## 5 协议及兼容

REM-02/CAP-02不新增网络协议；沿现有进程内命令。既有任务schema11、同步HTTP JSON v1及已触发认领事实保持兼容。

CAP-03模型请求的最小数据仅为用户选定文本、当前日期/时区和提取结构版本；默认不发送任务库、分类名、历史、账户身份或文件路径。分类建议首版在本机人工选择。可选发送的字段必须在请求前说明。取消/超时后丢弃晚回包；不在后台自动重试并产生不明费用。

候选响应格式version=1，字段白名单为title、sourceSpans、startLocal、endLocal、deadlineDate、reminderProposal、recurrenceProposal、locationText、notes、issues。所有值都是提议；本地复核枚举、长度、日期、时区、原文索引和条目数。未知字段拒绝/忽略须在provider契约中固定；实现前还须确定API认证、错误码、请求/响应大小和费用限额。无供应商选择前不冒称外部协议已定。

## 6 类型与接口契约

以下均为候选接口，不代表当前代码已提供：

| 接口/结构 | 契约 |
|---|---|
| ReminderOccurrenceKey | 资料命名空间＋taskId＋occurrenceAt；沿现有散列身份，周期每次触发独立处理 |
| pendingReminderPage(cursor, limit) | 只读当前有效待处理集合，返回items/total/revision/nextCursor；总数与分页同快照，后台新增不抢走焦点 |
| acknowledgeReminder(key, action, until) | 服务校验本机忽略或延后；未来时刻验证后持久化，成功才移除行。完成仍走任务CAS/父子规则 |
| ExtractionRequest | requestId、profileGeneration、inputHash、rawText、nowUtc、zone；rawText不进入诊断日志 |
| CandidateTask | 确定字段、待确认字段、原文证据及issues；不使用未经校准的百分比制造确定感 |
| commitCandidates(draftId, selected, context, idempotencyKey) | 校验草稿和资料绑定、服务层时间及标题约束；一次原子创建所选项，防双击和重复回包 |

时间策略：识别到“下午开会”等不完整表达必须待确认，不猜具体小时；只出现一个时刻不补一小时；多个日期不能拼成虚假跨天活动；“每月最后一个工作日”等当前规则不支持时保留原文、明确待设置，不静默近似。默认不提取父子关系，避免将两个独立活动误作整树联动。

## 7 数据库与事务

REM-02先沿现有QSettings本机呈现状态及提醒历史。现代码把到期弹窗开关与待处理投影耦合，必须改成“自动弹出可关、手动查阅仍可用”；复用同一个筛选来源。当前待处理恢复窗口为最近24小时及有效延后项，本方案第一阶段保持此窗口并在面板历史入口说明；“全部”指此范围全部待处理，不是所有过期任务或全部历史。更长期提醒保留策略另行设计迁移，不默默改变旧资料恢复行为。

单项延后不改原提醒时间/周期锚点，不同步；忽略不完成任务。暂不做“全部完成/全部延后”，避免QSettings批量部分成功及误操作。仅本机“收起面板”无需持久改写每条状态。

CAP-02不改schema。CAP-03首版草稿为内存态，保留原输入直到创建成功；关闭脏草稿须明确继续/放弃，失败不能清空。确认结果仅写现有Task字段；地点、链接、必要原文片段先作为用户可见备注，不冒充已有独立地点/附件字段。若需要草稿跨重启恢复、独立地点/来源字段或持久幂等键，实施前新增ADR及migration，不改历史迁移。批量创建及原outbox同事务，任一失败全部回滚；同步只传确认后任务，模型原响应/凭据不进入同步。

## 8 HIG/UX与完整状态

依据Apple HIG的[通知](https://developer.apple.com/design/human-interface-guidelines/notifications)、[输入](https://developer.apple.com/design/human-interface-guidelines/entering-data)、[就近面板](https://developer.apple.com/design/human-interface-guidelines/popovers)：简明有用、避免同一事项反复打扰、就地操作、少量相关功能、清晰输入反馈。具体尺寸使用Daymark现行token与真实工作区验证，不从截图按像素抄取。

### 提醒交互

1. 现有提醒入口改为“待处理提醒 N”；N只计待处理发生项，不计全部待办、未读公告或历史。0时仍可打开空态和提醒记录；不新开顶级导航分区。
2. 点击展开一个实体面板，标题“待处理提醒（N）”，各行显示任务名、分类路径、原定提醒时间；优先较早到期，顺序稳定。超过可用高度才出现独立滚动槽，头部及总数不滚动。全部数据可分页到达，禁止保留现有mid(0,10)造成第11条不可达。
3. 任务名打开原任务详情，已有脏草稿先走保存门；行内直接完成。次要动作“稍后提醒…”/“忽略本次”通过同一固定菜单入口；延后先保留10分钟默认，15/30/60分钟和自选时间为后续增强。
4. 面板关闭/外点/Esc只收起，不处理任务、不忽略提醒；忽略本次才移出待处理；延后在目标时间重新出现；完成沿父子规则并清理失效提醒。忽略可给短暂撤销机会，撤销失败原位提示。
5. 同时到期只出现一个自动摘要“有N项提醒”，点击进入汇总；不堆叠N个独立窗口、不每条重复抢焦点。手动汇总已打开时只更新数量/内容，不再额外弹摘要。新到项目不强制滚顶。
6. 系统通知由系统呈现，应用内做语义分组/去重，不能承诺控制系统通知中心布局。点击系统通知尽可能路由至对应任务或本应用汇总，平台不支持时提供等价本机入口。

### 输入交互

短句：输入 → 一行时间标签（完整日期/时刻和是否提醒）→ 点击直接修正 → Enter创建。移除标签忽略本条识别，不删除原文；IME组合中不触发提交。标签不伴随一个常驻“AI创作”大按钮。

长文本：用户粘贴 → 输入菜单“从文本提取任务…” → 一份可编辑预览 → 选择/修正 → “创建N项”。每项可查看原文依据，缺失/冲突字段以“待确认”表示。多任务预览用有足够空间的单面板，不能为了小而窄到日期/操作换行拥挤；同轴只留一条正文滚动。

状态必须覆盖：空/录入/规则可用/需选择/提取中/可取消/超时/无结果/部分不确定/提交中/写入失败/成功。Esc先关选择器，再返回保留输入的草稿；从不把Esc默认设为完成任务。控件位置稳定，Tab可达、辅助名称包含动作对象、浅深/高对比/100～200%与窄屏保持命中。

倒计时只做可选时间摘要：有精确结束/截止事实且临近时显示“还有3天”或“已逾期”；完整日期可查看，不在远期任务和无截止项强加倒计时。不新增倒计时看板或依靠动画制造紧迫感。

## 9 可靠性、隐私、性能

- 提醒完成/删除/取消/重新安排后，旧发生项即时失效；周期下一次不会被上次忽略吞掉。任务版本冲突重新读取后提示，不用缓存标题当成功。
- 服务状态、系统通知送达、本机展示三者分离。应用完全退出时保持原有“无后台提醒保证”的事实；开机/睡眠恢复策略按现行认领流程。跨设备延后不同步须在设置说明。
- AI只按用户显式动作发送当次选择文本；网络模式默认关闭，第一次使用先选处理方式/说明接收方。API密钥进平台安全存储，诊断只记脱敏错误/耗时/候选数；不把用户文本复用到可选择统计。
- 不读取其他应用/邮件/聊天记录，不自动上传截图或剪贴板。后续图片提取仅接收用户主动选择的图片，独立做OCR/模型方案与许可评审。
- 原文及模型输出都是不可信数据，文本中的“忽略规则/执行链接/删任务”等不能变成指令；无模型工具执行权限，不自动打开URL、不运行附件或脚本。
- 提醒用增量模型与分页，不为每个任务建常驻窗口/定时器。输入预览沿已有有限解析；远端请求有上限、取消及世代校验，不逐键调用AI。无需为本方案引入后台服务或新的账号体系。

## 10 单元、集成和用户链验收

| 范围 | 必须证明 |
|---|---|
| 提醒集合 | 0/1/10/11/100项全部可达，总数/游标一致；开关自动弹窗不影响手动查询；排序/焦点稳定 |
| 提醒动作 | 忽略≠完成，收起零写，延后不改周期锚点；CAS失败/设置写失败留行，重启/切资料隔离，旧提醒失效 |
| 通知窗口 | 主窗隐藏、小窗各形态及桌面固定状态下入口可用；同批到期只有一个自动表面，正常录入不抢焦点 |
| 时间规则 | 固定时钟下周/跨年/闰日/DST/过去/多个日期/范围/循环；不凭空补时长、提醒或未保存时刻 |
| 提取验证 | 无依据日期、无效字段、超长结果、重复/晚回包、断网/取消/超时、提示注入与不同provider返回偏差 |
| 创建事务 | 用户只选择部分候选、手改优先、固定资料/分类、重复点击只创建一次；写失败任务/提醒/outbox零半提交 |
| UX | 原位标签、取消保持输入、歧义可修正，任务/日历同ID；100/200%、浅深、键盘/IME和独立滚动边界 |

复用TaskTimeRecognitionTest、ReminderTest、TaskWorkspaceTest及既有小窗/输入QML探针；只补缺失边界，不用模型Mock通过冒充真实质量。AI用合成中文活动语料做字段准确率、缺失/幻觉率、多活动拆分及用户改动率评估，阈值须在选型时先定再验。测试/截图不用个人任务库；Windows/macOS实际系统通知、物理输入与读屏逐平台记录。

## 11 自审结论与待决项

本轮为单代理产品/技术方案自审，非独立评审；只批准方案收敛，不代表实施/测试通过。

## 12 推荐实施顺序与交付边界

1. **P0 / REM-02**：提醒数→完整集合、现有动作、单一摘要/汇总、防10条截断、状态恢复。第一批收益明确且无需模型服务。
2. **P0 / CAP-02a**：现有离线时间建议改为直接可修改标签，主窗/小窗一致；保持现有规则，不扩范围。
3. **P1 / CAP-02b**：明确起止范围、常见循环的规则扩展及保守歧义处理；可选临近倒计时、更多延后时间。逐项独立验收。
4. **P1候选 / CAP-03**：长文本一到多任务提取、原文依据、编辑预览及原子创建；先完成模型/隐私/费用/协议选型与质量评审。
5. **P2候选**：用户选择图片后提取活动；独立验证OCR、时间和多活动质量后再纳入。附件管理、聊天助手、自动抓取和工作台不列入本方案。
