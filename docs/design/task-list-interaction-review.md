# UX-37：任务列表交互复审与改进方案

2026-10-27追记：用户最新macOS提醒事项对照由[UX-43列表精修](reminders-list-refinement.md)覆盖本文的独立关系图标列；当前使用缩进/展开箭头、智能范围父名及数量入口。本文保留原设计过程，多选/菜单/草稿与原有验收继续有效。

2026-10-26。用户要求系统分析任务列表：无法顺手多选、父子任务应通过图标区分、详情打开不跟手。本文保留源码/合成画面复审及采用规则；随后用户已授权实现选择、关系及全局密度，代码映射见文末。当前实现状态见[PROGRESS](../PROGRESS.md)。基线为59b1644；保留已有打包修订及本地架构提案。

用户随后追加侧栏/详情密度不统一截图；全局约束与逐表面迁移见[UX-37D桌面密度](desktop-density-review.md)，与本方案共同作为本轮实现输入。

涉及PRD批量编辑P1、FR-025/030/031/035，UX-01/02/04/05/07/09/11/14。列表和日历继续操作同一任务；本方案不更改QueryService的范围语义、两层任务限制、树操作联动、CAS及原子提交。

## 1. 总体判断

问题集中在“选择、编辑、完成、展开层级、拖动”争用同一行，用户缺少稳定预期。多选有底层命令，但入口和手势不完整；父子关系有数据，但表达依赖当前视图；详情已有共享会话，但呈现与填充路径仍耦合。应先整理这些关系，再做局部视觉调整。

证据来自当前源码及本轮隔离fixture截图：`build/task-list-review/`。已查看list-scoped和inspector-nearby两图；均为Qt offscreen合成数据，不访问真实用户任务，也不代表物理交互或首帧延迟已实测。截图探针后续在stage27（月历拖动目标）失败，不能将此前截到的画面称为整轮通过。

## 2. 设计依据及取舍

- [Apple HIG Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)：选择应有可辨反馈，层级内容需表达结构。落实为独立选择状态、固定关系图标列和树展开控制。
- [Apple HIG Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers/)：临时面板聚焦少量相关任务，保持来源关系，避免遮挡必要内容，自动关闭应保护输入。落实为紧凑首屏、条目锚点和同一保存门。
- [Apple HIG Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/)：清楚层次、熟悉控制和精细反馈。落实为状态与手势分工；Windows用Ctrl，macOS用Command，多选不能照搬仅触控的“进入编辑模式”。

下文字号、列宽、毫秒和分位数均为Daymark拟定验收值，不是Apple官方数值。保留用户此前要求的“点击标题原行展开”，不在本次分析中擅自改成所有单击只选中；详情仍有信息按钮及键盘入口。

## 3. 已确认的问题

| 优先级 | 当前事实 | 体验后果 | 证据入口 |
|---|---|---|---|
| P1 | 多选入口在页面更多菜单；行没有Ctrl/Command增选、Shift区间选择、列表全选 | 用户按桌面习惯操作时直接进入编辑，感觉不支持多选 | Main.pageMenu、TaskRow.holdArea、taskList.Keys |
| P1 | batchSelection与currentIndex分开；行高亮只跟currentIndex | 勾选多项仍只有一项有主要高亮，选择集合与当前位置难区分 | Main.toggleBatch及delegate.highlighted/selectedForBatch |
| P1 | 多选增加方框，但完成圆、信息按钮、拖动手柄仍有独立动作 | “选中”和“完成”并列，批量整理时可能误执行单项动作 | TaskRow.contentItem、completionAction、handleArea |
| P1 | 原行单击经loadEditor→fillEditor先打开完整面板，再隐藏面板挂接原行；delegate未就绪时16ms重试，超过限制回退完整面板 | 简单编辑承担完整字段填充；同一入口可能显示不同容器，有布局/焦点反复变化风险 | Main.openQuickEditor/attachQuickRow/fillEditor |
| P1 | 非后台busy时navigateSafely直接返回；后台busy时仅保留一个backgroundNavigation | 某些点击可能没有即时反馈；用户无法区分“正在保存”和“没有点中” | Main.navigateSafely |
| P1 | 详情锚点以行尾坐标一次赋值；窄于1000或文字尺度≥1.5时自动改整块覆盖容器 | 位置未持续关联来源，跨阈值变形；用户感到详情脱离任务 | Main.openEditor、inspectorExpanded、editor.x/y/width/height |
| P2 | 普通树使用20DIP缩进和细L线；智能范围平铺，不同位置才出现父任务文字 | 子任务身份随视图变化，缺少稳定图形语义 | TaskRow.taskDepth、parentTitle、background |
| P2 | 子任务数量采用蓝色“子任务0/1”文字；父项箭头只在普通树可见 | 展开树、查看子项详情和完成进度三个含义混在一处 | TaskRow.childLink、taskChildren |
| P2 | 当前分类列表仍逐行重复同一分类；metadata Flow可堆叠多项文字 | 标题与辅助信息密度失衡，列表扫描慢 | TaskRow.metadata、本轮list-scoped截图 |
| P2 | 左侧所有行均预留24DIP展开槽，根/子/普通任务共用完成圆，缺少独立关系槽 | 空隙占位与缩进共同承担层级，无法单靠图形识别身份 | TaskRow.contentItem/leftPadding |
| P2 | 批量UI探针直接调用showVerificationPage进入对话框，事务测试覆盖服务而非修饰键选取链 | 测试通过无法证明用户能实际选中多个任务 | AppRuntime批量场景、TaskWorkspaceTest、Ux34WorkspaceTest |

需避免误判：TaskWorkspace.task使用QHash缓存读取；Repository在worker执行。TaskListModel.replace已有插入、移除、移动及dataChanged，不能把它描述为每次整表reset，也不能无证据认定SQLite阻塞导致弹出迟滞。详情本身是Pane，open仅visible=true，没有显式长入场动画；“缩短弹窗动画”不足以解决现有路径。

## 4. 选择与编辑的统一规则（拟实施）

| 操作 | 结果 | 禁止的副作用 |
|---|---|---|
| 无修饰键单击标题 | 选择该项并原行展开，保留既有快捷编辑方向 | 不先打开完整详情 |
| 单击行内其余非控件区域 | 只选中该行；已有脏草稿先走保存门 | 不抢标题输入焦点 |
| Ctrl/Command单击行 | 增选/取消该项，修饰键优先于原行展开 | 不编辑、不完成、不拖动 |
| Shift单击 | 按当前可见顺序选择锚点到目标范围 | 不把折叠、过滤掉的条目暗中加入 |
| Ctrl/Command+A（列表聚焦） | 选择当前范围内所有可见任务 | 文本编辑聚焦时仍为文字全选 |
| ↑↓、Shift+↑↓ | 移动键盘位置；后者扩展区间 | 不自动开启详情或改完成状态 |
| 信息按钮 / Enter | 单选时打开该任务详情；编辑字段Enter遵循字段语义 | 不覆盖输入法确认、不为多选挑任意一项 |
| 完成圆 | 单选浏览时执行完成；保留已有提交后动画 | 与选择标记不互换含义 |
| Esc | 先取消当前拖动/局部选择器；编辑退出走既有保存门；否则退出多选 | 不丢合法草稿，不顺便完成任务 |
| 右键 / Shift+F10 | 选中集合内右键作用于集合；集合外右键先单选该项 | 不偷偷打开编辑器 |

显式“选择”按钮保留在列表工具栏/可用的命令菜单，无修饰键用户也能进入。进入后直接点击行增选；这时完成圆列用方形选择标记替换，尺寸不变，单项完成、详情和拖动入口暂不参与操作，退出后恢复。无需同时摆出两种勾选控件。

选择模型独立存储selectedTaskIds、currentTaskId、anchorTaskId。焦点位置、选择集合、当前编辑身份分别管理，避免用currentIndex承担三件事。排序/模型增量更新按ID保持选择；搜索/切范围时清空选择，折叠移除不可见选择并更新计数。全选只包含当前列表匹配且可见项；跨分组区间按呈现顺序，不含分组标题。

多选动作在列表固定工具条显示“已选N项”，直接提供完成、分类、日期、标签；更多中只保留确有批量支持的动作。沿用已有四种批量命令和原子事务，不放批量永久删除按钮。父子重复选择由C++去重；完成/分类移动明确显示“选中N项，实际影响M项”，不能把级联影响伪装成显式选择。标签默认不得静默替换原值：沿用替换行为时明确标为“替换标签”并给预览。

命令预览捕获taskId/rowVersion，提交时校验该快照。选择长期保持不等于永久沿用旧版本，也不能刷新版本后悄悄绕过CAS；预览后发生变更须提示重核或冲突，整批失败零修改。

## 5. 父子关系与视觉骨架

建议固定列结构：展开槽 → 完成/选择槽 → 关系图标槽 → 标题/摘要 → 信息按钮。展开箭头仅表示展开/收起；完成圆仅表示任务状态；关系图标表示身份，三者不互相替代。

| 任务类型 | 关系图标 | 辅助信息 |
|---|---|---|
| 独立、无子项任务 | 无额外图标，保留列对齐 | 必要日期/提醒 |
| 有子项的父任务 | 原创“分支列表”图标 | 紧凑2/5进度，辅助名称读作“5项，已完成2项” |
| 子任务 | 原创“子项分支”图标 | 普通树配轻微缩进；平铺范围配“图标＋父任务名”关联摘要 |
| 兼容旧深层任务 | 同样关系图标，详情保留实际父链 | 不静默扁平化、不增加新建深层入口 |

图标在今天/计划/全部/分类/搜索始终一致。普通树保留弱缩进作为辅助；细连接线可移除或仅在键盘导航/悬停时提示。仅靠图标能辨“这是子项”，仍不能知道属于哪个父任务，所以智能视图须保留父任务名。图标具有可访问名称，关系不只靠颜色区分；原创QML/vector绘制，不引入SF Symbols资产。

行内标题建议默认14DIP、辅助12、分组12～13、详情任务标题16，不能以全局缩小解决拥挤。按全局密度追加：紧凑单行36/双行44起，舒适40/48起，200%文字自然增长；关系图形14～16，独立动作命中至少32。数值须经宽/窄实测再定。

摘要按“逾期/具体时段 → 父任务关联 → 提醒/子项进度 → 其他标签”排序；最多一行，溢出聚合，不让Flow无限长高。当前分类页面省略重复分类名；标题保留主要对比度，辅助文字降低权重但满足对比。多选高亮作用于所有selectedTaskIds；currentTaskId的键盘焦点为细边或独立焦点态，不用深浅近似的多层填色表示不同状态。

## 6. 详情跟手：拆解路径而非只调动效

当前路径可归纳为：

```text
点击原行 → 离开保存门 → loadEditor/fillEditor
                           ├ 填完整字段/分类/关联/循环
                           ├ editor.open + 标题焦点 + 滚动归零
                           └ 关闭完整面板 → attachQuickRow → 原行编辑焦点
```

拟改为同一会话的两个直接入口：

```text
点击标题 → 选择反馈 → 读取已有task缓存 → 会话草稿 → 原行呈现
点击信息 → 选择反馈 → 同一会话/草稿 → 锚定紧凑详情
                                   └ 按需打开时间/循环/分类等编辑内容
```

TaskEditorSession目前主要保存ID/dirty/saving等状态，字段原值和草稿仍分散在Main及隐藏表单中。下一片应让任务快照/草稿成为会话事实，原行与详情绑定它；允许重用字段组件，但禁止依靠“先填充隐藏完整表单”建立原行数据。不引入通用表单框架，不复制两份保存实现。

详情默认首屏为标题、备注摘要、时间摘要、提醒、分类/标签及子项数量；编辑某属性时才在同一容器内展开相应控件。420DIP候选宽度可沿用，但不再无条件以360最小高度装完整表单。详情/子项仍可在同面板切换，真实子项支持返回父任务且保持滚动位置。

打开时保留来源taskId及相对锚点；源行在视口内滚动时轻量更新定位，避免覆盖任务标题与完成圆。空间不足时优先换侧/调整上下位置；小窗/大字号使用明确的展开形态，不在同一阈值附近反复跳换容器。原行离开视口而有草稿时保留会话与明确任务标题，不因delegate销毁丢输入。

先显示按下/选择反馈，再填充必要内容。切任务有脏草稿时继续遵守ADR-020：保存成功才切换，失败保留所有输入和原对象；排队动作按会话令牌消费，只执行用户最新有效意图，不能让旧回调打开已过时目标。真正不能执行时显示短暂忙碌状态，不静默吞点击。

性能调查先测四个时间点：pointer event、会话草稿就绪、必要布局稳定、来源窗口frameSwapped。冷/热打开、不同入口、脏草稿保存分别统计；先用缓存快照避免多次taskMap及无关catalog/links投影，再按profile优化局部布局。保留现有增量模型、QueryService及worker边界。cacheBuffer=0用于规避已记录的Qt6.10.2问题，不能未经回归直接增大。

拟验收：选择反馈在下一帧出现；60Hz实机热打开首个可操作帧P95≤100ms，30次以上同时记录最大值；冷打开、保存等待与I/O单列。可选淡入80～120ms，无弹跳位移，减少动态效果时取消。首帧指标不能用signal发出、visible=true、菜单计时或offscreen成功替代；尚未测得本版本详情的实机延迟。

## 7. 下一里程碑：三个纵向切片

| 顺序 | 交付 | 边界与验收 |
|---|---|---|
| UX-37A 选择闭环 | 修饰键/区间/全选/显式选择、统一高亮、批量工具条 | 普通/树/搜索/完成范围；真实指针路径；选中与完成不冲突；父子N/M预览；CAS/失败整批回滚；100/1000/10k选择基准 |
| UX-37B 关系与行骨架 | 固定关系槽、父/子图标、摘要去重与密度 | 今天/计划平铺及普通树/搜索同一身份；隐藏子项不漏智能匹配；普通与兼容旧层级；浅深/880/200%/读屏名称 |
| UX-37C 详情路径 | 草稿会话解耦、原行直接呈现、紧凑锚定详情、首帧埋点 | 30次冷/热测量；脏草稿切换/CAS/磁盘失败；连续点不同任务；滚动源行/缩放/展开收起/IME；旧回调不覆盖新目标 |

先让选择能用，再换关系表达，最后据测量优化详情；不可只替换图标就标整片完成。现有Windows的完整UI/watchdog失败仍是发布门禁；新增选择/响应验收不能复用服务测试或此前macOS截图冒充。

本轮选择、关系/摘要及密度实现保持PRD时间/树语义和ADR-020的离开保存协议；UX-37C数据会话解耦和30次首帧性能矩阵继续独立追踪，不随图标或密度改动宣称完成。

## 8. 实现映射

`TaskSelection`维护可见ID、版本快照、当前位置及锚点；`Main/TaskRow`实现Shift范围、Ctrl/Command增减、列表全选/键盘范围、显式入口和集合内/外右键规则。macOS的Qt键盘事件将Command映射为ControlModifier、物理Control映射为MetaModifier，因此修饰键逻辑与平台行为一致；Windows保留Ctrl。依据[Apple提醒事项多选说明](https://support.apple.com/en-ca/guide/reminders/remnee767c58/mac)。

单选菜单保留该任务命令；多选只呈现可执行的批量完成/重新打开、分类、开始日期、替换标签，修改前继续预览影响。批量恢复通过TaskService一个事务，校验所有版本；同次完成后代恢复，其他独立完成子项保留，任一失败整批回滚。混合状态集合不显示不适用的完成/恢复/日期命令，不伪造尚未支持的批量删除/置顶操作。

关系使用独立原创分支图形，并以父任务名和进度补充含义；多选时方形选择替换完成圆，停用单项详情/拖动。菜单活动填色只由Menu当前项驱动，禁用项始终透明。`Ux37SmokeProbe`通过真实Qt合成指针/键盘覆盖实际入口、完成菜单禁用悬停、文本全选分工、宽窄/主题/密度及详情时间同行；服务测试覆盖旧版本和中途写失败回滚。

原行入口避免完整面板先开再关；保存期间的新导航保留最新目标。完整字段仍参与共享保存校验，不能把这部分改进说成已完成独立会话重构。所有证据及未测范围见PROGRESS。

细项边界：本轮保留既有普通点行原行展开；“行内空白只选中”的进一步命中细分、滚动来源锚点持续跟随及完整会话数据解耦，仍属于UX-37C，不将当前改善冒充这些细项已通过。
