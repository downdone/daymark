2026-10-23。关联FR-010/011/012/013、UX-01/04/06/09/11/13。本轮实现组件调整；日历部分为设计建议，未实现新事件能力。沿用[UI基准](ui-baseline.md)及[验收](ui-acceptance.md)。

## 1. 组件问题与调整

用户截图为展开态Floating；Mini是单行摘要。现有全局普通按钮最小36DIP，浮窗两排工具区占用过多阅读空间。问题主要是操作数量与常驻排数，单纯把按钮压得很矮仍会分散注意力。

- Floating只保留一排表头：今天/待办与完成数、添加、收起、更多；取消常驻“打开主窗”“隐藏”大按钮，这两项移入更多菜单。
- 工具图形16DIP起，命中区32DIP起、无常驻描边，hover/焦点才强调；大字时图形最多24，命中区最多36。尺寸是Daymark桌面判断，不是Apple移动端规范。
- Mini保留摘要和图标展开，48DIP默认高度；摘要可省略，展开入口不能挤出窗口。
- 图标始终可见，提供中文可访问名称、悬停/键盘焦点提示和焦点轮廓。表头拖动与按钮分区；任务完成、添加、隐藏、打开主窗及穿透外部恢复命令保持原路径。
- 字体不因窗口缩小而强制缩小，任务正文仍跟随用户字号。减少控件噪声，不以进一步降低背景透明度牺牲可读性。

## 2. Apple官方事实与适用边界

访问于2026-10-23，仅阅读公开官方资料，无客户端实测或素材提取。

| 官方事实 | Daymark判断 |
|---|---|
| 日历可显示、创建、编辑及完成已排期提醒事项；全天与定时提醒分别进入全天区和对应时刻；可关闭显示而不删除提醒事项。[日历中的提醒事项](https://support.apple.com/en-ie/guide/iphone/iph14f1d32a5/ios) | 共享任务记录与双向操作优先于复制一份“日历任务”；可见性过滤不修改排期 |
| 事件具有开始/结束时间，可设置位置、提醒等信息。[创建及编辑事件](https://support.apple.com/guide/iphone/create-and-edit-events-in-calendar-iph3d110f84/ios) | 事件表达时间占用，任务表达待完成行动；两者可同屏但有不同操作 |

Apple支持页未在上述说明中建立通用的“事件关联任务”关系模型。下文关联设计是Daymark建议，不宣称为Apple现成功能。Apple重复提醒的完成约束也不替代本项目既有独立实例语义。

## 3. Daymark现状与差距

当前CalendarService已将start_on/deadline_on映射到月/周视图：同日合并，不同日显示同一task.id的两个语义标记；点击打开同一详情，改期修改明确字段，失败回滚。完成态有开关，未排期任务可安排。现有服务是任务日历，没有独立CalendarEvent或事件时间段。

当前体验差距：日格标题容易省略；当天列表固定200DIP，大字/窄窗不够灵活；缺少日历列表内直接完成入口；常驻设置占顶栏；任务计划与截止主要依赖短符号解释。周视图是全天任务列表，符合FR-011，尚无小时轴。

| 概念 | 当前存储/含义 | 建议呈现 |
|---|---|---|
| 计划开始 | start_on，本地QDate；不是持续时间起点 | “计划”任务项，可直接完成 |
| 截止 | deadline_on，本地QDate | “截止”标记；与计划同日合并显示两种语义 |
| 通知 | remind_at_utc，UTC瞬间 | 提醒标记或详情，不据此生成占用时间块 |
| 事件 | 当前没有；未来需独立模型 | 全天事件或起止时间块，可关联任务 |

## 4. 推荐的日历操作链

月格用于扫视负载与截止，选中日期后在当天议程中读全标题并操作。宽窗议程在右侧，窄窗/大字放在日历下方或可关闭面板，不固定200DIP。默认选中今天；月格+N显式进入当天议程。

当天议程中任务带完成圈和“计划/截止/计划＋截止”文字；点击正文打开同一草稿，点击完成只提交统一任务状态命令。完成后随“显示已完成”选项隐藏或变淡，可恢复；不能在两个日期各维护一份完成状态。新增任务预填选中日期；拖动合并标记仍先选择改开始或截止。

后续有事件时采用同一议程分区：

| 10月23日示意 | 含义与操作 |
|---|---|
| 全天 · ○ 交付设计稿 · 截止 | 可完成任务；打开任务详情 |
| 09:00–10:00 · 产品评审 | 时间占用事件；打开事件详情 |
| ↳ ○ 准备评审材料 | 关联任务；完成不取消评审事件 |

事件与任务用图形、文字类型及操作共同区分，颜色只作辅助。新增入口在真正具备事件能力后才提供“任务/事件”选择，当前继续明确“新建任务”。新增显示过滤不得改写QueryService中的Today/Upcoming规则。

## 5. 事件关联的建议契约（尚未实现）

- 本地Event独立于Task：全天使用本地日期区间，定时使用UTC起止与展示时区；全天结束日是否排他须在ADR中冻结。禁止拿start_on/deadline_on或remind_at冒充事件时段。
- 通过显式关联表连接：一个事件可有多个准备/后续任务，一个任务可关联多个事件；初期UI只显示必要关系，不做自动生成任务。
- 完成任务不取消事件；删除事件只解除关联、保留任务；删除任务不删除事件。双方软删、事务与撤销分别定义。
- 事件改期不静默推移任务日期；可在后续独立设计中提供带差异预览和冲突处理的明确批量调整。任务改期也不自动挪动事件。
- 不自动连接iCloud、系统日历或账户。外部导入/同步属于另行授权的范围。
