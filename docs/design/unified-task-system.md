## 分析：哪些是同一对象，哪些是独立维度

当前实现有四个根源问题：项目/领域区别要求用户先理解方法论；任务/独立事件/重复模板使用不同编辑器和完成行为；清单项有类似任务的勾选，却不能独立安排；今天关注/今晚/重要性混在一个选择中。只替换名称、增加控件或将两类列表放一起不会完成统一。

目标模型是“任务 + 可选属性”。任务可以只有标题，也可以有子任务、分类、日期时间、循环和提醒。日历、特别关注、今天、分类都是同一任务的不同视角。分类回答放在哪里，父任务回答属于哪件事，标签回答怎样横向查找；置顶回答显示顺序，特别关注表达重要性，日期时间表达安排，提醒表达何时提示。任何一项都不强迫新建任务时填写。

| 用户要求 | 理解及设计裁决 | 数据/验证重点 |
|---|---|---|
| 1 分类 | 项目/领域合并为两级分类；无上级为一级，选择一级为二级。可升/降级，侧栏真实缩进 | 禁自引用、循环及三级；带二级的一级降级时先明确所需整理，不能悄悄挪动所有子分类；移动不改任务身份 |
| 2 提醒循环 | 对同一任务周期性提示，与“重复产生下一任务”不同 | 本地墙钟+时区、UTC触发、唯一认领；错过多次只汇总一次，下一次在未来；任务完成/暂停后停止提示 |
| 3/追加 子任务 | 删除清单概念；已有任务可选择父任务，任务列表呈树形，详情/子任务分tab | 子任务也是完整Task，有独立状态/安排；禁自引用及祖先循环；父完成不静默完成子任务，父软删后子任务仍可访问 |
| 4 特别关注 | 单独的特别关注开关及系统视图，不叫分类、不改变分类归属。今天安排用“加入今天”，启用后可选白天/今晚 | 重要性与时间独立；取消今天安排不影响重要性或日期，日期仍命中Today时提供明确安排选择 |
| 5 日期 | 图标直接打开日历，取消快捷预选菜单；可清除日期、手输及键盘选择 | 统一所有DateField；Esc不保存；Alt+Down/方向键/Enter保持 |
| 6/7 编辑动作 | 右上角统一保存状态、保存及更多。更多含取消任务、删除、查看编辑记录；记录用短时弹层 | 显式保存继续；脏草稿仍保护；删除确认及撤销；编辑记录来自真实成功修改而非把创建时间换个名字 |
| 8 备注 | 行内简易详情备注悬停显示完整内容，可选择/键盘进入详情 | 长文本tooltip有可滚动或合理高度/宽度，完整正文始终可在详情读取；PlainText避免解释用户HTML |
| 9 置顶 | 任务可置顶/取消，顶层或同父任务内优先显示，不改日期和重要性 | 持久化、跨视图同一事实，排序冲突/CAS；父子不因置顶拆散，手动排序不能越过置顶组边界 |
| 10 统一任务/循环 | 日历单次与循环事件转为完整任务；任务有循环开关和开始/结束时间，同一编辑器、同一完成/软删/搜索 | 不保留两份可写实体；旧事件ID/时间/时区/循环/关联/提醒历史迁移。截止和安排结束分开；循环编辑明确本次/后续范围 |
| 11 主题 | 设置外观明确展示跟随系统/浅色/深色，立即生效并持久化 | 已有themeMode复用，不新增另一偏好；返回/重启、200%与高对比回归 |

## 软件哲学与信息架构

主线仍是收集→澄清→安排→执行→回顾，原则P-14“简约而不简单”。不预置分类或层级，不要求区分项目/领域/事件。任务的完整能力按上下文逐步出现，新增字段不是首页表单。

侧栏：收集箱、今天、即将到来、随时可做、以后再说、特别关注、已完成；取消规划分区，日历位于内容区视图切换。分类分区显示一级→二级，标签有数据才出现。重复不再是与任务并列的对象；循环任务作为普通列表筛选入口，未完成迁移前不得删除旧内容的访问路径。

编辑主区：固定顶部返回、任务标题上下文、未保存/保存中/失败状态、保存、更多；正文“详情 / 子任务”tab。详情依次为标题备注、分类/标签、安排、提醒、循环；无日期时用“添加时间安排”，无提醒/循环时一个清楚入口或开关。子任务tab左侧列表、右侧独立任务编辑面板；窄窗改为列表→子任务面板并有明确返回父任务，不套用多层模态，不复制父/子草稿。点击子任务仅切换目标，已有修改先保存/放弃/取消。

列表：标题、完成状态及已有必要日期，父子以缩进和展开箭头区分；详情按钮仍直达完整编辑。置顶图形+名称可识别，右键/键盘提供同一操作。特别关注用独立图形及对应视图，不为每项添加文字徽章。事件迁移后的任务可以完成、分类、搜索、拖到侧栏和成为子任务。

## 时间、循环与完成的统一

计划开始日决定进入行动范围；截止日期是必须完成的日历日。时间安排是可选的开始/结束区间，全天用本地日期且内部结束排除，定时用UTC瞬间+IANA时区、结束排除。旧任务开始～截止范围仍保留原义，旧事件不能把结束自动当截止。午夜终点不多占一天；跨周/月横条引用同一任务；同日定时任务显示时刻摘要，无小时轴或忙闲计算。

任务循环复用可独立完成实例的规则能力，支持日/周/月/年及完成后N天；开关关闭停止后续生成，保留历史和本次内容。普通任务打开循环时原任务成为首个实例，不另造一条相同任务。编辑默认本次，修改循环明确作用于后续未改实例；已完成/手改实例保留。月末/闰日与DST歧义处理明确，不能用固定86400秒替代本地日期。

周期提醒只提示同一实例，不生成新任务；任务循环生成不同实例，两者在界面分开命名。当两者同时启用，提醒跟随当前实例，完成后停止本实例提醒，下一实例按规则设置。应用退出不承诺后台唤醒，不新增守护进程。

## 存储与迁移方案

- 使用追加migration，不重写001～004；升级前WAL一致备份失败即停止。只在QTemporaryDir做自动迁移，不操作当前真实用户库。
- 分类沿用既有projects实体作为内部兼容存储，增加self parent列，将旧领域转入分类、原项目归入对应一级分类，直接领域任务改同一分类ID；旧字段/表只为历史导入兼容，不继续形成第二份可写归属。公开API/UI使用分类词，内部legacy命名分批收敛。
- Task增加父任务、置顶、特别关注、可选时间安排和循环提醒事实；Recurrence模板为内部生成器，不再是独立用户对象。任务元数据/清单项迁移生成子任务，保留顺序、文字和完成状态；旧id命名冲突必须失败回滚或建立显式映射，不能忽略覆盖。
- 旧events迁成Task；准备/跟进关联保留为任务关联，不能擅自把多对多关联改成只有一个父任务。原事件提醒认领历史保留、避免迁移后重复触发；旧生成规则关联同一统一任务规则。
- 真实编辑记录记录成功事务的时间、动作及变更字段，不存到stdout；失败/取消不写成功记录。任务/关系/循环配置同一事务+CAS，导出/导入/恢复支持新schema与历史1～4兼容。

服务层负责全部查询、父子/分类循环、时间和规则校验，Repository唯一执行SQL；QML只呈现/草稿/发命令。日历和桌面组件用同一Task ID，禁止迁移后同时维护events和tasks两份可编辑记录。

## HIG与状态契约

依据沿用[官方调研](ui-research.md)及P-13的Simplicity/Purpose/Agency/Hierarchy/Sidebars/Modality/Accessibility；具体token和Qt表达由Daymark定义。主要动作直接，次要动作有名称；短时日历/记录可用弹层，任务编辑与子任务是稳定内容面板。完整状态覆盖空/浏览/编辑/未保存/忙碌/失败/禁用/完成/删除撤销。键盘顺序与视觉一致，Tab切换分段，Esc先关闭临时层，草稿仍受保护；宽窄、浅深、200%和真实读屏分别验证。

## 统一时间实现补充（UI-27C，设计先于实现）

时间安排采用Task的可选子组件`task_schedules`：只有task_id及全天/定时起止、时区、相对提醒，不另存标题/备注/状态。旧Event结构可在内部暂作日历时间投影DTO，持久化及所有命令都通过同一个Task；旧events表只用于历史兼容，不继续写入或与Task双向同步。日历中的未来循环实例也是实际Task ID，不能用系列根ID代替实例完成。

循环继续用内部recurrence_templates生成独立实例，追加source_task_id及完整的默认属性快照。普通任务开启循环时原任务成为首个实例；后续实例从快照复制分类、父关系、重要性、日期相对偏移、时间安排、提醒和标签，不复制置顶及完成状态。子任务有各自循环，父任务循环不擅自克隆其整棵子树。默认内容编辑仅本次，明确选择更新后续或更改循环配置才更新模板；停止循环保留本次/历史/手改实例，未修改未来实例软删，影响在保存前就地说明。

schema8转换由一个迁移事务创建时间组件/任务关联及规则来源，再将旧事件变为Task（保留ID，冲突整体失败回滚）、保留本地时区和排除式结束、转存准备/跟进关联和已触发提醒。旧事件没有完成事实，不能伪造已完成；历史时间仍保留。过期很久的未触发事件提醒不在升级时补发；相对提醒配置保留，未来实例正常计算。任务历史、旧模板和手改标记保留，导入/预览使用同一转换规则而不是第二套UI逻辑。

补充提醒与后续编辑边界：旧循环事件的历史认领归入实际任务实例，保留原提醒时间与触发时间，不重复投递；迁移前超过24小时的未触发事件提醒只保留时间配置。新规则分支只补本次之后的未修改实例，不重新生成一套历史任务；默认新开循环从今天起补齐，原任务仍是首个实例。认领已存在时修复状态但不再次通知，规则快照保留前身认领来源以防后续编辑重复提醒。循环筛选内新增默认为每日循环，可在同一详情修改；收集箱任务开启循环后成为可执行任务，未填计划日则使用今天。
