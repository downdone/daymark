# TIME-02 / CONS-01 同一任务周期与跨界面一致性

## 账号周期上线契约

1. **功能**。账号和本机任务均可设置重复。同一任务完成后按既有规则进入下一轮；客户端先在本机提交，再同步周期状态与历史。离线或自建服务尚未升级时保留待传修改。
2. **选型**。扩展现有 HTTP JSON 和 SQLite，复用任务修订号、业务规则、变更日志和签名更新器。周期是同一任务的受控事实，完成记录随任务同步，按发生键合并。
3. **架构**。TaskCycleService 生成本机事实，Mapping 规范编码，Journal 与任务同时提交。Go 在同一事务检查任务和结构修订、存储事实、追加变更并提高资料版本门。
4. **模块**。周期规则、轮次与完成历史有独立验证。同步冲突仍按任务、变更组和已有基线处理，禁止过期任务覆盖新轮次。
5. **协议**。REST `/v1` 与传输清单格式保持原版，`X-Daymark-DTO-Version` 协商 1 或 2。DTO 2 增加 `task.cycle_replace` 和可选任务 `cycle`。DTO 1 能力响应不宣告新命令，首次提交含周期事实的事务提升最低 DTO。旧请求收到 426，未启用周期的资料兼容 DTO 1。
6. **接口**。周期带规则、当前开始/结束、下一次开始和完成记录。每条记录包含发生键、结果、实际时间、同轮子任务组及撤销时间。既有实体修订号负责 CAS。旧规则显式转换时停止旧规则并保留已物化任务。
7. **数据库**。客户端复用 schema 12 与现有备份流程。服务追加 migration 保存类型明确的周期文档。旧资料默认无周期，无损迁移不需要选择；旧备份和未同步草稿仍可恢复。
8. **UX**。按 P-13、UX-09/11 一致性和清晰反馈，所有安排入口继续使用共享表单，周期可在原任务上编辑。同步暂停和升级提示集中在账号状态。已知有损转换须解释实际影响并等待确认。
9. **可靠性**。旧版本看不到新字段；未知命令和结构继续拒绝。冻结请求不改写，失败不丢当前任务、周期、完成记录或离线编辑。旧客户端入口与签名兼容目标分开检测。
10. **验证**。覆盖旧客户端读写被隔离、双设备同一 ID 周期/历史、同轮冲突、撤销、推进、旧规则转换、重启、导入，以及 Windows 升级入口。
11. **自审**。在客户端简单解锁会绕过序列化，周期将无法同步。把升级要求应用到资料而非全服，可以先上线新服务，再按已支持客户端安全激活。
12. **交付**。先验临时服务和两个 Windows 客户端，再确认公网部署及签名更新链。真实结果记入 PROGRESS。

2026-11-23。设计契约与单代理技术自审。关联FR-012/014/015/026/044、UX-09～13/69/77、P-02/03/05/07/13～18/22。实际实施和验证状态仅见[PROGRESS](../PROGRESS.md)。

用户已确定：小窗默认显示**全部分类**，可收起、可调整顺序；周期任务**不生成新任务**；完成本轮后，下一周期恢复同一任务，保留完成记录。本契约在实施后取代旧的“循环生成任务”产品行为，不能只改文案而保留旧生成器。

## 1 功能与完整实例

### 分类

- 左栏标题“分类”，今天固定在上方，不参与分类排序；其下为全部可用的一二级分类，与主窗共用身份、树和顺序。主窗新建/重命名/移动/删除及同步拉取提交后，小窗自动更新。
- 默认展开，沿既有设备偏好记忆收起；收起后保留标题分类入口与完整搜索。分类是导航，右侧是当前分类的任务，不再把两者做成两个互不协调的独立表面。
- 分类项右键提供上移、下移；Alt+上/下为键盘等价操作。命令复用CatalogService与版本检查，排序发生在同父节点内，主窗立即反映同一顺序。改归属/跨层级移动继续使用现有主窗分类管理，不能把排序误做重设父级。
- 首尾禁用对应动作，提交中禁重复，失败原顺序保留。分类多时仅分类区滚动；用标题省略、完整路径可访问名称与截断提示表达层级。不新增第二套常用顺序，不清除旧常用偏好，只停止将它作为默认显示集合。

### 安排、提醒与周期

| 用户概念 | 意义 | 默认 |
|---|---|---|
| 安排 | 哪天做；可展开为跨天及具体起止时刻 | 未安排；不自动提醒 |
| 提醒 | 何时提示本轮任务 | 不提醒 |
| 周期 | 同一任务下一轮何时执行 | 不重复 |

例：“每月2日清洗数据，09:30～12:30，开始前10分钟提醒”：任务只有一个taskId。12月2日本轮安排09:30～12:30，09:20提示；勾选后保存12月2日完成记录，任务本轮已完成。下轮安排为1月2日，达到该轮开始时恢复待办，不创建另一个任务。再次完成不重复登记同一轮。关闭应用期间不承诺到点弹窗，启动后由同一服务补判状态。

“完成本轮”与“停止周期”分开；停止周期保留已有记录和当前任务。过期而未完成的任务保留为逾期，不把它自动完成，也不堆出多个漏做副本。迟到完成时，选择原规则中完成时刻之后的首个有效周期；没有未来周期则结束循环。手动跳过另记SKIPPED，不能伪装完成。

## 2 现状与选型

核查3.2.0源码得到：

1. `TaskWorkspace::refreshWidgetBrowse()`已经从提交后的catalog生成全部分类；`WidgetCategoryRail`却绑定`widgetShortcuts`。常用只在首次初始化选最多三个顶级分类，此后新建不会自动加入。因此截图首先是**显示集合与入口含义不一致**，不能直接断言服务器同步失败。
2. 侧栏的`Theme.sidebar`是不透明Rectangle；正文shell使用`surface.panelAlpha`。这是材质/透明度不一致，与“重建两份分类数据”不是同一问题。
3. `ReminderField`的reminderRepeat提示同一个任务；`TaskTimingFields`的repeat调用RecurrenceService，实际物化新任务。截图“每月提醒/不重复”不是同一字段同步丢失，而是两个周期概念重名。
4. `Main.fillEditor()`与`WidgetTaskInspector.loadTask()`在打开时复制草稿。模型提交后有刷新，但缺少适用于已打开编辑器的统一提交观察契约。`stateChanged`还承担busy/主题/筛选等通知，不宜在每次触发时重载草稿。
5. 两个保存入口都会无条件附带remindAtLocal。TaskService正确将显式提醒解释为独立固定时刻，并令schedule.alertMinutes=-1；界面无差别传字段会把原来的相对提醒解绑。应修复**patch缺失/清空/设定的意图**，不能删掉服务端优先级规则。
6. 日期既在快编工具行出现两个无说明图标，又在详情与时段选择器重复出现；小窗与主窗详情的日期/提醒布局各自维护。需收敛共享表单和摘要，而非继续加解释标签。

继续Qt6.10.2/C++20、Qt signals/slots、SQLite、Go业务服务和HTTP JSON。不加RPC、通用事件总线、轮询定时刷新或第三方状态库。规则与事务归服务/仓储，QML只维护未提交草稿和呈现。

## 3 架构与提交顺序

```text
主窗 / 小窗 / 详情 / 日历
  → 强类型意图命令 + 原资料令牌 + expectedVersion
  → TaskService / TaskCycleService / CatalogService
  → Repository事务（任务、周期、完成记录、编辑记录、sync journal）
  → COMMIT
  → TaskWorkspace发布已提交快照
  → 列表增量模型 + catalog投影 + 编辑器观察者
```

是观察者模式，但直接复用Qt机制。写入失败不发布成功通知。写线程先完成事务与读取，再在GUI线程安装完整快照、更新索引/模型，最后发出提交信号。禁止先发通知、观察者随后读到旧缓存。通知带资料generation；跨资料旧回调丢弃。

## 4 模块与生命周期

- TaskWorkspace：快照安装与单次提交通知唯一出口；本地编辑、同步批次、恢复导入、周期推进均走此出口。视图筛选、主题、busy变化不冒充数据提交。
- TaskSnapshotObserver：QML可复用观察对象，按taskId、taskVersion、cycleVersion和profileGeneration比较；一个事件循环合并通知，只检查当前打开任务。它不是另一份持久任务库。
- TaskTemporalDraft：主窗、小窗、快编共享的时间草稿与patch序列化；记录每组edited标记，统一日期/时区/相对提醒/周期摘要。不在QML计算下一轮。
- TaskTemporalFields：统一“安排”入口、摘要和内部表单。各宿主只传递可用空间、锚点、焦点恢复与保存动作。
- TaskCycleService：纯周期计算、完成/跳过/恢复命令及推进策略，注入IClock。复用现有RecurrenceService的日历计算，不调用materialize创建任务。
- CycleRepository：周期配置、当前轮和不可变完成记录；TaskRepository仍拥有任务事实。同一数据库事务，不开第二个异步写连接绕开原journal。
- WidgetCategoryRail：全部分类树的展示及排序意图，不自行排序SQL、不复制分类数据；主窗与小窗共享CatalogService顺序。
- ReminderSchedule：只消费当前轮提醒实例；不借提醒触发任务创建或完成。应用层维护器检查下次需要推进的周期时间，不每秒全表扫描。

## 5 协议与兼容

进程内增加明确的提交事件与周期命令，事务成功后通知；不增加进程间服务。

现有同步v1是严格DTO，不能把新业务状态藏在可忽略metadata或defaultsJson中。网络沿HTTP JSON与原有认证/幂等/整组push/pull；设计新增DTO版本2、能力`task_cycle_v1`和完成记录实体。`/v1`路由仍表示传输协议主版本，`X-Daymark-DTO-Version: 2`表示业务结构；OpenAPI、Qt/Go生成契约、样本与规范编码同时更新。声明版本与未知字段仍严格拒绝。

资料一旦启用新周期，服务端在同一原子事务设置最低可写DTO=2；旧客户端在写入/下拉前得到明确升级提示，不得将不了解的周期字段覆盖或继续旧物化。服务端未支持时不得向其提交新周期命令；离线本地资料仍完整可用，账号资料已有修改保留，界面明确服务需升级，不悄悄切本地或清空待传队列。普通分类/界面修复可在周期协议上线前独立交付。

### 4.0.0 退出账号后的使用入口

FR-015 与 UX-09/11。按 HIG 清晰反馈和用户控制，已退出或登录失效的账号资料仍标明其归属，并在周期附近给出可用路径。账号窗口提供显式「打开仅本机资料」，通过现有草稿保存门、工作区切换和资料索引打开独立 SQLite 文件。首次建立空资料，之后复用同一文件；原账号资料和待同步队列保留，可从账号资料选择器返回。由此资料登录会另开账号资料，避免绑定仅本机任务。继续使用当前页面的按钮只关闭账号窗口。

复用 ProfileIndex、Coordinator、TaskWorkspace 和现有 QML 账号入口。不增加网络字段、数据库 schema 或周期同步命令，因为资料仍分开读写。自审核对了旧资料路径、重启记忆、资料保护及失败反馈。以临时 SQLite 验证退出后旧资料不可写周期、主动切换后可写、重开保存及返回。下拉输入单独按 [UX-53](repeat-choice-popover.md) 验收。

每条命令包含mutationId、taskId、expectedTaskVersion、expectedCycleVersion；周期动作还含occurrenceKey。服务端和本地都校验。重复重试取原回执；两设备同轮完成只产生一条语义完成记录；过期轮的恢复不能重开新一轮。

## 6 接口与数据

```text
SnapshotCommitted {
  profileGeneration, projectionRevision,
  source: local | sync | restore | cycle,
  changedTaskIds[], changedCatalogIds[], changedCycleTaskIds[]
}
TaskTemporalDraft {
  taskId, profileGeneration, taskVersion, cycleVersion,
  arrangement, reminder, cycle,
  arrangementEdited, reminderEdited, cycleEdited
}
TaskCycle {
  taskId, frequency, interval, anchorLocalDate, zone,
  weekdayMask?, monthDay?, yearMonth?, untilLocalDate?,
  state: active | stopped | legacy_review,
  currentOccurrenceKey, currentStartUtc, currentEndUtc?,
  nextStartUtc?, ruleRevision, rowVersion
}
CycleCompletion {
  taskId, occurrenceKey, ruleRevision,
  scheduledStartUtc, scheduledEndUtc?,
  outcome: completed | skipped,
  performedAtUtc, mutationId, revokedAtUtc?
}
```

ID/版本遵守同步契约：UUID、线上整数十进制字符串，不经过JS浮点数。轮次键由taskId+ruleRevision+规则中的计划日期/本地时刻确定，经规范编码生成，不能使用本机随机时间或自增计数。

命令：configureCycle、completeOccurrence、skipOccurrence、undoOccurrenceCompletion、stopCycle、advanceDueCycles(now)。同轮完成/撤销与任务状态、下轮游标、提醒取消/预约及journal原子提交。只要当前任务已进入新轮，旧轮撤销必须明确拒绝并允许查看历史，不能覆盖当前工作。

旧start_on为安排开始、deadline_on为现有结束边界，当前QueryService会将schedule投影为统一起止日期；本轮不凭改标签重新定义旧数据。安排草稿把“单日/跨天/具体时段”作为同一范围：无结束时默认同日，有跨天才显示结束，只有旧结束无开始的任务显示“最晚于…”，保留原字段直到用户修改。全天UI结束含当天，持久schedule结束排他；UTC瞬间与本地日期边界仅在服务转换。独立截止实体不在本次另行增加。

提醒模式互斥：none / relative_to_start(offsetMinutes) / absolute(localDateTime,zone)。未编辑不传patch；明确清除传null；固定时刻的显式修改才解除相对关系。相对提醒随安排及下轮起点重算，固定提醒不默默平移到另一时刻。改为周期时要求用户选择本轮提醒策略，不把单次绝对提醒猜成每轮提醒。

## 7 数据库、历史和迁移

预期本地schema12追加migration，旧migration不改写；Go服务按现有最高版本追加下一项migration（实施时核对编号）。增加task_cycles、task_cycle_completions，两表以taskId关联原任务，无新任务副本。周期状态/规则版本/当前轮/下次推进时间持久化。完成记录唯一键(taskId,occurrenceKey)；nextStartUtc建立有界到期查询索引；记录按taskId和performedAtUtc查询，面板分页，不随任务列表全量加载。

下轮等待期间任务保持本轮COMPLETED并展示“下次…”，计划视图可展示同一任务的下次安排；到下轮开始才恢复OPEN。完成记录为独立历史事实，不依赖tasks.completed_at持续不变。已完成视图按完成记录投影周期历史，详情打开同一任务并能定位那次记录；普通任务沿现有路径。跳过不是完成记录计数。

周期仅配置在根任务；子任务不能同时拥有独立周期，防父子轮次冲突。根任务本轮完成仍沿原有父子原子联动，记录本轮成员与完成状态；下轮只恢复该轮纳入周期的子项，保留ID、顺序、分类与属性，不恢复已删除/取消的子项。后来新增子项进入当前轮，不追写已完成历史。

schema升级前做一致快照并验证可恢复。旧recurrence模板/物化任务不能自动粗暴合并：保留所有任务及历史，停止新版客户端继续物化，标记legacy_review，在显式转换页选一个保留身份作为周期任务。其他已生成任务默认保留为普通任务；若要清理未来项，必须列明未改/改过/已完成项并单独确认软删，不能在迁移中静默删除。旧提醒重复配置也保留：标记“原重复提醒”，提示它不会按周期恢复完成任务，提供转换到新周期的明确预览。

账号资料转换必须由新服务原子提交兼容门及实体变更；未同步完成不能让旧设备继续按原规则生成副本。失败回滚，原资料与待传记录保留。3.2.0旧更新器应继续拒绝跨schema自动安装；新发行必须完整安装并写明兼容边界。

## 8 紧凑UI、HIG与所有状态

主窗原行编辑、主窗详情、小窗详情和日历新建任务各提供一个“安排”入口。未设置时显示“安排”，已设置时显示主要日期或时段，周期和提醒以辅助摘要呈现。窄处优先保留主要日期，完整信息可通过展开或辅助技术读取。点开同一表单依次编辑开始、结束、周期与提醒。默认显示开始日期，结束可选，具体时刻按需打开。周期提供不重复、日、周、月、年及自定义，自定义支持完成后若干天恢复。提醒提供不提醒、开始时、提前多久和指定时刻。

主窗和小窗复用同一个表单组件、草稿和校验。主窗详情就地展开，可用宽度足够时将日期与时刻放在同一行。小窗采用紧凑单列，优先收紧外边距与组间距，保留 Daymark 控件字号、命中区和用户的字体缩放。空间充足时就近锚定，空间不足时在当前详情内替换为安排视图并提供返回，从原处恢复焦点与滚动。内容超出时仅表单正文滚动，取消和完成留在可达位置。打开时保持原小窗尺寸及分类栏位置。表单的“完成”应用到当前任务草稿，任务仍走宿主已有的保存门，Esc 优先关闭子选择器，其次返回安排入口。

周期预设等下拉的总高度取选项实际高度、分组线内距和容器内边距之和。下拉可展开到当前显示器的工作区，只有超出工作区时才滚动，且可用键盘到达末项。菜单和下拉共用字体与行高，分隔线只出现在真实分组之间。共享 ComboBox 的[弹层契约](repeat-choice-popover.md)可独立交付，进程协议、网络和数据库均不涉及。

侧栏与任务正文属于同一小窗外壳，只绘制一套圆角边界；导航使用轻量选中与细分隔，不用另一块全不透明深色板。全窗背景透明度同源，内容/文字不随背景降低opacity；菜单和任务编辑弹层仍为实体不透明表面，不复发菜单透明/黑条问题。收起后恢复正文宽度，Mini/球的尺寸、锚点、拖动和穿透通路不改。

HIG内容优先→三项明确概念与上下文摘要；一致性→同草稿/同表单/同领域规则；渐进呈现→跨天/时间/高级周期按需；用户控制→周期停止与完成分离、冲突不覆盖、迁移显式确认。沿既有Theme字级/4DIP节奏/小圆角，不新增大面板或复制Apple资源。

浅深/100～200%/窄窗自然重排，单行控件行高不锁整个弹层高度；超出屏幕才滚动且有独立槽。Tab、Enter、Esc分别覆盖打开、应用、返回；弹层取消零改；输入法组合不提交。错误具体到日期逆序、时区缺失/DST歧义、周期无有效日期、旧轮冲突、服务不支持，并保留输入。图标和状态有可访问文字，不只靠颜色。

## 9 跨界面同步、冲突与性能

- 未修改的已打开编辑器收到同任务新版本时更新值与摘要，保留当前页签、滚动/焦点；没有变化不重载，不随主题/busy/定时提示不断重置。
- 有本地草稿遇到外部提交时保留全部输入，提示“该任务已在另一处修改”；显示“查看最新/重新载入”明确动作，CAS仍以原版本提交并拒绝覆盖。不能无提示更新baseVersion来掩盖冲突。
- 当前编辑器自己的保存用operation/来源标识处理，避免把自身提交误报外部冲突。异步成功先更新缓存再回调；同任务删除/切资料立即阻止旧草稿写到新上下文，允许复制或明确放弃。
- 分类选择器按kind+id保存选择，不按currentIndex保存语义；分类增删/重排时更新选项但不改草稿归属，失效分类明确提示，不回退收集箱后悄悄保存。
- 周期推进使用到期索引、一次维护事务和有界批次。两设备抢到同一轮通过唯一键/CAS幂等合并；服务端时序裁决不能依赖最后一次UI刷新。网络断线重试保留mutationId。
- 不上传输入内容用于分析；错误日志只记动作/错误码/关联标识与版本，不记任务标题、备注或真实数据库路径。关闭应用不保证提醒；时钟回拨不重开已经进入过的轮次。

## 分类名称显示与截断提示（UX-77、UX-09/11）

1. **功能定义**  
   主窗和小窗的分类以名称为主。保留两级缩进、选中状态、整行点击及现有排序。以「月循环工作」下的「华东区域月度数据复核与归档」为例，小窗可显示「华东区域月度…」，悬停名称显示完整路径。找不到足够空间的用户可通过「查找分类」在同窗查看和搜索完整路径。
2. **现状与选型**  
   小窗在 100% 下左列宽 104 逻辑像素。外边距、固定滚动槽、行内边距和 14 像素文件夹加 5 像素间距之后，一级名称约剩 43 像素，二级约剩 35。主窗也同时预留展开、文件夹和更多操作。方案采用单行名称、现有层级和有效的少量符号，优先回收通用图标的宽度。两行常驻、横向滚动和仅靠提示补全会分别降低扫描密度、移动阅读位置或让指针成为唯一入口。沿用 Qt Quick 和 Daymark 控件。
3. **架构与数据流**  
   主窗读取现有分类树，小窗读取同源的工作区分类投影。名称和路径来自已提交数据，分类 ID 驱动选择与排序，宽度和截断由 QML 布局计算。名称长度变化不参与窗口和栏宽计算。
4. **模块与生命周期**  
   `NavRow` 的分类实例保留父级展开和尾部命令，`WidgetCategoryRail` 管理紧凑行与稳定宽度。两者和现有分类查找复用一致的名称提示规则，使用 Daymark `ToolTip` 的锚定和延时。被移除、重命名或失焦的委托关闭旧提示，提示随当前行存活。
5. **协议及兼容**  
   进程内只调整 QML 呈现。IPC、网络协议及同步版本不涉及，因为分类数据和提交动作沿用现有接口。
6. **类型与接口**  
   分类名呈现输入为 `title: string`、`path: string`、`enabled: bool` 与布局后的可用宽度。输出为原文单行省略和完整辅助名称。读取 `Label.truncated` 判断实际截断。路径不可用时用原名作为提示文本。文本以纯文本处理。
7. **数据库与事务**  
   数据库、迁移和新增事务不涉及。现有分类身份、名称、颜色和排序仍从分类模型读取。
8. **HIG 与交互规则**  
   有子项的主窗父级保留展开箭头。普通分类移除重复的文件夹轮廓，系统入口「今天」和「查找分类」保留各自图标。层级靠缩进，选中靠中性底色和独立键盘焦点线；用户明确选择的分类色可在现有内边距点缀，正文保持主题文字对比度。小窗 100% 的分类列建议从 128 逻辑像素验证，按字号和工作区调整，优先保住任务区原有最小宽度。放不下两列时使用现有同窗分类查找。长名单保留独立垂直滚动。沿用同级排序、拖入分类及其焦点规则。[Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) · [Apple 图标设计](https://developer.apple.com/design/human-interface-guidelines/icons)
9. **提示与可靠性**  
    仅当名称实际截断且指针在文字区时显示完整名称或路径，沿用约 600 毫秒延时。提示使用实体底色，在原窗口工作区内换行并避开当前行，不接管焦点或点击。按下、滚动、拖动、打开菜单、移出和切换形态时隐藏。读屏直接获取完整路径，键盘可进入「查找分类」输入关键词，用方向键浏览结果、Enter 选择、Esc 返回焦点。查找结果显示父级路径，长路径可在现有较宽列表中换行。无需新增日志、对外数据或后台扫描。[Apple Offering help](https://developer.apple.com/design/human-interface-guidelines/offering-help)
10. **验证**  
    用临时资料检查恰好放下与首次截断、两级同名、中文长名和混合字符、空分类、长名单滚动、浅深/高对比及 100/150/200% 字号。单测覆盖实际省略与提示阻断的判断。QML 集成覆盖鼠标进入/退出、滚动、右键、拖拽、键盘和分类重命名。保留任务区宽度、排序和三形态回归；原生多屏和读屏单列验收。
11. **自审与取舍**  
    分类深度和选择可通过位置及中性底色识别，通用文件夹重复传递分类信息。固定或受工作区约束的栏宽可避免改名导致窗口尺寸变化。提示是补充读取路径，完整内容仍可经同窗分类查找与可访问名称获得。
12. **实施队列**  
    先调整小窗分类名称的可用宽度和提示，再统一主窗分类行与查找结果，最后执行视觉与交互回归。当前为设计提案，实际验证记入 [PROGRESS](../PROGRESS.md)。
