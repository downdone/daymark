# UX-58：稳定空间、独立滚动槽与组件同宽

2026-10-28；FR-012/018/035，UX-01/02/05/06/07/09/10/11/14，P-13～17。HIG的稳定熟悉感、内容层级、用户控制及适应布局落地为具体几何约束，沿用现有视觉资源和运行平台习惯。

依据[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)的熟悉关系、对齐、稳定适应与文字缩放，以及[Scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views)的溢出内容、键盘操作、避免同轴嵌套。固定尾部操作槽、同窗形态共享宽度、18 DIP独立滚动槽是Daymark据此制定的工程规则，不是Apple规定的数值或所有界面必须等宽的要求。密度先由内容优先级和可用空间决定，不通过强制缩小字号、隐藏字段或取消键盘访问实现。

问题不是局部配色：固定520高上限使详情在仍有空间时提前滚动；滚动条画在字段所在视口内；日历对月视图隐藏标题并改变弹性占位，推动比例切换；小窗与Mini分别使用340/260宽和12/6边距，破坏空间记忆。分别从容器预算、滚动槽、操作锚点和共享几何修复。

- 详情按实际内容和头部自然高度生长，最多使用主窗安全范围。普通短内容不滚动；长备注/大量子项或大字窄窗才滚动。滚动条在独立槽，正文不可进入该槽，头部和错误保持可达。新增、选择器和同类表单沿同一规则，保留1 DIP溢出容差、键盘揭示与单轴滚动；不靠隐藏溢出或缩小字号实现无条。
- 移除“后续任务沿用本次属性”及其专用触发路径，保留默认的本次内容编辑行为；更改循环配置仍走原后续未改实例更新与历史保护协议，不迁移或删除已存规则/实例。
- 日历始终保留日期标题的弹性区域和固定比例控件/导航区；长标题截断。日/周/月/年采用同一控件顺序和宽度；紧凑组件的标题行也不随月视图消失。只有由容器宽度/字号决定的明确断点可换行，主/独立日历共用。
- 小窗→Mini→小窗保留当前宽度和左上位置，仅改变高度；恢复原小窗高度。两形态水平内边距、展开/收起和更多的尾部槽相同；Mini不增加置顶按钮，展开形态的置顶占前一个槽。统一头部顶对齐和Mini最小高度，标题只占剩余空间并截断。现有锁定、屏幕边界、持久化、穿透恢复不变。

审查范围：共享ScrollView、详情/子项、日历新增/时间/内部选择器、列表、独立日历及组件。表单滚动采用预留槽，日历时间轴/格线和表头需使用同一可用宽度，不能单独缩正文造成日期错列。逐片迁移与实际结果见PROGRESS。

原生追加发现：较窄组件文字截断后，整行全文tooltip会在完成按钮处遮挡点击。改为仅文字区域悬停触发；完成操作保持直接可点击。验收需在原生渲染完成列表布局后检查移除动画，不能以模型已更新推断视觉反馈已呈现。

复用既有contextual_workspace、calendar_interaction、desktop_surfaces及widget_window测试入口，检查自然高度/必要溢出、槽与字段无交集、循环选项移除但保存语义保持、四比例控件矩形稳定、Mini往返位置/宽度和动作槽一致。保持全部业务断言与原超时，临时数据库/设置；主窗、独立组件、浅深/100/200%截图复看。原生窗口/高DPI/读屏/macOS与离屏证据分列。
