# 可定位的账号、同步与服务错误码

2026-11-05。AUTH-09：保留现有业务错误 key / HTTP 状态 / OpenAPI v1，同时补稳定诊断编号、模块与请求关联。不把网络超时猜成账号注册失败；没有服务响应时明确未知。

## 编号及兼容

展示 `Sxxx-Cxxx`。`S000` 表示未获得可识别的服务端错误，`C000` 表示客户端已正确收到服务端业务拒绝；`999` 是未登记兜底，不能替代新错误登记。编号在 [注册表](../api/diagnostics.json) 一次分配，不重排、不复用，删除的编号也不授予其他含义。

| 范围 | 服务端 | 客户端 |
|---|---|---|
| 1xx | HTTP、校验、并发与限流 | DNS、代理、TCP/TLS、传输、超时 |
| 2xx | 认证、会话、账号 | 登录入口、配置、系统凭据 |
| 3xx | 同步、游标、作业、冲突 | 协议、同步状态、资料兼容 |
| 4xx | 存储、配额 | 本地 SQL、备份、资料切换 |
| 9xx | 未分类内部错误 | 未分类本地错误 |

例：`S000-C103` 为客户端连接/传输超时，不能证明服务端已创建或未创建账号；`S000-C104` 为 TLS 错误；`S000-C107` 为代理失败。服务端的细分对应表直接读取注册表，避免文档复制编号漂移。客户端从业务 key 独立映射服务端编号，兼容尚未部署新响应头的服务器。

服务端通过 `X-Daymark-Error-Code` 返回 `Sxxx`，不向严格 `Problem` JSON 添加字段；旧客户端仍读取原 `code`。请求关联使用 `X-Daymark-Request-ID`（合法 UUID，否则服务端新建），服务返回既有 `X-Request-ID`。客户端不信任任意长度或任意文本的 ID。

`scripts/generate-diagnostics.py` 同步生成 Qt / Go 映射，`--check` 拒绝未登记的服务端契约 key、重复编号或副本漂移。开发时 Windows / macOS / Linux 均运行 `python scripts/generate-diagnostics.py --check`；Go 测试验证全部服务端编号与 v1 Problem 兼容。

## 诊断和用户恢复

客户端记录请求 ID、操作类别（capabilities/register/login/sync）、阶段、HTTP 状态、耗时、Qt/应用版本和 TLS 后端；阶段为 resolving_or_proxy / connecting / tls_established / waiting_response。Qt 复用连接可能不重复发出每个信号，因此阶段是观察证据，不是精确的网络抓包结论。注册 POST 结果丢失保留 `syncRegistrationUncertain`，诊断仍保留其底层网络 key；不自动重复注册。

错误正文后显示组合码和请求 ID；失败态提供测试连接、复制诊断、错误详情和日志目录。测试只 GET 能力入口，不发送账号、密码或任务，不切换资料。复制使用白名单，补充Qt网络错误整数/枚举、脱敏传输描述、TLS错误列表、配置预算与服务地址指纹，排除明文URL、账号、凭据、任务和SQL。HTTP错误不保留服务器reason phrase；Qt没有公开的原生码明确标为未提供。详见[全局日志](runtime-diagnostics.md)。服务端结构化错误日志只含请求 ID、业务 key、编号、状态和路由模式，不记录原路径参数/请求体/Authorization。

状态链：连接中禁用重复动作 → 失败保留本地资料并清理密码 → 用户测试连接或重试登录 → 成功明确反馈。沿 UX-09/11/13 与 HIG 清晰反馈、可恢复和用户控制；共享按钮/字体和滚动布局，错误长文本与 200% 缩放可换行，键盘 Tab / Enter 可达。
