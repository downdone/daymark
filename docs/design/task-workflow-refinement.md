# Daymark 日常任务工作流精修设计

范围为 FR-015、FR-042、TIME-02 / CONS-01、UX-09/11/53/75/77。目标是让用户在离开任务前能回答三个问题：写到哪里了，下一次什么时候做，修改是否已经保存。用已有交互与数据契约实施，每个切片先在目标发行源码复测，已经满足验收的路径只补缺失证据。

## 1. 四条交付路径

| 路径 | 默认动作 | 可观察结果 |
|---|---|---|
| 记录 | 小窗选分类，打开第二个父任务的子任务页，连续添加 | 每次确认后新增行紧随所属父任务，输入焦点留在该父任务的子任务输入框 |
| 编辑 | 主窗列表原位改标题，打开同一任务详情续写备注，再回列表 | 详情带入刚输入的标题；保存后仍能找到原来的阅读位置，列表和小窗都读到同一份已保存结果 |
| 安排 | 给根任务设置每月 2 日 09:30 开始、提前 10 分钟提醒 | 保存后各界面能读出同一执行时间和提醒时间。完成本次后看到下一轮日期，到时恢复待办 |
| 恢复 | 离线编辑后恢复网络，或取消一次更新后重新检查 | 本机保存、等待上传、同步成功可区分；更新取消后可再次检查，重启后可找回已保存的任务 |

## 2. 技术选择与实施位置

沿用 Qt Quick、C++ 模型、SQLite 及既有同步与更新器。落点按本工作树核对，合入目标分支时按职责追踪重命名。

| 位置 | 负责的改动 |
|---|---|
| WidgetTaskInspector.qml、WidgetTaskRow.qml、WidgetViewModel | 输入焦点与草稿归属、父子行顺序、窄宽摘要、已编辑行的增量刷新 |
| TaskRow、TaskSelection、ListViewportState | 行内命中区、批量选择、来源行及滚动锚点恢复 |
| TaskQuickEditor、TaskEditorSession、TaskSnapshotObserver、TaskDetailsFields | 原位与详情衔接、字段草稿、版本冲突、保存结果及返回动作 |
| TaskDetailsFields.qml、ReminderField.qml、任务列表和日历的安排入口 | 用同一草稿提交安排，读取同一份执行及提醒摘要 |
| TaskCycleService、ReminderSchedule、TaskWorkspaceReminders | 提供当前轮、下次执行与真实预约信息。展示层只选择显示精度 |
| 现有账号状态与设置页、更新控制器 | 从已有保存、待上传、认证、版本与更新事务状态派生文案并路由已有动作 |

## 3. 架构、接口与边界

任务命令 → 服务校验 → SQLite 事务提交 → 已提交变更通知 → 各模型按资料、任务 ID 与版本更新 → QML 展示。沿用[同一任务周期与跨界面一致性](task-cycle-and-cross-surface-consistency.md)的 SnapshotCommitted 和 TaskTemporalDraft 契约。实施先查找现有等价信号与角色，避免叠加第二套广播。

展示端需要的只读值为任务身份、轮次状态、当前安排、下一次执行、下一次有效提醒、提醒策略。没有有效预约时留空；已完成等待下轮时，执行摘要取下一轮，提醒时间只在服务确认有预约时展示。列表使用短格式，详情和辅助技术名称使用含日期的完整格式。查询层决定筛选结果，QML 不计算下一月日期。数据提交失败保留输入、锚点和错误。

本轮复用 SQLite 原字段、周期完成记录、同步 DTO 和签名更新机制。草稿与可见状态属于进程内展示，不写入同步队列。无新增数据库迁移、网络或进程间协议。若在目标版本发现缺少必要业务事实，先记录缺口，再按既有迁移契约单列实施。

## 4. 小窗和输入

悬浮球承担唤回，Mini 条承担一瞥，小窗承担录入与执行。小窗左列仅一棵可折叠分类树，复用已有分类顺序与选中 ID；右列显示当前范围，父任务在前，匹配的子项按原顺序缩进。若筛选只命中子项，在首个命中项前显示父任务名称作为上下文，不计入匹配数量。同名父任务始终按 ID 分组。分类名截断时悬停或键盘聚焦显示全名，读屏始终可读全名。最窄状态先收起分类列，标题保留切换入口。

子任务编辑的身份由资料、父任务 ID、编辑用途共同确定。刷新不得重建仍在编辑的输入控件；输入期间暂停自动收球，弹层开启期间同样暂停。Enter 在 IME 组字时交给输入法，提交候选后另一次 Enter 才新增。成功后清空本框，失败保留原文。切到另一父项时隔离草稿；远端删除父项时保留草稿并提供复制和关闭，禁止自动改投根任务。菜单退出将焦点还给触发控件。后台分钟计时只更新必要的时间角色，不应触发窗口隐藏、列表重置或重新抢焦。

### 4.1 从窗口列表浏览到编辑

现工作树中 TaskRow 的正文点击会请求快速编辑，批选模式用同一位置改变选择；TaskQuickEditor 同时有完成圆、保存勾号和详情入口。小窗详情还有失焦后尝试保存关闭的路径。三个风险分别是右击命中与已选行混淆、两个勾号语义混淆、开子菜单或切窗时意外提交。下列为目标行为，实施前在发行版分别重放。

| 用户动作 | 主窗任务列表 | 桌面小窗任务列表 |
|---|---|---|
| 浏览、滚动、键盘上下移动 | 保持浏览行高，标题为主、时间摘要为次；键盘移动只改变当前位置 | 同一摘要与父子顺序，标题截断可查看全文；菜单和编辑器关闭后继续原位置 |
| 单击正文 | 保留现有一击原位编辑。选择模式中单击仅增减选择；Ctrl/Shift 沿用平台批选 | 沿用已有紧凑任务详情；窄窗免去在任务行中再撑开一份表单 |
| 点完成圆、展开箭头、详情按钮 | 分别执行本次完成、展开子项、打开详情。每次指针动作仅由一个命中区消费 | 同样独立命中；具备子任务页的根任务可直达子项 |
| 右击或打开键盘菜单 | 右击未选行只作用于该行；右击批选范围内才提供支持的批量动作。键盘菜单以焦点行为准 | 右击以指针下的任务 ID 为准。空白处不触发任务菜单或面板菜单 |

浏览时保留完成圆、标题、必要摘要；选中、键盘焦点和展开编辑用各自的反馈。操作区预留位置，悬停显露按钮时标题和邻行不挪动。最近删除显示恢复及删除操作；已完成列表保留历史语义，查看周期完成记录时标明所选轮次，编辑当前任务从明确入口进入。

### 4.2 原位编辑与详情如何接续

| 场景 | 编辑内容与提交边界 |
|---|---|
| 原位编辑 | 标题、短备注、安排、分类、标签、特别关注。已有多行备注显示摘要，点击在详情定位原文。任务完成沿用左侧完成圆；有修改时右侧显示有文字或可访问名称的「保存」。单行输入 Enter 在组字结束后保存，Ctrl/Cmd+Enter 保存并收起。 |
| 打开同一任务详情 | 使用原有附着弹窗，沿用同一资料、任务 ID、基准版本及脏字段。主窗行内草稿直接交给详情，打开时零写入。标题和备注靠前，随后是安排、归属与标签；子任务沿用独立页签。多行备注 Enter 换行。 |
| 编辑安排或标签 | 需确认的子弹层以「应用」把选择带回外层草稿；「取消」只还原本次选择。外层保存时一次提交已编辑字段。独立打开且没有外层编辑器的安排入口，「保存」直接提交。 |
| 离开或转向另一任务 | 主动点另一行、关闭详情或切分类时，沿用保存后离开的机制。有改动先保存，成功后执行一次待办导航；失败停在原任务并可重试。切应用、弹出系统输入法或菜单造成的暂时失焦不提交、不关闭。Esc 先关闭最内层；外层干净时退出，有草稿时允许继续编辑或明确放弃。 |

跨原生窗口沿用小窗现有「先保存再打开完整详情」路径，保存失败留在小窗。主窗和小窗各自打开同一任务时，未编辑字段跟随最新快照；同字段并发修改保留两个值，显式选择后按新版本提交。异步保存以资料代次、任务 ID、该次提交标识关联回执；迟到的结果不能关闭后来打开的任务。子任务新增是独立命令，放弃父任务的文字草稿不撤回已确认新增的子项。

返回定位记录来源视图、筛选、任务 ID、相邻可见 ID 和视口内偏移，不把列表下标或旧 delegate 当作身份。任务仍在范围内就恢复其焦点和可见位置；改分类、完成或删除使其离开筛选时，保留筛选和滚动位置，焦点落到原位置的下一项、上一项或空列表入口。主动改分类时给出短反馈，例如「已移至『活动筹备』」。放大字号时详情内容可滚动，保存与错误提示可通过键盘到达。

## 5. 安排弹层与视觉顺序

主窗与小窗使用同一编辑器和提交逻辑。小窗采用紧凑排列，空间不足时换行或调整弹层方向，保留原按钮命中区、字号和键盘顺序。基础视图按「日期、周期、提醒」排列。日期默认只显示一个日期，选择具体时段或跨天后才展开起止控件；旧数据仅有截止日时显示「最晚于」。选择周期后显示周期规则与下一次执行预览；子任务沿用根任务周期约束。提醒默认关闭，选择提前提醒才显示偏移量；没有开始时刻时提供「设置开始时间」及「指定提醒时间」。绝对提醒只对指定时刻生效。既有重复提醒单独标明「重复提醒」，保留原行为。

例如保存「12 月 2 日 09:30、每月、提前 10 分钟」后，列表主行显示标题，次行可显示「12 月 2 日 09:30 · 每月」。打开安排可读「12 月 2 日 09:20 提醒」。完成本次后显示「本次已完成 · 下次 1 月 2 日 09:30」。无日期无提醒的普通任务只占标题一行。只预览或取消产生零写入；有外层草稿时遵守 §4.2 的提交边界，独立安排编辑器一次提交所有已编辑字段。并发修改同一字段时保留草稿，显示本机填写值和最新值供选择。

沿用 HIG 的层级、直接操作、反馈与用户控制，以及 Daymark 既有字体和表面 token。标题、父子关系、时间依次占据阅读优先级。用缩进表达从属，键盘焦点与选择分别表达，状态同时提供文字。弹出列表按实际行数测高，到屏幕可用边界才滚动；Esc 先关子菜单，再关安排。验证浅深主题、窄窗、200% 文字和中文输入法。

## 6. 保存、同步与更新的反馈

| 事实 | 呈现及操作 |
|---|---|
| 本地提交失败 | 编辑位置显示「未保存」及可重试原因，保留草稿 |
| 已保存、离线或上传排队 | 账号与同步页显示「已保存在此设备，等待同步」及待传数量；恢复网络后自动继续 |
| 登录失效 | 显示「修改已保存在此设备，登录后继续同步」，登录后继续原资料的队列 |
| 版本不兼容 | 可无损升级时走已有签名更新；有损转换列出受影响对象、字段和数量，确认前零写入。没有可靠转换目标时保留数据并给出恢复动作 |
| 取消更新 | 回到可检查状态，保留已安装版本；下次手动检查重新发起。正在提交的事务按既有恢复契约处理 |

错误细节和关联码保留在诊断入口；界面首句回答数据是否已保存。日志不得包含标题、输入法组字、备注或账号凭据。

## 7. 开发顺序与完成标准

| 切片 | 开发与验收一起交付 | 失败判定 |
|---|---|---|
| 1 小窗输入与层级 | 两个父任务各加两条子任务，在第二个输入框输入「01、准备材料」。注入正常分钟刷新及无关任务变更，再用 Windows 中文 IME 和指针验证。覆盖待编辑父项删除 | 草稿丢字、重复新增、归错父项、重置模型导致失焦或弹层闪退 |
| 1b 列表→原位→详情→返回 | 在长列表中段改标题，带未保存标题打开详情、补多行备注，取消一次安排子菜单，切应用后回来保存。验证打开详情零写入、保存一次、两窗同值和返回焦点。再测改分类后行消失、批选内外右击、保存失败后重试、两窗同字段冲突及延迟回执 | 串行操作错任务、截断备注、失焦误存、草稿丢失、列表跳顶、同一命令重复执行 |
| 2 时间摘要与安排 | 临时库、可控时钟覆盖单日、仅截止、跨月、固定与相对提醒、完成与撤销；对照主窗、小窗、日历和第二设备的同一任务。若完成下一轮前存在错过周期，按现有周期服务规则验证 | 同一任务出现两种执行时间、固定提醒漂移、下一轮产生新任务 ID、取消产生写入 |
| 3 同步与升级恢复 | 两个隔离资料目录及临时服务跑离线编辑、认证恢复、版本门；Windows 隔离安装走取消→再检查→更新→重启，核对数据和上传状态 | 已保存误报为已上传、数据损失未经确认、取消后无法重试 |

每个切片先复现或记录目标版本已通过，再改动并运行仓库 Windows 构建及相应 CTest。真实窗口覆盖窄宽、焦点、弹层命中及画面闪动；跨设备测试用隔离测试资料，公开安装验收按发布流程执行。普通刷新不得重置整个编辑模型；以模型重置次数、焦点对象和任务 ID 验证。跨平台表现及现场闪动仅在实际环境验证后记录通过。

## 8. 设计自审

发现产品哲学文档中仍有「循环生成可独立执行的任务」的旧表述，与现行同 ID 契约冲突，随设计校正。排序、草稿保护、无损升级和有损确认均复用既有领域规则。本设计的交付状态为文档自审完成；目标发行版的实现差异与实机验证按上述切片记录。

## 9. 从用户目标复审整条动线

用户经常把一次任务跨成三段使用：工作被打断时先记下；有空时再整理；到点时直接处理。三段可分别从小窗、主窗和提醒弹窗开始。收集、分类、安排并非每条任务必经的向导步骤。普通任务只写标题即可完成；需要提醒的任务可以在录入时直接安排；回顾、同步和设置按需进入。

| 用户此刻的问题 | 页面与现有依据 | 设计判定与可见结果 |
|---|---|---|
| 第一次打开，从哪儿开始？ | 收集箱已有顶部快添和空态新建。Main.qml 的「收集箱已清空」同时覆盖从未录入与处理完毕 | 空收集箱用中性标题「收集箱为空」。宽窗如已有快添输入，空态动作聚焦同一个输入。允许全程离线，只填标题。无需新增首次使用状态或向导 |
| 一边工作一边记，会记到哪里？ | 小窗沿用今天或当前分类；日历带选中日期；自然语言也可能给出日期与提醒 | 在输入旁预览最终归属、日期和是否提醒，只显示影响本次结果的值。用户手选优先。上下文日期与文本建议冲突时并列显示候选让用户点选，保留原文；仅归属来源不同且结果一致时无需询问 |
| 按 Enter 后，任务去哪了？ | 收集箱表示未分类；今天与计划为自动范围；一个任务可同时命中多个范围 | 当前范围仍匹配时让新增行可见；若筛选使其不可见，输入旁短暂显示「已添加到『活动筹备』」并给「查看」动作。保留当前筛选及连续输入焦点，不自动跳页。收集箱移入分类后沿用同一规则 |
| 今天先做什么？为什么看到这条？ | 主窗今天、小窗今天、分类的「今天」过滤看起来相近，实际还受分类限制 | 标题优先表达范围，小窗用「活动筹备」配「今天」或「全部未完成」。仅在原因不明显时附「已逾期」等真实状态。搜索和筛选持续可见并可清除。区分正在加载、无匹配、当前范围为空和读取失败。历史视图内搜索无结果首先给清除条件，不能显示从未完成任务 |
| 需要换到日历找刚才的任务吗？ | 列表与日历是同一范围的两种呈现；未安排项没有日历位置 | 切视图保留范围，对有日期的选中任务定位到对应日；无日期时提供已有未安排入口。返回列表恢复滚动和选择。直接改标题、分类或完成任务均可留在列表，详情按 §4.2 接续 |
| 到点后，哪个按钮能得到我想要的结果？ | 到期提醒可关闭、延后或完成；ReminderInbox 已区分延后与任务时间不变 | 提醒呈现任务名、原定时刻和三个有区别的动作：完成、本次稍后提醒、关闭本次提示。延后反馈含新的提醒时刻；关闭提示保留待办。仅周期任务的完成动作显示「完成本次」并反馈下一轮日期。退出期间漏过的提醒沿用启动补查，不把已完成任务重新推给用户 |
| 晚上回看，我今天究竟完成了什么？ | 已完成列表承载结果；周期任务的本次完成与下一轮共用任务身份 | 已完成页按实际完成时间定位历史轮次；同时显示当次计划时间，跨日时带日期。再次进入当前任务时明确标示下一轮。误点完成用既有撤销路径，返回来源范围后重定位；历史筛选为零时保留清除条件入口 |

### 验证优先级与交接

1. **先验录入与找回。** 在明天的日历日期输入含另一个日期的标题，保存前能指出生效日期及提醒。再在带筛选的分类中添加一个不匹配的任务，验证仅存一条、能查看、草稿焦点和筛选保留。接入切片 1/1b。
2. **再验范围与空态。** 同一份临时资料含一条未分类的今日任务、一条未来分类任务和一条无日期任务。分别从收集箱、今天、分类、日历进入；核对标题、计数及任务 ID，以及加载、筛选为空和确实没任务时的操作。接入切片 1b/2。
3. **最后贯穿提醒与回顾。** 可控时钟下为周期任务先延后，再从提醒完成，核对原安排、下次提醒、完成列表和下一轮；重启后不重复呈现已处理的这一次。接入切片 2/3。

可用性复核让首次使用者独立操作，先问「它保存在哪、何时提醒、完成后在哪里找」，再看其选择与结果。记录误判点、额外往返页面和是否需要讲解。自动测试负责数据结果与状态恢复；能否理解文案须由实际操作验证。上述均为设计目标，当前未取得用户观察数据。

## 10. 高频面板逐项走查

具体布局、逐按钮交互、异常和模块验收以[高频任务面板交互详设](frequent-panel-interactions.md)为准。

本节细化 §4.1、§4.2 的按钮行为。依据是当前工作树的 TaskQuickEditor、TagMenu、CatalogPicker、TaskDetailsFields、WidgetTaskInspector 和 DesktopTray。表中改动为设计决策。

### 10.1 原位编辑和按钮弹层

原位行最重要的信息是正在改哪条任务、已填了什么。当前安排按钮有文字，标签的已选数量存在于辅助名称中，分类和旗标主要靠图标表达；打开多个选择器逐一查看才能确认一条任务的归属。保留一行紧凑工具区，已设属性优先显示值。变窄时先截断值并提供完整名称，保留操作位置。右侧的保存勾在有改动时显示为「保存」，与左侧完成圆分开。

| 按钮 | 打开后首先看到什么 | 如何结束，返回后看到什么 |
|---|---|---|
| 安排 | 现有日期和时间摘要；周期和提醒按 §5 展开 | 「应用」更新原行草稿，右侧「保存」持久化；独立安排入口使用「保存」。取消还原打开前的值 |
| 分类 | 当前归属及其完整路径，单选树；长列表可搜索 | 单击一个分类即回原行，按钮显示所选名称。收集箱表示移除分类，列为明确选项；同名二级分类以父级区分 |
| 标签 | 可勾选多个，打开时标出已有标签 | 连续勾选保持面板打开；「应用」带回草稿，「取消」还原本次勾选。按钮显示首个标签及其余数量。若实现已有逐项更新，弹层打开时保存当次选择快照即可支持取消 |
| 特别关注、详情 | 旗标直接切换草稿中的状态；详情带着当前内容打开 | 旗标就地给出选中反馈；详情返回遵循来源行锚点。拖动、保存和完成任务不共享点击区域 |

选择器一次只开一个。窗口靠近屏幕下缘时优先换向，使弹出项可点击，长列表到工作区边界才滚动。点另一选项不得穿透至任务行。键盘打开时聚焦当前值，Esc 只退一层并回到触发按钮。新建分类或标签是独立的资料操作；在任务内创建后，取消任务只撤销关联。

### 10.2 主窗任务详情

保留现有贴近任务的详情弹窗。用户打开详情通常为读长备注、调整多个属性或处理子任务。首屏阅读顺序为标题 → 备注 → 安排摘要 → 分类与标签；有父任务时显示可定位的父名。空备注只占一行，长备注按需扩展；普通任务的空关系和低频管理动作收在关系入口或更多菜单。根任务的「子任务（数量）」保留可发现入口，零项时能直接添加。子任务自身不展示再建一级的入口。

有修改时固定显示「保存」，清晰区分「关闭」「放弃修改」「完成本次任务」。关闭按钮遵循 §4.2 的保存保护，脏状态下用提示或可访问名称表明“保存并关闭”；显式放弃才丢弃输入。字段错误贴近出错项，冲突显示涉及字段与两份值。「重新载入」覆盖未保存内容前允许保留或复制。保存失败时仍能看见当前任务和可修正字段。

### 10.3 桌面小窗面板

小窗内有三种层级：面板标题与更多菜单管组件，任务行与右键菜单管指针下的任务，紧凑详情管该任务的草稿。组件层只放显示形态、层级及设置等；空白处点击只退出当前菜单，任务右键菜单首屏优先详情、完成和置顶，删除放末组。两类菜单打开期间暂停自动收起，菜单背景独立于小窗透明度。

小窗正文上方显示分类及当前范围，中部读任务，底部负责录入。点击某一行后只打开一个紧凑详情；进入安排时在同一面板换页，返回时保留标题和备注草稿。正在编辑子任务时，父名持续可见；从子项返回恢复父任务的子任务页及输入位置。临时失焦保留面板。本工作树已有失焦时调用 finish("close") 的路径，应优先实测点击输入法、子菜单与别的应用；只让明确的离开动作进入保存流程。跨到主窗口完整详情时，原窗口在保存成功后再交接。

### 10.4 系统托盘菜单

当前 Windows 入口用 QSystemTrayIcon 和 QMenu；主窗口、收集箱新建、组件显示、鼠标穿透、恢复点击、重置位置、设置与退出均已有命令。尤其要保留一个救援场景：组件开启穿透且移出可用屏幕时，用户只能从别处找回。建议保留原生菜单，按意图组织：

| 顺序 | 菜单项 | 触发结果 |
|---|---|---|
| 1 进入工作 | 打开主窗口；在收集箱新建… | 第一项恢复当前主窗上下文；第二项按现有实现打开主窗并聚焦新任务，原编辑有草稿时先走保护 |
| 2 桌面组件 | 显示／隐藏任务组件；启用鼠标穿透或恢复组件点击；重置组件位置 | 第二项按真实状态切换动词，把恢复放一级菜单。重置位置会显示组件，菜单中表明结果；重置不代替解除穿透 |
| 3 应用 | 设置…；分隔后退出 Daymark | 设置走现有设置入口；退出表示结束应用。存在未保存编辑时先完成草稿保护，日常关闭主窗到托盘保持原偏好 |

托盘左击沿用唤回主窗口；右击只开菜单。每次展开重读真实状态，包括由主窗设置改变的穿透状态。托盘不可用时，主窗设置须能恢复点击与位置。保留原生键盘导航及系统缩放。

### 10.5 实施优先级与实机验收

1. **先保草稿和命中。** 小窗输入半句中文，下拉选项超出原面板边界，点击最后一项，再切应用、返回。验证任务 ID、草稿、焦点和窗口状态。另测有未保存内容时从托盘进入新建、退出并取消。
2. **再验按钮结果。** 在同一次原位编辑中修改分类、连续选择两个标签、取消一次安排、打开详情并保存。检查最终字段及 SQLite 写入边界；复测选择同名二级分类、标签取消和只切特别关注。
3. **最后验阅读和找回。** 同一条含长备注及子项的任务在主窗和最窄小窗展示，测试深浅色、200% 文字及屏幕下缘。再从隐藏、穿透、位置偏离三种状态，通过托盘恢复到可点击的小窗，键盘和鼠标分别操作。验收记录首个不可达控件、误点对象、返回位置和是否需要额外打开主窗。
