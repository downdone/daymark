# Daymark UI/UX设计基准 v1

日期：2026-10-22。状态：**项目UI目标，待分批实现与验收**。依据：[Things/Apple官方调研](ui-research.md)、PRD §3、工程原则。本文件的尺寸、颜色、断点和动作预算均为Daymark自主设计目标，不是Things测量值或Apple强制数值。PRD业务与数据安全优先，不能以“更像Things”为理由改语义或删功能。

## 1. 产品体验目标

**安静、清楚、可靠、顺手。** 打开应用先看清今天要做什么；录入不费力，安排有明确含义，完成有反馈，失败能恢复。桌面组件让用户随时看到任务，主窗承担组织和计划。

UI目标分四层：正确且可恢复的行为 → 熟悉的桌面操作 → 低干扰信息层次 → 细节与动效。前三层不合格不能靠装饰补分。Things提供交互机制参考，Apple提供平台与人因原则，Daymark自行定义视觉与跨平台实现。

## 2. 信息架构与页面骨架

左侧保留PRD六个系统视图，其下日历月/周、Areas/Projects、Tags；未交付页面不放无效按钮。导航与动作分区，设置归设置入口，备份归数据设置/菜单；托盘与窗口命令不得靠被隐藏的侧栏底部作为唯一入口。

│ 导航开关              页面标题/日期               搜索  + 新任务 │
├──────────────┬────────────────────────────┬───────────────────┤

### 布局尺寸（DIP）

| 项目 | 初始目标 | 适应规则 |
|---|---|---|
| 主窗 | 默认1120×720，最低880×580 | 保留PRD；系统标题栏不重绘成另一平台样式 |
| 侧栏 | 默认220，范围200～260 | 可折叠；折叠后显式按钮仍能返回导航 |
| 详情 | 默认300，范围280～340 | 内容优先级低于任务列表；不足空间转主内容编辑页（UI-10） |
| 工具栏 | 48～56高 | 标题与主要动作同组，技术状态不挤占中心 |
| 标准任务行 | 单行44，元信息行按需增至48～64 | PRD标准密度40～48；大字可自然增高，不截正文 |
| 侧栏行 | 32～36 | 图标16～18；文字与右侧计数分列 |
| 正文边距 | 24～32，窄窗16～24 | 同列标题、正文、分组边界对齐 |
| 完成图形/命中区 | 图形18～20；命中区至少32×32 | 与行点击区域分离；不强迫移动端44pt用于所有桌面控件 |
| 浮窗/Mini | 默认340×360 / 260×48 | Floating可调；Mini文字放大时允许增高/展开，48不是裁剪约束 |

详情出现条件：先确保侧栏宽＋内容最小440＋详情宽＋必要边距均容得下；默认字体参考窗口≥1080DIP可以三栏，否则导航＋主内容编辑页。放大文字后以内容可用空间重算，不固定以设备或操作系统判断。超宽窗列表阅读列建议最大800DIP，不拉长短标题到整屏。

## 3. 视觉语言与token

### 表面与层级

默认使用一个连续列表表面；悬停/选中才出现弱背景，分组靠留白、标题和少量细线。任务行不默认做大白卡，侧栏不做一列等权大按钮。主要动作突出一次；恢复、编辑和更多是次级动作。

禁止用整页玻璃、全窗低opacity、持续发光或每行强阴影营造“Apple感”。主内容先保证可读，组件背景alpha与文字分离。支持减少透明度/高对比的实色回退；Qt能力不足时完整使用实色设计。

### 颜色候选（sRGB，均待实际状态对比验收）

| 语义token | 浅色候选 | 深色候选 | 用途 |
|---|---|---|---|
| surface.content | #FFFFFF | #202124 | 任务正文表面 |
| surface.sidebar | #F3F4F6 | #191A1D | 导航背景 |
| surface.hover | #F1F3F6 | #2B2D32 | 非选中悬停 |
| surface.selected | #E8EFFC | #263A5B | 选中背景，不代表焦点 |
| text.primary | #24272D | #F2F3F5 | 标题与正文 |
| text.secondary | #626976 | #B3B8C2 | 元信息；禁止降低整行opacity |
| accent / focus | #315DB5 | #93B6FF | 主要动作、焦点、活动日期 |
| feedback.danger | #B3261E | #FFB4AB | 错误/过期，附文字/图形 |
| feedback.success | #216B46 | #8BD5AD | 可恢复完成反馈 |
| separator | #D8DCE3 | #41454E | 分隔装饰，不独自承担控件边界 |

普通文字至少4.5:1；大字及必要图形/控件边界目标至少3:1；必须按**实际相邻颜色**校验。这里不因颜色表存在就标PASS。accent作填充时分别用白/深文字核查，不直接把浅色accent的反色用于所有状态。深色主题不机械反相；disabled、selected、focus、error各自验证。

### 排版、间距与图形

- 字体：读取系统UI字体并允许中文回退；macOS使用系统提供的字体，Windows使用其系统UI字体。禁止把Apple字体复制到Windows包。QML用语义字号token，不混用硬编码pointSize/pixelSize；初始目标为任务正文14～16逻辑像素等效、次级信息12～13、标题24～28，最终按平台字形与可读性校准，不能拿这些数值冒充Apple pt规范。
- 层次：页面标题semibold，分组13～14 medium，任务regular；避免全加粗。标题一行、溢出省略且可在详情完整读；元信息只显示存在的字段；长备注在详情滚动。
- 间距阶梯：4/8/12/16/24/32。控件圆角4～6、选中行6～8、覆盖面板10～12；保留平台控件合理差异。
- 图标采用一致线宽和基线，完成圆/日历/截止/更多独立绘制或许可明确。彩色图标仅在导航和日期语义中少量使用；不复制Things的标志性图形组合，不默认跨平台分发SF Symbols。
- 文本缩放目标100/125/150/200%，与OS DPI100/125/150/200%分别测试。Qt不等同SwiftUI Dynamic Type；以系统字体与应用文本缩放满足同一用户需求。尺寸是默认值，大字允许重排和增高。

## 4. 核心交互契约

### 4.1 导航与列表

一次点击导航切视图，保留每视图滚动位置；选中态和键盘焦点独立。上下键在任务间移动，Enter打开详情，Space仅在列表导航状态切完成，文本编辑中仍是空格。完成控件单击不打开详情，行单击不意外完成。更多操作在悬停、选中、键盘焦点时可达，也能由上下文菜单访问。

不把每任务的“编辑”大按钮作为唯一详情入口。新用户能看出行可选、完成可点；不能为了干净让所有关键动作只在hover存在。主操作命名使用动词，破坏性操作不作为默认Enter动作。

### 4.2 快速收集

始终有一个明确“新任务”入口和Ctrl/Cmd+N；快速录入默认标题为焦点。Enter提交后继续输入，Esc退出输入。默认Inbox；在Today等上下文录入要明确计划含义。无效输入原地提示，写失败保留文本；创建成功后可定位到新条目，因过滤不可见时提供“查看任务”。

快速录入目标从列表浏览状态开始至标题字段获得焦点≤1个显式动作；连续创建不需反复重开弹窗。不得将未落库任务显示成已保存。

### 4.3 详情与草稿

宽窗右侧详情、窄窗主内容编辑页共用同一编辑状态与命令，详见[UI-10](unified-task-editor.md)。优先标题、备注；归属/日期常用，标签清单在需要时展示；避免首次打开就像数据库表单。常规编辑无需模态确认链。

分阶段：当前显式保存保留，重构时先保证未保存离开保护；实现PRD的标题/备注400ms防抖后，失焦/关闭等待落库或保留失败草稿，才能减少常驻保存按钮。重要状态动作立即提交。Esc关闭一层临时UI；脏草稿需保存/放弃/取消；不得将“关闭”和“取消任务”放在容易误触的位置。

### 4.4 排期

计划开始、截止、提醒分开命名。日期选择器有今天/明天/选择日期/清除入口，保留键盘与本地化展示；高级/直接输入可接受ISO格式，但不是唯一方式。无效范围显示字段附近原因；未成功前列表不跳到另一日期。

同一taskId在Today/Anytime重叠是预期，不以“去重视觉”为由改变QueryService。Someday显示“日期已暂停”；未来任务加入Today调整开始日并给轻提示；移出Today时说明仍命中日期条件的原因。日历Start/Deadline使用文字/图形区分，同日合并移动先明确字段。

### 4.5 完成、删除与恢复

写入pending使用局部反馈，成功后短暂完成过渡再移至Logbook；不因动画延迟接收其他任务操作，不把视觉反馈当已保存。失败原任务留在位置并可重试。

普通删除采用软删＋8秒轻量撤销；完整编辑菜单需区分文本撤销与任务撤销。多步撤销属后续交互增强，当前仅最近删除撤销必须如实标注。删除项目和替换导入仍按PRD二次确认，不能一律改成无确认。

### 4.6 搜索

入口可见且Ctrl/Cmd+F可达；激活后显示当前范围、清除、退出以及结果数。默认标题/备注的全局未完成搜索，历史包含选项按PRD提供；不将导航结果和可编辑任务结果混在无标识列表。Type-to-search不是首批目标，避免干扰中文输入法和文本编辑。

### 4.7 日历与组件

月/周保持同一任务、同一详情，周视图无小时轴。月格最多先显示3项和+N，点击展开当日列表，不裁剪到不能操作。

Floating最多先呈现8项可滚动；Mini提供今日数量及第一项摘要，空间不足可省略标题但不隐藏展开通路。表头拖动与完成/展开区域分开。被动刷新不抢焦点，不自动弹出主窗。穿透必须先建立托盘和主窗外部恢复入口；减少透明度、深浅背景、高对比都保持可读。

## 5. 状态、文案与反馈

| 状态 | 表现 | 禁止 |
|---|---|---|
| 默认 | 任务标题、少量必要元信息 | 大段工程解释常驻 |
| Hover | 弱背景/更多动作出现 | 整行突然改变尺寸 |
| Selected | 弱强调背景，详情关联清楚 | 与键盘焦点共用唯一标识 |
| Focus | 清楚焦点环/轮廓，键盘可追踪 | 去掉outline只保留颜色 |
| Pending | 局部指示、阻止该命令重复提交 | 全页长期禁用或输入被清空 |
| Success | 安静的就地更新，可定位结果 | 每条完成都弹模态/音效 |
| Error | 原地短解释＋可行动恢复，保留输入 | 仅stdout或“出错了” |
| Empty | 当前视图说明＋可用下一步 | 只显示空白或未实现按钮 |
| Offline | 正常核心能力 | 无必要的离线警告条 |

文案说用户任务，例如“开始日期不能晚于截止日期”，不在产品中使用row_version、Repository、QSQLITE等实现词。PRD必要的保存/失败状态可用简短状态区，不把每一页变成调试控制台。技术诊断集中到设置/支持页。

## 6. 平台、可访问性和动效

macOS菜单栏提供应用/文件/编辑/视图/窗口/帮助的适用命令；Windows保留系统窗口与Ctrl习惯。使用Qt StandardKey处理编辑常用键；项目导航数字键遵守PRD，不照搬Things编号。Alt+F4和Cmd+Q/关闭窗口的含义按平台与托盘设置解释。

所有关键动作有键盘路径、可访问名称、角色、状态和合理顺序；tooltip不能作为唯一名称。字体放大、读屏、减少动态效果、减少透明度和高对比按实际平台能力验收；不以QML Accessible.name存在代替VoiceOver/Narrator实测。

动效120～200ms作为项目初值，主要解释展开、完成与层级变化；减少动态效果时替换为即时或轻淡入。重复高频操作不播放大幅弹跳。动画可中断，不阻挡保存与连续勾选。圆角和动效是最后打磨项，不先于焦点/读屏/草稿安全。

## 7. 工程落地约束

新增Theme/Tokens及独立NavRow、TaskRow、IconButton等QML组件，封装视觉与输入；QueryService/Repository保持既有边界。主题切换只改token，日期/状态判定仍在C++。先做一个Today完整纵切再推广，不一次重写全应用。

每次UI改动先列受影响UX基准ID、状态和验收截图条件；完成后按 [UI验收](ui-acceptance.md) 检查。新视觉可以逐步落地，当前BASIC-01在未迁移组件上允许保留，但不得将其截图作为最终UI目标。

UI-12自主数值修订：默认控件32DIP起（文字放大按内容增高），标题24DIP、页边20DIP、字段间10DIP，紧凑模式字段间8DIP；其他操作和可访问性目标保留。具体设计见[整体精修](ui-polish.md)，实际状态只见PROGRESS。
