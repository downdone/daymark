# 功能定义与验收

状态：功能契约；Windows实现入口见implementation.md，实际验证状态见PROGRESS。UF为更新子系统的设计需求ID，不改写原PRD历史FR编号。P-01/03/07～13与既有UX-09/11/13适用；Apple HIG按项目[基准](../ui-baseline.md)映射为清晰状态、用户控制、不中断工作、失败可恢复、键盘/缩放/辅助技术可达，具体数值为Daymark定义。

## 1. 功能清单

| ID | 固定行为 | 可执行验收 |
|---|---|---|
| UF-01 启动检测 | 默认自动；RuntimeReady后约3秒异步检查。隐藏主窗/启动托盘同样适用；重复激活不触发，测试/smoke禁联网 | 首窗/资料可用无需等待网络；一次实际启动最多一轮；限流时明确使用缓存/延期 |
| UF-02 发现资格 | 正式SemVer、Windows x64、签名清单/ZIP齐全、运行时/布局/引导/数据兼容 | 错架构/同版本/源码ZIP/半发布/错误签名零安装 |
| UF-03 自动准备 | 发现合格新版自动唤起updater prepare，下载、验签、解压、预检到独立目录 | 当前EXE/DLL不改，用户继续操作，整个包不进入主进程内存 |
| UF-04 过程反馈 | 关于页可看真实阶段/字节进度并取消；后台不弹模态进度框 | 未知大小不伪造百分比；取消不恢复旧请求状态 |
| UF-05 安装完成 | Ready落盘才提示“更新已安装，重启后生效”；立即重启/稍后 | 下载完但验签/预检未通过时不能显示安装完成；prepare退出无常驻进程 |
| UF-06 重启切换 | 立即重启走保存退出门；稍后则下一次正常从根入口启动时应用Ready | 不因关主窗进托盘就偷偷切换；下次即使关闭自动检测，已Ready仍可明确应用/取消 |
| UF-07 保存失败 | 任一草稿、命令排空或设置失败取消切换，保留输入并提示 | 不强杀旧应用、不丢草稿、不显示成功 |
| UF-08 健康与清理 | 新版就绪、持久化提交、正常生产初始化RUNNING确认后自动清旧版 | COMMIT前不删除；RUNNING未确认不删除；占用延期，无未知文件递归删除 |
| UF-09 故障恢复 | 提交前失败恢复已验证旧版；提交后失败启动新版修复路径 | current/journal/消息不一致时单一裁决，不能同时放行新旧版写资料 |
| UF-10 手动入口 | 主窗底部工具栏及设置→关于可检查更新；Ready 可重启，关于页保留说明/取消 | 不需账号、不输入URL，小窗保持任务操作 |
| UF-11 关闭自动 | 关“每天自动检查并准备更新”取消当前prepare；已有Ready保留并有明确取消入口 | 不再自动新下载；取消Ready后下次用当前版；手动检查仍可用 |
| UF-12 网络与取消 | 超时/限流有界，断点安全保存，用户取消同候选至少24小时不自动重下 | 不循环重试至通过；退出应用后prepare有界停止；下次启动按策略续传 |
| UF-13 多实例 | 同安装一个prepare，apply前其他资料进程需先关闭；安装锁与资料锁分离 | 不触发多份ZIP；不替其他资料强制退出；不同安装不夺同资料锁 |
| UF-14 磁盘控制 | 正常仅当前+一个Ready；旧版清理待完成时不自动准备再下一版 | 空间不足不删当前/备份腾空间；失效孤立staging有所有权才清理 |
| UF-15 数据边界 | 任务/账号/备份和设置不随版本删除，旧/新共享同一资料命名空间 | 升级不出现空资料/重新登录假象；未登录核心仍离线可用 |
| UF-16 首次/兼容边界 | 现有版本手动安装一次引导包；不同schema/ABI或更高引导协议显示手动升级说明 | 不在自动更新中隐式迁移DB/提权或覆盖引导器 |

## 2. 用户可见状态

| 状态 | 文字/主动作 | 后续 |
|---|---|---|
| Idle / Deferred | 当前版本/检查更新；必要时显示下次可检查时间 | 从未成功检查不能显示最新 |
| Checking | 正在检查更新/取消 | 成功发现合格版自动prepare |
| Available / Preparing | 已发现新版本，正在准备更新器/取消 | 不要求再确认下载 |
| Downloading | 正在下载…字节进度/取消 | 校验→解包→预检 |
| Verifying / InstallingSideBySide | 正在验证/正在安装新版本/取消 | 写入Prepared记录成功才Ready |
| Ready | 更新已安装，重启后生效/立即重启、稍后；次级取消待应用 | 不强制重启 |
| SavingAndClosing | 正在保存并重启/保留既有保存失败处理 | 成功才允许apply切换 |
| Switching / RestrictedStartup | 正在完成更新 | 原生启动提示在较慢时出现，不播虚假百分比 |
| Running / Cleaning | 正常任务界面，后台清理旧版 | 清理失败不遮挡任务 |
| Failed / ManualRequired | 可操作原因、重试/查看发布页 | 不含任务/密码/临时签名URL |
| RolledBack | 新版未完成启动，已恢复旧版本 | 仅恢复成功后使用该文字 |

Ready提示仅该候选一次；关闭提示不取消Ready。主窗隐藏可用现有系统通知，系统通知被禁用时关于页保留可见状态，不能因通知失败阻止更新或抢焦点。自动准备失败默认仅在关于页显示，非每次启动弹窗打断。

设置页不常驻安装路径/原始协议/哈希等开发信息。可展开发布说明、当前/目标版本、大小及最后检查时间；诊断导出是次级主动动作。根启动器apply提示使用Windows原生可访问控件，尊重系统DPI/字体，不引入另一个Qt界面依赖。

## 3. 调度与资源约束

- 同安装自动检查最短24小时，长期运行用低频唤醒复查；手动重查可立即执行，仍遵守服务端Retry-After/reset。网络失败的自动检查也服从24小时间隔。
- 用户取消候选的24小时限制只阻止自动重下，明确手动重试可立即执行并遵守服务端限流。缓存验证、解压时取消与下载中取消使用同一候选退避。
- Ready存在时不自动准备更高候选；手动替换候选必须先明确取消Ready，不能悄悄扩大磁盘占用。
- 更新器取消下载/验证必须5秒内停止可取消工作并保存状态，超时主程序记录未完成、禁止新worker争抢同任务。主程序不在取消失败时强杀正在切换的apply进程。
- 更新进度最大10Hz，阶段变化立即发；无包时无更新器进程。检查/准备不能阻塞Qt主线程、资料命令或提醒。
- 下载最多512MiB，解压最多2GiB/10,000文件，文件索引最多8MiB；更大正式包需要新能力协议或显式修订，不能现场忽略限制。

## 4. 必须设计并验证的界面组合

浅/深、100%/200%文字、窄设置窗、鼠标/Tab/Space/Enter/Esc、长发布说明、网络离线、主窗隐藏、保存失败、取消后重开、Ready重启恢复。主动作文本始终可见，窄窗操作换行但不覆盖进度/正文；帮助使用必要说明而非悬停才知关键状态。读屏名称/进度播报节流、原生更新提示焦点、物理DPI与Qt离屏分别留证。
