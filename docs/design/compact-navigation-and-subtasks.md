# 紧凑导航与两层子任务（UI-32）

2026-10-25。FR-025/030/031及新增FR-032，UX-01/02/04/05/07/09/11/14，P-13/14。依据用户两张截图；沿用[UI-31](macos-desktop-language.md)官方HIG Sidebars/Hierarchy/Consistency/Agency/Accessibility映射，尺寸为Daymark自主值。

## 问题与方案

导航26DIP图标底座、32DIP动作和较大分区间隔叠加，文件夹/标签显得过重。去来源行的彩色/白色底座，保留16图形和文件夹形状；导航文字12、分区12、系统正文14/任务标题13不全局缩小。行32起、间隔0、分区4、二级缩进16，侧栏208起，智能卡60起、计数16。顶部六入口和底部工具仍清楚，200%按文字增长；动作命中至少32，不能为了紧凑裁掉名称或恢复入口。

子任务旧面板在窄窗把列表和完整详情同放一列，两者fillHeight使详情位于视口外；切tab还自动选第一项，产生隐性编辑对象。改为单一页面：父任务“详情”编辑父项，“子任务”只列直接子项、圆形完成、少量备注/日期摘要及信息按钮；点击标题/信息直接进入该子任务详情。子项没有无意义的子任务tab、添加下级或“查看此子任务的子任务”按钮。返回和保存回到父项子任务列表，保持独立任务ID与草稿保护。空列表给简短空态，新增保留连续输入。

## 关系约束与兼容

正常关系仅两层：根任务→直接子任务。Service拒绝在子任务下新建、将任务归入子任务、将已有下级的任务降为子任务；父任务选择器只列合法根。循环/自引用仍先校验；拒绝必须零修改并给可操作原因。任务属性编辑、删除/完成/分类移动联动保持。

已有深层旧库/JSON继续可读、可编辑原关系、可备份和恢复，不更改schema或静默扁平化。既有下级仅在真实存在时显示兼容访问入口，子项仍不能新增更深层；用户可清除父关系整理为独立任务。测试用Repository构造旧多层数据验证兼容恢复，不再用新Service创建三级关系。

## 验证

临时库覆盖新建/改父拒绝、带下级降级拒绝、失败历史/版本零变、可脱离再归属、父选择合法候选及旧深层整树联动。QML真实行点击进入可见详情、保存/返回、草稿取消与放弃、无下级入口、导航列/缩进及排序，浅深/880/200%截图。保留原407阶段数据/键盘/手势/窗口门禁并按新导航替换旧隐式选择断言，45/120秒不放宽；Debug/Release17项、lint、Cocoa与静态检查，物理输入/读屏/Windows另列。
