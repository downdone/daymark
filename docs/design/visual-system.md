# UI-13：视觉关系与日历事项

本页为历史设计；当前全局字号、配色、半径、线框与矢量图标唯一值见[UX-48](global-visual-system.md)，与下文旧数值冲突时按UX-48执行。

FR-007/010/018、UX-01/05/06/09/10/11/12。用户截图指出：紧凑日历只显示数量；详情外框和每个字段的闭合边框叠加，缺少统一关系。本轮规则替代UI-07/12中冲突的边框表达；保存/草稿/日期/单轴滚动和查询语义不变。

当前色彩与动作呈现由[UI-15动作和配色](actions-and-color.md)更新；下表布局/字形/边界职责保持，旧具体色值以UI-15为准。

## 整体视觉原则

UI-14扩展：[全界面设计](hig-redesign.md)。FormGroup以浅色分组而非描边卡片组织相关字段；SegmentedPicker选中同时使用背景、字重和强调色，支持左右键；EmptyState提供解释和必要的下一步动作。菜单外层12、行内6DIP圆角；图标随文字放大但上限24DIP，命中区至少32DIP。普通字号设置窗口560DIP上限、批量窗口随内容收缩；大字/短窗保留固定操作栏和滚动正文。所有值为Daymark自主选择。

| 层次 | 统一规则 | 目的 |
|---|---|---|
| 字体 | 使用Qt读取的平台系统UI字体，中文按系统回退；不分发字体、不模拟另一平台 | 与原生标题栏及系统文字协调 |
| 字号/字重 | 正文14 regular；字段标签/辅助12 regular；分组15 demi；面板18 demi；任务标题20 demi；页面24 demi。全部跟随100–200%文字缩放 | 同类信息同层级，避免所有标题都加粗 |
| 布局 | 4/6/8/10/12/16/20/24阶梯；字段间10、分组留白16–20、页边20；编辑正文最多680×文字比例，居中，宽窗侧栏344起 | 避免横向超长输入框，形成稳定阅读轴 |
| 容器 | 页面连续表面；停靠详情只用左分隔线；窄窗编辑页不画大圆角外框 | 不用框套框表达每一层 |
| 输入 | 常规字段浅填充＋一条底边线；悬停加深填充；聚焦才出现2DIP强调轮廓。标题/备注作为文档正文，默认无框，焦点用底线 | 可编辑性由标签、填充、文字提示与焦点共同表达 |
| 线条 | 装饰分隔1DIP低对比；字段底边1DIP、必要对比3:1；焦点2DIP、3:1。禁止用深色完整轮廓包围每个字段 | 区分结构、输入和焦点的职责 |
| 圆角 | 常规字段/按钮6；选中行8；真正覆盖弹层12；页面与停靠面板0 | 圆角跟随层级，不随处使用卡片 |
| 色彩 | 文字/表面/字段/状态取UI-15成对语义token；蓝色仅强调/焦点/选中，危险色附文字 | 安静但可识别，选中与焦点保持区别 |
| 按钮/图标 | 每区一个主要蓝色动作；次要动作中性填充、无默认描边；工具透明，32DIP命中区、统一线宽，焦点可见 | 主次分明，减轻按钮和字段边框竞争 |
| 状态 | Default/hover/selected/focus/disabled分别表达；错误文字保留输入；装饰动画不影响正文位置 | 不以视觉精简牺牲可恢复性 |

复选框、完成圈及弹层保留必要轮廓，与表单行的装饰边框分工不同。

数值为Daymark自主选择，并非Apple/Things规范数值。字段底边与实际相邻填充、正文与背景分别计算对比；装饰线不作为唯一交互标记。真实读屏和OS高对比模式单列UNVERIFIED。

## 日历事项契约

紧凑模式仅决定议程上下排列，不得隐藏月格的事项标题。每个有事项的日期格至少显示一条具体标题；按实际高度显示更多，剩余用“+N”。类型/完成状态独立标记，长标题省略并提供完整提示/可访问名称；点击标题打开同一任务/事件，+N进入当天议程。默认、窄窗、200%都保留这一路径。增加最小格高，避免标题和数量互相裁切；允许外层纵向滚动，不增加格内滚动条。

## 验收

Debug/Release构建和CTest、应用/样式lint；原生合成数据验证默认和200%月格真实标题delegate非空且文字对应同一事项，格内不溢出。截图检查浅深、880/1120/1440、详情标题/备注/日期/底部动作及日历。验证字段/焦点对比；草稿/错误/Tab/日期弹层和短备注滚轮回归保留。自动测试使用QTemporaryDir；不改真实数据、业务层或历史迁移。原生部署/完整矩阵独立记录。

## Apple HIG依据与本轮映射

遵守[项目原则P-13](../principles.md)：Purpose/Simplicity落实为月格直接读事项、正文优先；Familiarity落实为系统字体与Windows窗口/键盘习惯；Flexibility落实为宽窄/200%重排而不隐藏事项；Agency/Responsibility保留草稿、原子保存及错误恢复；Craft落实为层次/完整状态/实际截图，Delight体现为安静且可预测的反馈。形状与数值为Daymark实现选择，来源及边界见[官方调研](ui-research.md)。

UI-17修订：常规控件圆角8、选中行10、任务内容组16，开关为胶囊；任务详情采用灰画布/白内容组（深色对应），组内保持UI-16同行关系，见[iOS分组设计](ios-grouped-details.md)。
