# Daymark 全产品体验复审与实施方案

2026-10-24，回应用户对整个UI/UX、功能定义及“简约而不简单”的要求。依据[产品哲学](../product-philosophy.md)、PRD FR-001～022、UX-01～14及P-01～14。本文记录源码和合成截图发现的问题、设计裁决、后续实施边界；不是用户研究结果，也不将设计目标当成已实现。执行状态只维护于[PROGRESS](../PROGRESS.md)。

## 1. 核心判断

Daymark应帮助人**记下事情、决定下一步、按时关注、安心完成和回顾**。软件内部可以有完整的数据关系和时间规则，日常使用不应像管理数据库。

当前主要矛盾是功能并排陈列、层级不足：任务的状态、归属、日期与标签一起暴露；工作页面与资料管理页面接近；重复的标题、说明、提示和按钮挤走正文。只换圆角、颜色或把弹窗放大，都不能解决这些问题。

因此采用以下裁决：

1. **简约而不简单。** 每个常驻元素必须帮助判断当前位置、当前内容、下一步动作或真实风险。必要能力保留，通过清楚的层级和上下文降低负担。
2. **行动优先，组织可选。** 第一条任务只需标题；领域、项目、标签均不成为入门步骤，不预置一套要求维护的分类法。
3. **工作页服务内容，管理页服务整理。** 项目页用来推进结果，领域页用来回顾责任；改名、归档、配色等低频操作不占工作页主体。
4. **一个事实，多个视角。** 今天、随时可做、日历、组件引用同一任务；标签不拥有任务，搜索不移动任务。
5. **安静而可信。** 后台维护安静执行；只在确实有草稿、等待、结果或错误时反馈。不用常驻“已保存”代替真实保存状态。

## 2. HIG映射与取舍

本轮读取Apple官方页面及其同域Markdown正文。以下为Daymark自己的设计规则，不是Apple规定的控件数量、尺寸或Qt实现；Windows保留自身窗口、系统字体、Ctrl快捷键和托盘习惯。

| 依据 | 在Daymark中的裁决 | 对应验收 |
|---|---|---|
| [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)：Simplicity、Purpose | 删除没有当前用途的常驻元素；优先内容和高频行动，说明放到空态、按需帮助或真正发生风险的位置 | UX-01/03/09/10；不能用密集小字或只剩图标制造简洁 |
| 同上：Agency、Responsibility | 分类可选，离开草稿有选择，危险后果明确，失败保留输入 | UX-05/07；简约不降低数据安全 |
| [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) | 稳定目的地、两层归属、可折叠且有恢复；不把管理命令伪装成列表内容 | UX-02/09/11 |
| [Modality](https://developer.apple.com/design/human-interface-guidelines/modality) | 长期浏览在内容页；短时选择、单项输入、危险确认可用弹层。不给每种功能再建一套弹窗导航 | UX-05/07/14；保留合理模态，不做“零弹窗”指标 |
| Design principles：Flexibility、Familiarity、Craft | 宽窄/200%不丢上下文，键盘与辅助技术可用，视觉和动作一致 | UX-04/09～14；原生与合成证据分列 |

## 3. 对象、视图与入口各司其职

| 对象或视图 | 一句话意义 | 不承担的职责 |
|---|---|---|
| 任务 | 一个可以完成的行动 | 不要求先建项目，不等于占用小时的日程 |
| 项目 | 一个有完成条件的结果 | 不作为永久分类；完成项目不擅自完成子任务 |
| 领域 | 一项长期责任 | 不设置虚假的“完成”目标；退出关注用归档 |
| 标签 | 跨归属找到相似行动 | 不改变归属、规划或日期；不增加第二套文件夹 |
| 日程 | 在某段时间发生的事情 | 不因准备任务完成而结束，不充当任务状态 |
| 今天/即将到来等 | 从行动阶段或时间看同一批任务 | 不复制实体，不因界面更干净而改筛选规则 |
| 项目分组/检查清单 | 项目内部阶段/单个行动内部步骤 | 不进入全局侧栏，不产生独立的日期与提醒 |

默认导航以六个系统视图和日历为主；领域下呈现项目，独立项目直接可见。标签已有内容时才占据独立列表，没有标签时仍可在任务归属字段或整理页新建。规划只保留日历与重复安排，重复任务和循环日程共享发现入口，内部保留不同语义。提醒历史是辅助工具，不显示历史量冒充未读徽标。

设置和数据管理保持低优先级、稳定可找；穿透恢复和退出不能只依赖侧栏底部。未来可按实际使用证据调整重复安排的可见优先级，当前不删除既有入口或要求用户先自定义侧栏。

## 4. 逐条操作链

| 场景 | 目标操作链 | 复杂性出现的位置 | 失败与退出 |
|---|---|---|---|
| 第一次记录 | 打开收集箱→输入标题→Enter→继续记录 | 不要求分类、日期、注册或教程 | 空标题拒绝；失败保留标题，不出现成功反馈 |
| 澄清一项 | 原行打开→改清楚行动→按需归属/安排→保存 | 快速编辑处理常用属性；完整详情处理备注、清单等 | 快速与完整共享草稿；取消/放弃/保存导航边界一致 |
| 开始一天 | 看今天→辨认到期/关注原因→决定顺序→完成 | 晚上仅有内容时呈现；解释原因按任务需要出现 | 日期导致仍在今天时，移出提供重新安排/以后再说/保留 |
| 推进项目 | 进入项目→看结果及下一步→补任务→完成或结束项目 | 项目设置在上下文，分组在项目内部 | 结束说明未完成数量；恢复可继续，删除保留任务 |
| 回顾领域 | 进入责任范围→看项目和零散任务→决定推进或暂缓 | 直接任务与项目分组展示，已有归属不再重复录入 | 归档后恢复路径明确，不隐式删任务 |
| 安排日历 | 看月/周→选日期→看当天任务与日程→修改一个日期或编辑日程 | 事件时间与任务开始/截止分别展示，溢出有明确入口 | 冲突回滚、草稿保留；单个实例与整个系列范围明确 |
| 周期安排 | 新建任务规则或日程系列→选周期→看摘要→保存 | 周/月/年只显示适用字段；后续实例预览按需 | 停止产生与删除未来实例分开，历史保留 |
| 回顾与恢复 | 已完成→找到内容→恢复；数据页→预览→选择→确认 | 回顾历史和导入替换是不同任务，不堆进今日列表 | 软删撤销、CAS、导入零修改、替换先备份等契约不变 |

## 6. 统一页面与状态规则

### 内容与动作

页面上方只需要清楚的标题、真正有用的动态摘要以及当前动作。今天的日期与待办数有用途；“选择任务查看详情”“领域承接责任”等反复常驻的说明不承担同等用途。概念说明只在空态需要理解时出现一次，帮助文档承担完整解释。

一个操作在同一状态只设一个主要入口；返回列表、创建和保存不同时争主位。编辑状态以内容和保存为主，创建另一个对象需先退出或通过既有列表。项目设置不占据项目工作页主体，危险动作靠后，确认时讲清影响。

重要动作保留文字，常见且有名称的图标可节省空间；不把所有文本改成问号或更多菜单。200%优先减少无效层次、让正文滚动，保持提交区可见，不能缩回文字或缩小点击区域。颜色、图标、字重、间距表达同一层级，避免靠多层框/卡片补层级。

### 草稿、反馈与错误

| 状态 | 显示与操作 |
|---|---|
| 浏览/空闲 | 直接看内容；无常驻“已保存”口号 |
| 未保存 | 编辑表面一个清楚标识及保存入口；切换经统一导航保护 |
| 显式操作进行中 | 禁止重复提交，准确称“正在处理”或该具体操作；不将所有busy称“正在保存” |
| 后台维护 | 不弹全局转圈/保存提示，不打断输入/长按；失败需要可行动反馈 |
| 成功 | 以真实完成信号更新内容；需要撤销的结果保留可恢复入口，不常驻多条成功标语 |
| 校验错误 | 对应输入附近说明如何修正，保留草稿；不传播到无关页面 |
| 存储/冲突错误 | 不显示成功，不丢输入；提供重试/重载与风险说明，不能以清空错误掩盖失败 |
| 无结果/无数据/加载失败 | 分开说明；无结果清除搜索/筛选，无数据就近创建，加载失败重试，不能统一装作空库 |

### 键盘、辅助技术与平台

Tab顺序跟随视觉主线；编辑输入时Space/Enter/IME候选键优先属于输入框；Esc先关闭当前临时层，再经草稿保护离开。导航选择应被辅助技术读出，不能只染色；NavRow当前有自定义selected与highlighted，真实选中播报需VoiceOver/Narrator实测，不能仅由Accessible.name推断通过。

真实系统菜单、中文IME、鼠标/触控板、读屏、多屏/DPI、睡眠/午夜、通知权限和穿透恢复逐项验收。现有309阶段合成smoke覆盖广，但与计时、焦点和维护耦合；按ENG-01逐片拆成能力场景，保留综合退出门禁和原断言，不放宽预算掩盖回归。

| UI-25 时间与查找 | 承接CAL-06剩余事件检索/定位，重复摘要/实例预览、提醒范围及密度 | 服务输出，10k、跨日/周/月/年/DST及整个系列范围；无小时排程/单次例外扩张 |
| UI-26 设置与恢复 | 设置呈现、数据概览、清楚导入步骤、窗口设置同源 | 即时偏好失败、WAL备份/预览/双确认/回滚、托盘不可用及穿透恢复；不触碰真实库 |
| UX-平台门禁 + ENG-01 | 实际键盘/IME/读屏/多屏/通知/长时与独立分发；按能力拆smoke | 平台矩阵分别记录PASS/FAIL/UNVERIFIED；自动成功不解除人工门禁；不混入新功能 |

后续设计的取舍标准是：日常能否更快看清和完成事情、是否少做无意义选择、是否仍理解操作后果。不是控件越少越好，也不是功能越多越完整。视觉截图只能证明指定状态的布局，形成性用户评估继续按UX验收执行，当前没有真实用户成功率或耗时结论。
