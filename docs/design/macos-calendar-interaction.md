# UX-39 macOS日历交互对齐

本轮用户明确要求日历操作对标macOS Calendar，覆盖UX-35的单击空白即新建约定。范围FR-034～037、UX-02/03/04/05/06/09/10/11/12/14；共享主窗和独立日历，不改变统一任务、循环实例、CAS、DST或草稿保护。

## 对照与完整交互契约

| 操作 | 当前差距 | 本轮契约 |
|---|---|---|
| 单击事项 | 月格立即编辑，小时轴只选中 | 日周月统一先选中，以填色和焦点表明目标；双击/Return/详情菜单编辑同一任务 |
| 月格空白/日期 | 双击总是打开议程 | 空白双击新建所选日期任务；日期数字双击进入日；更多入口继续打开当天议程 |
| 日周空白 | 单击直接弹大表单 | 单击选中时刻，不写库、不弹窗；双击/Return新建一小时草稿；拖选范围释放新建，Esc取消无写入 |
| 日期头/年视图 | 周日期、年日期单击即跳转 | 单击选择；双击日期进日、双击月份进月；键盘Return提供等价入口 |
| 新建 | Cmd/Ctrl+N退出日历到收集箱 | 保留日历范围和视图，在所选日/时刻打开就近草稿；独立日历同样工作 |
| 视图快捷键 | 数字键切智能范围，Mac手写Meta误用 | 日历上下文Cmd+1/2/3/4对应日周月年；Windows对应Ctrl；非日历仍保留任务导航 |
| 导航 | 无今天/日期/前后快捷键 | Cmd/Ctrl+T今天、Shift+Cmd/Ctrl+T跳日期、Cmd/Ctrl+左右前后；不抢文本输入的普通方向键 |
| 选择后的编辑/删除 | 月格无稳定选中事项，必须鼠标 | Return/Cmd+E编辑，Delete经现有安全删除门；Esc先取消手势/选择；文本编辑不被这些命令截获 |
| 改期 | 已有真实坐标、15分钟吸附、整段/端点与CAS | 保留并统一选中、光标/预览；未拖过阈值不移动，取消不写，失败不伪造结果 |
| 视觉 | 整日大蓝背景、每块描边、冗余信息按钮 | 日期数字与事项分别表达选择；时间块用细色条/淡底，选中加强填色，端点及详情只在选中/焦点时出现；周末弱分区、现在红线；文字缩放保持视口的实际时刻，不能因像素高度变化把08:00变成04:00 |

Apple事实来源：[日期/视图与手势](https://support.apple.com/en-md/guide/calendar/icl1010/mac)、[键盘](https://support.apple.com/en-ae/guide/calendar/ical002/mac)、[创建与编辑](https://support.apple.com/guide/calendar/create-and-edit-events-icalwr70783/mac)。双击编辑、拖动改时段和端点来自这些官方指南；尺寸、色值、实现及时间块选中视觉是Daymark独立设计。Qt的便携Ctrl在macOS映射Command，Meta映射物理Control，依据[Qt QKeySequence](https://doc.qt.io/qt-6/qkeysequence.html)，不能用Meta字符串冒充Command。

## 数据与边界

CalendarPanel拥有只读选择身份/日期/分钟和命令路由，月格/时间轴只发选择与编辑意图；所有写入继续C++服务和主窗离开保存门。新增仍是一份未落库草稿，取消不生成占位任务。独立日历不改变主窗范围。系列批量修改、系统日历订阅/账户/邀请、旅行时间、自然语言解析、跨日历剪贴板、日历多选及触控板物理手势需要独立契约与测试，不能在此次基础对齐中宣称与Apple全产品等价。

## 验收

独立临时库验证月格单击不编辑/双击编辑、日期与空白双击分离、小时空白单击无草稿/双击及拖选新建、Ctrl+N不离开日历、1～4/今天/跳日期/前后、文字编辑不误删、独立日历一致、失败保留；保留已有整段/端点/Esc/CAS/DST/草稿测试。浅深、窄窗、200%、键盘与实际截图分别记录。旧完整长探针失败仍保留，不增加watchdog预算；macOS实机/IME/读屏/物理触控板无证据时UNVERIFIED。
