# 统一起止安排与直接动作（UI-33）

2026-10-25。FR-027/028/030～033，UX-02/04～07/09/11/14；按用户截图，替代“计划日期与日历时段独立”的旧定义。遵循P-13/14及UI-31的HIG一致性、上下文、可恢复动作与键盘映射。

## HIG与操作关系

依据[一致性与平台习惯](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)、[上下文菜单](https://developer.apple.com/design/human-interface-guidelines/context-menus)和[就近小面板](https://developer.apple.com/design/human-interface-guidelines/popovers)：同一内容在不同视图保持身份和属性一致；主点击查看或简易编辑，右键只提供当前任务合法动作；菜单命令完成后焦点回原任务。分类/标签改名就近弹出并聚焦全选名称，Escape与点击外部仍遵守脏草稿保护。日期入口直开日历，具体时间在同组渐进显示，不并列两套同义安排。

对应UX-02验证视图身份与返回，UX-04验证点击/完成/右键分离，UX-05验证同一详情及草稿上下文，UX-06验证统一起止、提醒和DST，UX-07验证软删恢复与失败零修改，UX-09验证200%布局，UX-11验证菜单/日期键盘及焦点，UX-14验证Cocoa与系统拖动阈值；物理输入和未运行平台另列。普通拖动使用运行平台阈值；计划/历史排序限制经菜单可用状态表达。保留Menu/Shift-F10、完成/删除恢复、CAS失败保留原数据、浅深与200%自然增高。上述为设计要求，实际状态以PROGRESS及验证报告为准。

## 单一安排

任务只有一套开始/结束，可只设日期，也可指定时分及所属时区；日期在列表/日历都是同一事实。保留原开始/结束字段位置，改名为开始、结束，移除第二套日历时段日期与开关；“全天”控制是否显示时间。无日期不强迫安排。日期图标直开选择器，日历任务/横条/议程单击进入同一任务详情。

不改schema。既有schedule为精确时间事实，旧date列为兼容日期投影；读取统一由C++投影。时间安排修改时同步日期列，日期修改时在原时区按墙钟重建时刻，不用24小时秒数换算日历日，非法/DST时刻拒绝且零修改。定时任务详情保留所属时区墙钟输入；日历、今天归属与逾期按本机时区投影同一UTC，不因原时区日期较早而提前进入今天或标为逾期。只改开始时平移旧时段，明确结束时独立校验；清除日期取消其具体时间。只修改备注等属性不自动覆盖旧不一致日期；界面有旧日期差异提示，用户修改安排时明确统一，原日期前后值写入编辑记录。旧JSON/备份仍可恢复，循环生成维持独立任务ID和时区。

## 拖动与右键

普通列表（收集箱、全部、分类、标签、特别关注、循环筛选）支持同组同父/同置顶分区的手工排序；今天同时遵守时段，计划/完成/历史/搜索按日期或结果排序，禁止伪装可自由排序。筛选子集不改其他条目或跨组；失败保留原序，重载验证持久。鼠标移动超过系统阈值直接开始拖动，原长按、手柄、Esc和键盘替代保留。拖到导航仍是安排/归属，不改子任务关系。

任务右键在指针附近打开，Menu/Shift-F10同菜单：详情、置顶/取消置顶、特别关注/取消、取消提醒、完成/重开、删除、移到及合法排序动作。单击标题继续简易编辑，完成按钮只完成。右键不启动简易编辑或拖动；先处理已有草稿再执行，取消提醒同时清周期和相对提醒偏移，删除复用整树确认/软删/恢复。

分类/标签右键“重命名…”直接进入就近编辑，名称聚焦全选，保留原元数据/层级/颜色/版本校验，失败保留输入。其他属性入口继续保留，不产生第二套改名逻辑。
