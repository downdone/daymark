# UI-23A：任务详情、导航拖放与跨天范围

2026-10-24，用户三张截图反馈。范围FR-002/003/004/005/007/010/011、追加FR-023，UX-01/02/04/05/06/07/09/11/14。遵守P-14简约而不简单：常用详情直接打开，拖放有准确目的，日期范围清楚但不冒充日程占用。Apple HIG依据沿用[官方调研](ui-research.md)的直接操作/反馈/用户控制及[全产品复审](product-experience-review.md)的Simplicity/Agency/Sidebars映射；状态、键盘、缩放和实际证据单独验收。

## 观察与裁决

1. 行尾更多先打开菜单才能进详情。改为带名称/tooltip的详情图标，直接进入现有完整共享草稿；行内快速编辑保留，其他行命令仍由右键/键盘菜单和详情提供，不增加第二份编辑器。
2. 拖动原只允许Today/Project排序，系统侧栏仅Today接收。拆分“可拖动任务”与“当前列表可排序”，开放任务可长按或手柄拖到六个任务目的地；禁排的筛选列表仍不得内部排序。拖动预览跨侧栏显示，目标有命中反馈；Esc/丢到空白零写入。
3. 详情“状态”实际是planning_state；INBOX带日期/关注时会按PRD自动转ACTIVE。明确称任务安排；用户显式选择收集箱时在草稿中清除开始/截止/关注并就地告知，保存才提交，放弃零修改；以后再说保留日期、暂停关注；在收集箱草稿填写日期时即时显示可执行，避免保存前后表述不一致。真实完成/取消仍沿用现有动作。
4. 跨天任务目前只有开始/截止标记，连续条仅覆盖独立事件。按[ADR-015](../ADR/015-task-ranges-and-navigation.md)追加可视范围，不改Today/Upcoming规则，不增加小时排程或每天一份任务。

## 导航拖放命令

所有目标由TaskService构造并校验单个TaskPatch，TaskWorkspace异步提交；QML不复制视图筛选。保留版本检查，不能在拖放时悄悄使用新版本覆盖。

| 目标 | 写入意图 | 保留与失败 |
|---|---|---|
| 收集箱 | INBOX，清除开始/截止/今天关注/今晚 | 有安排时先确认；备注、归属、标签、清单、提醒保留 |
| 今天 | ACTIVE，持续关注；未来开始日提前到今天 | 截止不自动改变；父项目暂停/结束等阻止进入时明确失败 |
| 即将到来 | 选择严格未来的开始日，ACTIVE，清除关注/今晚 | 取消零修改；开始晚于原截止拒绝，不静默推迟截止 |
| 随时可做 | ACTIVE，清除未来开始日和主动关注/今晚 | 过去开始与截止保留，日期仍可能使它出现在今天；不承诺视图互斥 |
| 以后再说 | SOMEDAY，清除关注/今晚 | 原日期保留但暂停，恢复可继续安排 |
| 已完成 | 现有完成命令 | 与勾选相同，不完成检查清单，不删除任务 |

快捷键/右键提供相同详情与移动入口，不能使拖动成为唯一入口。导航过程中仍先保护共享草稿；失败保留原任务、错误可行动。拖动时后台维护继续使用既有交互协调，不停止维护。

## 日历范围

C++ CalendarService统一输出有开始和截止且开始早于截止的有效任务范围；当地日期含两端、跨周分段、跨月裁剪。范围内当天议程包含同一任务，起点/终点仍表达开始/截止，中间称计划范围。任务条使用任务图形及配色；事件条继续表达独立事件。任务和事件共用稳定分周泳道、三条可见与溢出入口，隐藏事件不隐藏任务条。点击/Enter/Space打开同一任务，右键可选择只调整开始或截止；不拖整条暗改两个日期。

单日/仅开始/仅截止保持原标记；暂停、归档、已结束项目、软删及完成显示设置按现有有效性规则处理。不扫描QML全表，不存新实体、不需要schema迁移。

## 验证

先交付直接详情/安排/导航移动并构建、服务与模型测试，再接范围投影/共享日历并完整构建。临时SQLite覆盖六目标、冲突/非法日期/已结束归属/实例覆盖保护/失败零修改；范围覆盖跨周跨月、闰日、长范围、单日/单边日期、暂停、完成、溢出与主/独立日历一致。QML真实指针路径覆盖跨侧栏拖动、取消/日期选择、直接详情和安排保存重开；浅深/880/1120/200%、键盘与原309阶段回归保留。物理输入、读屏和Windows当前源码未实测保持UNVERIFIED；不操作真实库、不推送发布。
