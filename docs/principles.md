# 工程原则

这些原则适用于人和 AI，代码评审逐项检查受影响项；不要求每个小改动生成形式化报告。

| 编号 | 原则 | 落地检查 |
|---|---|---|
| P-01 | 离线与隐私是默认能力 | 核心路径无网络依赖；日志无任务标题、备注、真实用户库 |
| P-02 | 一个事实只有一个来源 | SQLite 保存业务事实；同一 ID 驱动列表、日历和组件；不建 UI 任务副本 |
| P-03 | 先保证数据完整，再改善体验 | 事务、软删、迁移前备份；失败不显示成功；导入验证失败零修改 |
| P-04 | 时间含义明确 | QDate 存计划日期，UTC 存瞬间；通过 IClock 测试跨天；禁止用 24 小时替代日历日 |
| P-05 | 界面不裁决业务 | QueryService 唯一决定视图归属，Repository 唯一执行 SQL；QML 只展示与发命令 |
| P-06 | 每次交付一个可运行切片 | 有需求、设计、验收和 build/test 证据；不先堆全套空类再验证 |
| P-07 | 先设计操作链，再修改界面 | 记录入口、主要动作、状态、失败和退出；覆盖键盘、窄窗和 DPI |
| P-08 | 平台能力必须实测 | 自动测试、Mock、offscreen、真实 OS 交互、干净机部署分别记录 |
| P-09 | 所有模式都有恢复通路 | 穿透可经托盘和主窗口解除；屏外可重置；错误可重试且保留输入 |
| P-10 | 保持简单，按证据抽象 | 优先 Qt 公共 API；不预建云端/插件框架/通用 ORM；第三方依赖必须有 ADR |
| P-11 | 变化有边界且可追溯 | 一个文件/模块一个写入者；接口、schema、行为变化同步契约、测试和 ADR |
| P-12 | 状态来自证据 | IMPLEMENTED、AUTO-PASS、MANUAL-PASS、RELEASE-READY 不互相替代；缺平台写 UNVERIFIED |
| P-13 | Apple HIG是UI/UX的强制设计依据 | 设计先映射HIG原则，再落实到交互、布局、字体、颜色、图形、动效与可访问性；提交需有状态、键盘、缩放与实际截图证据 |
| P-14 | 简约而不简单 | 默认界面只呈现当前内容及必要动作；复杂能力按上下文逐步展开，说明不代替清楚设计。减少重复入口、术语、装饰和常驻提示，保留错误、草稿、撤销及数据安全；不靠隐藏关键能力、缩小文字或堆进更多菜单制造简约 |
| P-15 | 操作位置与尺寸稳定 | 同类操作共用容器锚点、顺序、命中尺寸；标题长短、日期格式、日周月年和小窗/Mini切换不推动常用按钮。跨形态共享宽度和水平边界，内容先截断/换行；只有真实空间变化才按统一断点重排，不能由内容隐式决定布局 |
| P-16 | 内容与滚动视口分离 | 面板先按自然内容利用可用空间，确实溢出才允许滚动；无溢出不显示滚动条、不接受空滚动。滚动条拥有独立预留槽，不覆盖文字/输入/操作区；避免同轴嵌套，滚动与重排不改变稳定内容轴和头部操作区，大字/窄窗保留可达性 |
| P-17 | 布局契约必须可验证 | 同类界面共用字号、边距、控件区、滚动槽与断点，禁止页面临时拼坐标。验收比较切换前后控件矩形、视口/内容/滚动条边界以及浅深/100～200%截图；先判定空间关系与信息价值，再调颜色/圆角，不把对象存在当作布局正确 |
| P-18 | 垂直节奏单一归属 | 4 DIP间距基准，行内/相关控件/区域分别使用共享token；相邻留白只由一个容器负责，禁止padding、子margin、layout spacing叠加。标题按实际内容/控件自然高度，不为隐藏副标题占位；同排对齐，浏览/选中不改行高，编辑只为新增内容增高 |
| P-19 | 提示不得妨碍操作 | 普通图标默认无tooltip，必要说明显式准入；菜单/更多/视图与层级切换/展开收起/完成关闭不提示。截断补全只在文字区，普通提示延迟、与来源保持安全距离；移出、按下、禁用、菜单/拖动时关闭，名称/状态保留给辅助技术 |
| P-20 | 先分配职责再增工具 | 导航、视图显示、筛选与任务操作分层；常驻工具只保留高频且需要直接点击的动作，低频设置进入分组菜单，选中项操作靠上下文，拖动/键盘提高效率但保留可发现入口。互斥视图减少重复状态，当前模式可辨、切换目标明确、常用动作共固定槽；不能用更多按钮掩盖信息架构问题 |
| P-21 | 字体与空间作为整体设计 | 字体角色同时定义家族/回退、字级、字重、自然行高及配套留白；大标题不能沿用字段间隙，文字放大时区域和行内留白按角色同步增长，水平空间按可用宽度适应。正式与测试使用同一字体管线，按实际中英数字和100～200%验证，不以更换字体名或机械加字号代替排版 |

普通工程细节由开发者在既有授权内决定；只有确实影响数据安全、产品范围或外部发布的决定才向用户提出具体问题，不用审批取代工程判断。

UI目标落实P-07/P-08/P-09：以 [设计基准](design/ui-baseline.md) 的内容优先、渐进呈现、可恢复操作、平台熟悉感和辅助技术为设计依据，并按 [UX验收](design/ui-acceptance.md) 记录真实结果。Things仅为交互机制参考；Apple HIG按P-13作为强制设计依据，布局token与跨平台表达由Daymark独立定义。

## Apple HIG项目约束（2026-10-23用户指定）

从本轮起，Apple HIG由参考升级为项目UI/UX设计与评审的强制依据。入口为[Apple中文入门指南](https://developer.apple.com/cn/design/human-interface-guidelines/getting-started)，核心为[设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles)、[布局](https://developer.apple.com/design/human-interface-guidelines/layout)及[可访问性](https://developer.apple.com/design/human-interface-guidelines/accessibility)。八项原则及Daymark映射见[官方调研](design/ui-research.md)。

必须执行：

1. 内容与主要任务优先；用排版、对齐、留白和分组建立层次，避免依靠层层边框堆叠界面。
2. 一致、熟悉且可恢复；相同动作共享控件和反馈，保留撤销、草稿与明确错误处理，尊重用户控制。
3. 适应用户与上下文；支持宽窄窗口、浅深主题、200%文字、键盘及可访问名称，不仅靠颜色传达状态。
4. 打磨完整状态；默认、悬停、选中、焦点、禁用、空态、忙碌和错误都进入设计与验收，动效有目的且可减少。
5. 设计先于实现；每项UI变更记录适用HIG原则、Daymark具体规则及验证证据。原则冲突需写明取舍，不能以“更像Apple”为由丢失功能或数据保护。

Windows采用其原生窗口、系统字体回退、Ctrl快捷键及托盘习惯；macOS遵循对应平台交互。Qt实现、数值token和独立资源由Daymark定义；不复制Apple专有字体/图标，也不因采用HIG而承诺Liquid Glass等原生能力。无实机或辅助技术证据的项目仍为UNVERIFIED，不宣称已通过Apple官方认证。


## 辅助提示准入（P-13/14）

遵守[UX-40](design/help-tags-and-menu-type.md)：完整可见文字、通用展开/关闭/完成图标不重复tooltip；必要图标说明动作，截断文字补全原文。指针停留后才出现，键盘焦点不自动触发，按下/菜单/拖动时抑制。备注全文预览与受限拖放原因属于明确例外，保留可访问名称和可操作错误，不能以tooltip代替界面设计。共享菜单使用正文正常字重和统一文字列，不继承标题或选中项字重。

全文提示的悬停范围绑定文字区域；进入同一行的完成、展开等操作区时退出提示，不能以整行悬停触发的浮层抢占按钮命中区。布局收紧导致更多文字截断时，需一并验证提示与点击的关系。
