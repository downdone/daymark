# 工程原则

这些原则适用于人和 AI，代码评审逐项检查受影响项；不要求每个小改动生成形式化报告。

| 编号 | 原则 | 落地检查 |
|---|---|---|
| P-01 | 离线与隐私是默认能力 | 核心路径无网络依赖；日志无任务标题、备注、真实用户库 |
| P-02 | 一个事实只有一个来源 | SQLite 保存业务事实；同一 ID 驱动列表、日历和组件；不建 UI 任务副本 |
| P-03 | 先保证数据完整，再改善体验 | 事务、软删、迁移前备份；失败不显示成功；导入验证失败零修改 |
| P-04 | 时间含义明确 | QDate 存计划日期，UTC 存瞬间；通过 IClock 测试跨天；禁止用 24 小时替代日历日 |
| P-05 | 界面不裁决业务 | QueryService 唯一决定视图归属，Repository 唯一执行 SQL；QML 只展示与发命令 |
| P-06 | 每次交付一个可运行切片 | 有需求、设计、验收和 build/test 证据；不先堆全套空类再验证 |
| P-07 | 先设计操作链，再修改界面 | 记录入口、主要动作、状态、失败和退出；覆盖键盘、窄窗和 DPI |
| P-08 | 平台能力必须实测 | 自动测试、Mock、offscreen、真实 OS 交互、干净机部署分别记录 |
| P-09 | 所有模式都有恢复通路 | 穿透可经托盘和主窗口解除；屏外可重置；错误可重试且保留输入 |
| P-10 | 保持简单，按证据抽象 | 优先 Qt 公共 API；不预建云端/插件框架/通用 ORM；第三方依赖必须有 ADR |
| P-11 | 变化有边界且可追溯 | 一个文件/模块一个写入者；接口、schema、行为变化同步契约、测试和 ADR |
| P-12 | 状态来自证据 | IMPLEMENTED、AUTO-PASS、MANUAL-PASS、RELEASE-READY 不互相替代；缺平台写 UNVERIFIED |

普通工程细节由开发者在既有授权内决定；只有确实影响数据安全、产品范围或外部发布的决定才向用户提出具体问题，不用审批取代工程判断。

UI目标落实P-07/P-08/P-09：以 [设计基准](design/ui-baseline.md) 的内容优先、渐进呈现、可恢复操作、平台熟悉感和辅助技术为设计依据，并按 [UX验收](design/ui-acceptance.md) 记录真实结果。Things和Apple仅为明确来源的参考，布局token与跨平台表达由Daymark独立定义。
