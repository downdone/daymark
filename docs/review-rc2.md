# RC2系统评估与改进路线

评估基线：CAL-04源码617d4f0及本地232556包，Qt6.10.2/schema4。依据代码、测试与既有截图，不是用户研究或Apple认证；当前实施状态只见[PROGRESS](PROGRESS.md)。

| 维度 | 已有证据/评价 | 缺口与影响 | 优先级 |
|---|---|---|---|
| 产品闭环 | 任务、项目/标签/清单、重复、事件与桌面组件已有本地闭环 | 事件全局检索、单次循环例外未提供，复杂日程效率仍有限 | P1/P2 |
| 日历可信度 | 按范围生成循环、DST/月底与提醒去重测试通过 | EventRepository按系列锚点排序，TaskWorkspace投影后未按实例重排；可能晚开始的安排排在早开始前 | P1，本轮修正 |
| 查看/编辑 | 共用显式保存、草稿保护、系列删除提示 | CalendarPanel的格内及议程点击直达EventDialog，后续实例打开起点日期，容易误解本次与系列；摘要看不到提醒规则 | P1，本轮修正 |
| 导航效率 | 月/周/今天、独立桌面窗口、键盘逐日移动 | 远期日期只能逐页翻；需要可手输与选择的直接定位 | P1，本轮实现 |
| 数据可靠性 | SQLite事务/软删/迁移前一致快照；JSON1–4及异常分支测试 | 已记录提醒再提交OS，崩溃窗口不能保证系统恰好一次展示；缺少真实权限/送达验收 | P1，平台验证切片 |
| 视觉与输入 | 共享token、系统字体、200%和浅深合成截图 | 不等于真实IME/读屏/物理DPI通过；过多表单步骤和长说明仍需真实操作评估 | P1持续 |
| 工程与交付 | Debug/Release17测试，172阶段原生，严格SDK隔离/33库审计/ZIP清单 | Main/TaskWorkspace/串行smoke体量增长；维护成本增加，长场景时序耦合已有历史失败 | P2，分层提取，不重写 |
| 发布成熟度 | Windows本地候选可交付 | macOS、独立干净机、8h/睡眠/多屏、许可/签名未验；尚不满足双平台正式V1门禁 | 发布阻塞 |

结论：适合继续Windows本地试用；优先减少误操作、建立可观察的浏览路径，再扩展复杂规则。无实测不打“精致度/稳定性百分比”总分，功能实现和发布成熟度分别评价。

## 系统改进方案与顺序

| 里程碑 | 交付内容 | 依赖/退出标准 |
|---|---|---|
| CAL-05 日程浏览与定位（本轮） | 只读事件详情、具体实例/系列范围、规则/提醒摘要、直接跳转日期、实例排序 | 无schema变化；主/独立窗同源；失效实例不得冒充起点；构建/测试/浅深200%/严格本地包 |
| CAL-06 事件查找与日程密度 | 全局标题/备注查找、明确系列/实例范围、长标题/跨日条与高密度月格设计 | 先定义检索范围、结果定位和10k性能预算，保持任务QueryService语义 |
| REL-01 提醒及恢复实测 | 权限关闭/无托盘/系统通知、真实睡眠唤醒、时区切换与多屏、8h资源趋势 | 自动注入与真实OS证据分开；需要交互式设备和完整运行时间，不用短跑替代 |
| CAL-07 循环例外 | 修改/取消单次和后续，实例稳定身份，导入导出/恢复/提醒联动 | ADR+新migration，保留原系列和历史去重；未设计前不放入口 |
| ENG-01 可维护性 | 拆分日历映射、提醒编排及按能力分组的原生场景，保留集成退出门禁 | 先稳定接口，逐片等价迁移；基准不退化，不改业务语义 |
| REL-02 正式发布 | macOS构建/签名、双平台人工矩阵、干净机、分发许可和发布说明 | 依赖平台设备、许可和REL-01；未经明确授权不上传或推送 |

本轮只实施CAL-05，其余是可审查的后续计划，不自动宣称已完成或在后台运行。
