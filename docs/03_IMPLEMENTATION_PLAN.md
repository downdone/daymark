# Daymark 开发计划、工作分解与验收（Codex 可执行）

> 版本：1.0 · 依赖 `01_PRODUCT_SPEC.md`、`02_TECHNICAL_DESIGN.md`  
> 执行策略：一项或少量紧密关联任务为一个可审查改动，持续保证可编译、可运行、可测试。  
> Codex 不应一次性编写所有源文件后再尝试首编译。

## 1. 项目交付策略

以里程碑 M0→M7 严格推进。每一步需要：功能实现、单元/集成测试、README 或文档更新、可复现 build/test 证据、剩余风险。阶段之间设门禁；质量门禁未通过不能假称阶段完成。

- `M0` 平台窗口 POC：识别最大平台风险；允许独立 `poc/` 小程序，验收后移入正式工程。
- `M1` 工程骨架与 SQLite 迁移：可运行空应用；持续构建。
- `M2` 基础数据模型与任务 CRUD/分类：可本地持久化。
- `M3` 完整核心视图和主窗口 UI：形成任务管理闭环。
- `M4` 月/周日历及日期编辑：形成任务+日历规划闭环。
- `M5` 桌面悬浮组件及托盘：形成桌面高频闭环（**MVP 用户试用版本**）。
- `M6` 重复、提醒：完成 V1 常用效率能力。
- `M7` 导入导出、稳定性、打包、双平台验收：**V1 正式自用发布**。

建议每阶段采用 `Plan → Implement → Build → Test → Manual Check → Report → Commit`，并更新 `docs/PROGRESS.md`。

## 2. 里程碑与任务拆解

### M0：跨平台窗口 POC（最高优先级）

**目标**：在 Windows/macOS 各自原生构建并验证：Qt Quick/QML + 可用悬浮窗口 + 透明/置顶/穿透/交互恢复。此阶段不写完整业务。

| ID | 工作项 | 必须输出 |
|---|---|---|
| M0-01 | 盘点 Qt/CMake/编译器运行环境，选择安装的 Qt 6.8+ 版本 | `docs/environment.md`；不硬编码 Qt 路径 |
| M0-02 | QML MainWindow + 第二个透明 WidgetWindow | 能同时打开两个窗口 |
| M0-03 | Floating / normal z-order / mini 模式 | 三种模式演示入口 |
| M0-04 | 整窗鼠标穿透开关，托盘外部恢复 | 穿透后通过托盘能恢复 |
| M0-05 | Windows/macOS 显示器与窗口位置保存 | 屏外安全恢复 |
| M0-06 | 平台实测矩阵和已知限制 | `docs/platform-test-matrix.md` |

验收：

- Windows：Qt 置顶成功、透明文字清晰、`Qt::WindowTransparentForInput` 或适配实现能穿透并通过托盘退出。
- macOS：正常桌面完成以上测试；记录 Spaces/原生全屏限制，不绕过 OS 安全行为。
- 如果只有单个平台的构建环境，只能标记该平台已验证；另一个标记 `UNVERIFIED`，不会据此阻塞后续业务开发，但不得声称跨平台 POC 已验证完成。
- 失败与替代：若透明方案性能差，先切为不透明工具窗但保持交互和架构，记录 ADR，继续验证 Qt/原生组合。

## 2.1 资源、工期与风险（规划假设）

估算以“一名熟悉 C++/Qt 的开发者 + Codex 辅助开发 + 至少一台 Windows、一台 macOS 测试环境”为假设，单位是**有效工程人日**，不等于自然日，也不包含完整商业级 UI 反复打磨成本：

| 里程碑 | 参考工程人日 | 主要不确定性 |
|---|---:|---|
| M0 平台窗口 POC | 3–8 | macOS Spaces、透明穿透、焦点行为 |
| M1 工程/数据库 | 4–8 | Qt Kit/CMake/单实例细节 |
| M2 数据与 CRUD | 8–14 | 归属、状态和事务规则 |
| M3 任务 UI 与筛选 | 12–22 | QML 交互打磨 |
| M4 日历 | 8–15 | 双日期标记、拖拽语义 |
| M5 桌面组件 | 8–16 | 系统窗口行为、多屏 DPI |
| M6 重复/提醒 | 10–18 | 日历周期、跨时区通知 |
| M7 测试/打包 | 10–20 | macOS 签名公证、干净系统兼容 |
| **合计** | **63–121** | 串行估算，Codex 的实际效率需用 M0/M1 校准 |

主要风险与应对：

| 风险 | 等级 | 规避/验证策略 |
|---|---|---|
| 桌面透明/置顶行为在两个 OS 下不完全一致 | 高 | M0 首先双平台验证；公开 API；不可用模式降级显示 |
| 用户误以为悬浮窗等于系统原生 Widget | 中 | PRD 明确定义 Qt 第二顶层窗口；原生 Widget 不承诺 |
| 日期/截止/今天出现多套语义，用户任务重复或漏显示 | 高 | C++ 单一 QueryService + TC-003~013 自动测试 |
| 同一任务在多个视图编辑造成竞态与数据丢失 | 高 | 单实例、单 writer、事务、信号刷新、版本字段 |
| 重复规则生成重复任务或月底错误 | 高 | 固定唯一键、幂等测试、月末及闰日测试 |
| WAL 数据库直接复制导致备份不一致 | 高 | 一致性快照 + roundtrip 恢复测试 |
| 视觉体验低于 Things 3 | 中高 | 先实用主路径后逐轮打磨 UI；真实体验任务评估 |
| 开发无限扩展至云、移动端和 AI | 高 | 按 Out of Scope 和里程碑门禁严格控制 |

完成 M0/M1 后，必须根据实际耗时和已发现问题更新剩余工期范围，不能把初始估算视为承诺。

## 5. 当前开发启动建议

第一次发给 Codex 的工作范围应严格限定为 M0 + 最小 M1 骨架，优先验证 Windows / macOS 的窗口特性，再扩大任务引擎。直接使用 `START_CODEX_PROMPT.md` 的首轮提示。

若 Windows 和 macOS 不能在同一工作机编译，至少设计两个原生构建脚本，使用双系统或 CI 分平台验证；Codex 所在单机缺工具链时明确标 `UNVERIFIED` 并给出本地执行命令。

**拆分原则**：每次改动尽量不超过一个完整的功能纵切（例如“新建任务从 QML 到 SQLite，再显示于 Inbox 并自动测试”），比先写所有数据类、再写所有 QML 更容易稳定交付。
