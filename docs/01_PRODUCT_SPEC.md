# Daymark 产品需求规格说明书（PRD）

> 版本：1.0 · 基线日期：2026-10-22  
> 项目代号：Daymark（暂定，不作为商标或最终品牌）  
> 文档状态：开发基线；若实现方案与本文冲突，先记录 ADR 后调整。  
> 目标读者：Codex、产品负责人、软件架构师、测试工程师。

## 0. 项目指令与边界

开发一个具有 Things 3 式简洁任务管理体验的**独立跨平台桌面应用**，首要支持 Windows 10/11 与 macOS，新增月/周日历视图及可交互的半透明桌面悬浮任务组件。使用 C++20 + Qt 6.8+（Qt Quick/QML）+ SQLite + CMake；本地优先，断网完整可用。桌面端代码与核心数据由项目自有实现，不直接复制 Things 3 的私有源码、商标、图标或受保护视觉资产。

交付顺序：跨平台窗口 POC → 工程骨架/数据层 → 任务组织和筛选 → 月/周日历 → 桌面组件 → 基础重复和提醒 → 备份/发布/验收。V1 严禁提前引入云端服务和复杂外部日历集成。

**成功判定**：个人能在 Windows/macOS 上使用 Daymark 完成每日任务收集、分类、安排、查看日历、桌面勾选和追溯；应用无须登录，无网络也不丢数据。

### 0.1 产品愿景

- 把“收集 → 澄清 → 安排 → 执行 → 复盘”连成一条顺畅的个人工作流。
- 保留任务与日程的区别：任务表示要完成的行动；日历表示任务的时间安排和截止提醒。
- 桌面组件让高频事项始终低干扰可见，主窗口负责组织和计划。
- Local-first：SQLite 为唯一事实数据源；日后同步作为单独服务，而非任务 CRUD 必需依赖。

### 0.2 目标用户/平台

- 主要：需要 macOS + Windows 跨设备办公的个人用户。
- 典型场景：工作任务、个人事务、项目拆解、周计划、桌面今日待办。
- 首版桌面：Windows 10/11 64 位、macOS 13+（Intel/Apple Silicon；对每一架构分别编译/验证），Linux 为后续兼容探索，不承诺首版正式发行。
- 界面语言：首发简体中文，架构允许英文翻译；所有文案使用可国际化资源，日期/周首日采用本地化设置。
- 数据模型对平台中立，不存 HWND/NSWindow 之类平台对象。

### 0.3 明确不做（V1 Out of Scope）

- Windows/macOS 之外的正式移动客户端、Web 客户端；账号与 SaaS；端到端同步；共享协作、多人权限。
- 原生 Windows Widgets / macOS WidgetKit 系统小组件（首版采用 Qt 独立悬浮窗口模拟）。
- Google/Outlook/Apple Calendar 双向同步、CalDAV；时间块编辑器；会议管理；AI 助手；OCR；附件管理；复杂自然语言输入。
- Things Cloud 连接和私有数据协议兼容；购买 Things 的授权解锁、本地数据直接覆盖写回 Things。
- 任意嵌套子任务、Gantt、看板、富文本所见即所得编辑器、协作通知。

### 0.4 优先级与交付门槛

- `P0`：首个实用版本必须提供，无法完成则 V1 不发布。
- `P1`：有助于形成完整日常使用闭环，允许最后一个里程碑完成。
- `P2`：明确留作路线图，不阻塞 V1。
- 本文的“必须”若无特别说明，指 V1；工程实施顺序以 `03_IMPLEMENTATION_PLAN.md` 为准。

## 1. 信息架构与导航

主程序采用左侧导航 + 中央内容 + 按需出现的右侧详情面板。

```text
Daymark
├── 快速入口
│   ├── 收集箱 Inbox
│   ├── 今天 Today
│   ├── 即将到来 Upcoming
│   ├── 随时可做 Anytime
│   ├── 以后再说 Someday
│   └── 已完成 Logbook
├── 日历
│   ├── 月视图 Month
│   └── 周视图 Week（按日分栏，不含小时排程）
├── 领域 Areas [自定义，可排序]
│   └── 项目 Projects [自定义，可排序]
│       └── 分组标题 Headings
├── 标签 Tags
└── 设置 Settings

独立悬浮窗口（可多个视图模式，但 V1 单实例）
├── 今日任务
├── 迷你任务条
└── 设置/交互/穿透切换
```

状态清晰：Inbox 是未澄清的收集区；Today、Upcoming、Anytime、Someday 是基于数据计算的**视图**，不是彼此独立的任务复制库；Logbook 展示终态数据；Area/Project/Heading 是归属与层级。Today 和 Anytime 允许部分重叠，避免违背“今天也属于当前可做”的认知。

### 1.1 任务和项目的归属关系

- 一个任务可以归属某个 `Project`、某个 `Area`，或无归属；不允许同时直接归属 Project 与 Area（Project 所属 Area 可推导）。
- Project 最多归属一个 Area；Area 可包含多个 Project 和直接归属 Area 的任务。
- Heading 只属于 Project；任务引用的 Heading 必须与任务的 Project 一致；不提供跨项目 Heading。
- Checklist 是任务内部一级检查项（有序、可完成），不作为全局任务也不参与日历、重复和提醒。
- Tag 是多对多，任务可有多个标签；项目可有标签留作 P2，首版项目标签不做。
- 删除 Area/Project 时必须二次确认且采用**可恢复的软删除**；默认处理方案为“任务移到无归属/当前 Area”，禁止级联永久删除任务。

### 1.2 日期/状态的术语

- `planning_state`：`INBOX` / `ACTIVE` / `SOMEDAY`，代表规划状态。
- `task_status`：`OPEN` / `COMPLETED` / `CANCELLED`，代表执行状态；已删除另由 `deleted_at` 标记。
- `start_on`：计划开始/进入执行范围的**本地日历日期**，不包含具体时间，允许空。
- `deadline_on`：必须完成的**本地日历日期**，允许空；截止日期不等于提醒时间。
- `today_focus`：明确加入今日优先事项；允许在未设置 `start_on` 的 ACTIVE 任务上使用。
- `evening`：Today 内的“今晚”分组标记；Today 外的任务保留值但不显示该分组，或在离开 Today 时清除，实施统一采用**离开 Today 时清除**。
- `remind_at_utc`：一次性提醒时间（UTC ISO 8601），与 deadline 分离；提醒以用户本地时区输入和展示。
- `completed_at_utc`、`created_at_utc`、`updated_at_utc`：UTC 时间戳。
- `task_occurrence`：重复规则生成的具体任务实例；可独立完成或取消。
- `scheduled_start_at`、`scheduled_end_at`：P2 时间块计划字段，V1 不做编辑器，不能混同 `start_on`。

### 1.3 视图计算规则（必须一致、统一在 C++ Service 实现）

计算时使用用户当前**本地日期** `D`；所有查询必须过滤 `deleted_at IS NULL`、`task_status = OPEN`，并考虑所属项目的有效状态。

1. `Inbox`：`planning_state = INBOX`。快速录入默认进入 Inbox；若录入时明确选择项目/日期，则自动变为 ACTIVE。
2. `Someday`：`planning_state = SOMEDAY`，或被标记 Someday 的项目下且未单独迁出的任务；Someday 不自动按 deadline 激活。设为 Someday 时保留历史日期用于编辑，但不在活动视图/日历呈现，UI 应提示“日期已暂停”。
3. `Today`：有效 ACTIVE 且满足 `(today_focus=true) OR (start_on 非空且 start_on <= D) OR (deadline_on 非空且 deadline_on <= D)`；已完成/取消移出。
4. `Upcoming`：有效 ACTIVE 且 `start_on > D`。`deadline_on` 的未来值可作为 Upcoming/日历的截止标记呈现，但 **deadline alone 不使任务退出 Anytime**；Upcoming 中的“截止提醒”作为视图辅助分组，与将来才开始的任务分开。
5. `Anytime`：有效 ACTIVE 且 `(start_on 为空 OR start_on <= D)`，无论是否勾选 Today；若仅有未来 deadline，则仍属于 Anytime。
6. `Logbook`：`task_status IN (COMPLETED, CANCELLED)` 且未删除，按完成/取消时间倒序；支持恢复为 OPEN。
7. `Overdue`：有效 ACTIVE、OPEN 且 `deadline_on < D`；在 Today 和相关归属视图高亮但不用反复弹窗。
8. `This Evening`：Today 满足条件且 `evening=true`；今天之外不显示“今晚”。

**优先级冲突规范**：`SOMEDAY` 优先于任何日期；`INBOX` 优先于自动 Today/Upcoming（Inbox 中录入时间后转 ACTIVE）；`COMPLETED/CANCELLED` 优先于所有进行中视图。为保证一致性，用户将未来日期任务加入 Today 时系统将 `start_on` 改为 D 并展示轻提示；当 `deadline_on < start_on` 时禁止保存并提供解释。

### 1.4 过期与跨天

- `start_on` 早于今天的未完成任务自动持续显示在 Today，直到完成、重新安排或改为 Someday。此逻辑叫 carry-over，不产生副本。
- 日历/Today 在应用保持打开跨过本地午夜时自动刷新；恢复睡眠、时区变化和系统日期变化亦刷新。
- `today_focus=true` 代表持续关注，跨天不会自动清除；用户可自行移出 Today。此行为在首版设置中固定，避免“任务凭空消失”。
- 时区仅影响当前本地日期的判定以及一次性提醒展示；`start_on` 与 `deadline_on` 保持原本的日期值，不做 UTC 日期换算。

## 2. 功能需求逐项定义

### FR-001 收集箱与快速录入（P0）

**入口**：主窗口顶栏 `+`、Inbox 页面、应用内 `Ctrl+N`（macOS `Cmd+N`）、托盘菜单。全局级快捷键（在其他应用中唤起）列为 P2。

**交互**：

1. 输入任务标题，Enter 保存并继续输入，Shift+Enter 换行仅用于备注编辑，Esc 关闭输入。
2. 空标题不能保存；标题前后空格去除；最大 512 个 Unicode 字符，超限给出提示。
3. 默认存 Inbox，status OPEN、planning_state INBOX、无日期。
4. 可选“项目 / 领域 / 开始日期 / 截止日期 / 今天 / 以后再说”；填写明确计划则自动移到 ACTIVE/SOMEDAY。
5. 创建成功立刻更新主窗口和悬浮组件，无需重启。

**异常**：SQLite 写入失败时保持输入文本并给出可操作错误，不显示虚假的成功提示。

**验收**：快速连续新增 20 条任务后数据数目、排序和重启恢复均正确；无空任务；键盘操作可完成流程。

### FR-002 任务列表与基础操作（P0）

- 任务行包含完成圈、标题、项目/区域归属、日期/截止标记、可选标签；列表密度可调（紧凑/标准 P1）。
- 单击行打开详情；单击完成圈完成；支持取消任务、恢复完成、删除与撤销提示。
- 完成/取消的任务进入 Logbook；支持“显示已完成”开关（项目内）。
- 批量选择与批量编辑 P1：批量完成、移动项目、修改开始日期、修改标签；不做批量永久删除。
- 搜索 P0：标题+备注子串，不区分大小写；输入防抖；支持按项目/标签过滤，标签 AND/OR 高级组合 P2。
- 排序：项目内自定义；Today 自定义顺序；其余视图使用日期优先 + 明确的稳定二级排序，避免加载时随机变化。
- 无任务时有可操作空状态，不能显示大面积空白。

### FR-003 Today（P0）

- 顶部显示当前本地日期、未完成总数、已完成数（当天完成口径）、`+`。
- `Today` 分为常规任务、This Evening；支持拖拽排序；拖入晚上区令 `evening=true`，从晚上拖出令其 false。
- 可选按 Area/Project 视觉分组 P1，默认单列任务列表。
- 今日任务可执行：完成、修改标题、移到未来日期、移到 Someday、移出 Today。
- “移出 Today”若由 `start_on <= D` 或到期 `deadline_on <= D` 导致，不能仅将 `today_focus` 置 false 造成无效操作；应弹出“重新安排/设为 Someday/保留”选项。
- 在桌面组件完成任务与主窗口完成任务行为一致。

### FR-004 Upcoming（P0）

- 以日期分组显示未来 `start_on > D` 的任务，默认显示未来 30 天，滚动加载后续。
- 对“仅有未来 deadline”的 Anytime 任务显示独立“临近截止”提示，不让它产生第二份任务实体。
- 支持在日期上修改 start_on；可以从 Upcoming 拖到 Today（等价于 start_on=D）。

### FR-005 Anytime / Someday / Logbook（P0）

- Anytime：按未归属/Area/Project 组织，显示当前可执行任务。今天已列出的任务可能仍在这里，旁边显示“今日”标记。
- Someday：收纳尚未计划任务与 Someday 项目，允许一键“激活到 Anytime”、选择开始日期。
- Logbook：已完成/已取消，按最近时间排序，支持撤销完成/恢复任务、按近 7/30 天筛选 P1。
- 恢复时回到原 planning_state；若所属 Project 已删除，则改为 ACTIVE 且无归属，向用户告知。

### FR-006 Area/Project/Heading（P0）

- Area 字段：id、名称、排序、颜色标识（有限中性色+主题色）、归档/删除状态。
- Project 字段：id、area_id 可空、标题、描述、planning_state（ACTIVE/SOMEDAY）、status（OPEN/COMPLETED/CANCELLED）、start_on 可空、deadline_on 可空、排序。
- Heading 字段：id、project_id、标题、sort_order；仅作为项目内视觉分组。
- 任务可以拖入项目、在 Heading 之间移动；实现明确排序写回 DB。
- 项目完成时：须二次确认，**默认只完成项目，不自动完成所有未完成任务**；未完成任务继续保存在项目中，但从活动视图隐藏，项目恢复后再次显示。界面显示未完成数并提示。
- 删除 Project：二次确认，项目软删，内含任务保留并解除项目归属、转为 ACTIVE（保留时间）；Heading 软删/解除关联；一次数据库事务完成。删除 Area：内部项目保留但 area_id 设空，直接归属 Area 的任务解除归属。

### FR-007 任务详情（P0）

字段：标题、备注（普通文本，可保留换行，预留 markdown）、项目/领域、Heading、标签、Checklist、状态、start_on、deadline_on、today_focus、evening、提醒时间、创建/修改/完成时间（只读）。

- 修改标题/备注可延迟提交（400ms 防抖），失焦/关闭面板时确保落库；重要操作采用立即提交。
- 日期选择器区分“计划开始”和“截止”；“清除日期”有单独操作。
- 输入 `start_on > deadline_on` 提示错误且不写库；允许 start_on 空、deadline_on 单独存在。
- 删除不可逆恢复的 UI 暂不开放；软删后提供撤销入口。
- 修改任务归属时自动处理互斥条件：选择 Project 清空 direct area_id；选择 Area 清空 project_id 和 heading_id。

### FR-008 Checklist（P0）

- 一个任务可有 0..N 条 Checklist Item，含 `title`、`is_done`、`sort_order`。
- 支持新建、勾选、重排、删除、回车新增。
- 完成主任务时**不强制自动勾选** Checklist；展示未完成数量并可直接确认完成。
- Checklist 项不参与全局搜索？**参与备注/搜索 P1**，P0 只搜任务标题和备注。

### FR-009 标签与筛选（P0）

- 标签可创建、改名、删除；有色标（主题有限色板）；名称在大小写折叠后唯一（数据库需明确 Unicode casefold 由应用层实现规范化键）。
- 给任务添加/移除多个标签；左侧点击标签查看该标签下 OPEN 任务。
- 过滤结果保持 Today/Project 等上下文，不直接变动任务归属。

### FR-010 日历月视图（P0）

**目标**：从时间维度查看任务负载、计划开始、截止日期，支持基础任务重排。

- 日历顶栏：上/下月、回到今天、年月标题、月/周切换。
- 每个日期格至少显示日期、最多 3 条任务标题、超过条数 `+N`；当天高亮，周末弱提示。
- `start_on` 事件显示为计划项；`deadline_on` 显示为截止标记（不同色/线型/图标），同一任务同一日期两个标记合并。
- 若 start_on 与 deadline_on 分处两日，可以在两天分别显示引用同一任务的不同语义标记。点击任一标记打开同一 `task.id`。
- 默认不显示 Inbox/Someday、已完成/取消；可切换显示已完成 P1。
- 单击日期：右侧显示当日任务；双击空白日期：新建任务，`start_on` 预填该日、planning_state=ACTIVE。
- 拖拽计划项到另一日期：修改 **start_on**；拖拽截止标记则修改 **deadline_on**。拖拽前后均遵守 `start_on <= deadline_on`，冲突时提示并回滚，不允许静默修改另一个日期。
- 月视图内“未排期”侧栏显示 ACTIVE 且 start_on/deadline_on 都为空的任务（P1）。
- 跨月份拖拽在 V1 先采用选择目标日期弹窗，不要求自动滚动翻月。
- 月首周几可设置周一/周日；避免 QML MonthGrid 月份 0-based 与 QDate 月份 1-based 混淆，由 C++ CalendarService 输出 yyyy-MM-dd 日期值。

### FR-011 日历周视图（P0）

- 7 列：每天一列的**全天任务列表视图**；显示 start_on 计划、deadline_on 截止标记；周一/周日首日跟随设置。
- 支持上一周/下一周/本周、点日期、拖任务跨天调整 start_on。
- 视觉上区分“任务计划开始”和“截止”。
- **明确没有小时轴、时间块拖动、冲突检测**；后续时间块功能的 schedule 字段另建模型。

### FR-012 悬浮桌面组件（P0，重点）

**定义**：Daymark 创建的第二个原生顶层窗口，与系统 WidgetKit/Windows Widgets 无关；Windows/macOS 共享 QML 内容，采用平台适配层处理窗口细节。

V1 模式：

1. `FLOATING`：半透明无边框、置顶、可交互，今日任务最多显示 8 条，滚动可见更多，勾选完成；可拖动和调整宽度/高度。
2. `MINI`：约 260×48 的单行摘要（今日任务数 + 第一项），点击可展开到 Floating；具体尺寸响应 DPI。
3. `PASSTHROUGH`：完全鼠标穿透，只展示任务，不能直接勾选；通过托盘或主窗口关闭穿透。**不能设计成鼠标穿透后仅靠悬浮窗口自身退出**。

首版不提供桌面真正“嵌入壁纸层”的固定模式（macOS 相关窗口层级与 Windows WorkerW 均非统一可靠 API），可提供 `NORMAL_ZORDER`（不置顶、能被其他窗口遮挡）作为近似。

控件：标题、完成/未完成数、最多 N 条任务、完成按钮、`+`（新建今日任务，可打开主窗口）、展开主窗口、更多菜单（模式、透明度、锁定、关闭）。

设置：可见性、置顶开关、穿透开关、透明度滑杆 60–100%（只对背景容器渐变；文字对比度须可读）、位置/尺寸、锁定拖动、开机自启 P1、开机默认显示/隐藏、迷你模式。

约束：

- 多屏时持久化屏幕标识、归一化几何信息、像素尺寸和 DPI；显示器被移除或分辨率变化时移动到可见屏幕内。
- Floating 必须支持拖动表头，不抢夺其他应用窗口键盘焦点；主动点击输入框时允许焦点。
- 点击勾选后必须通过统一 TaskService 落库并同步刷新所有视图。
- `WindowTransparentForInput` 属于**整窗**输入穿透；为避免部分穿透的跨平台不一致，V1 使用显式模式切换。
- 在 macOS Spaces/全屏应用上尽力正确显示，不承诺强制覆盖系统级全屏/安全桌面；记录平台支持矩阵和已知局限。
- 不采用平台未公开的桌面注入和私有 API；不修改系统桌面进程。
- 退出穿透的恢复路径必须始终可用：托盘菜单“关闭鼠标穿透”，以及主窗口设置。
- Widget 隐藏不等于退出整个应用。

### FR-013 主窗口和系统托盘（P0）

- 主窗口可最小化、还原、关闭；托盘菜单可打开主窗口、显示/隐藏组件、切换穿透、退出。
- 首版关闭主窗口默认最小化到托盘，首次关闭时提示一次，设置可切换“关闭即退出”；若操作系统不提供托盘则关闭直接退出并保护未提交编辑。
- 应用单实例，重复启动时唤起已运行主窗口；通过 QLockFile + 本地进程唤醒机制实现，避免单纯锁文件后第二次启动无反馈。
- 关闭主窗口后提醒调度和悬浮窗口继续运行（若配置允许）。

### FR-014 提醒通知（P1；V1 完成）

- 每项任务允许一个 `remind_at_utc`；支持设置/编辑/清除，未来时间为默认；过去时间保存时要求明确确认或拒绝，本版选 **拒绝**。
- 任务完成/取消/删除后不再触发；提醒只触发一次，记录 `reminder_fired_at_utc` 或单独 delivery 表。
- 应用正在运行时使用平台通知适配器：优先 Qt 系统托盘通知作为基础能力，按平台补充原生通知；若通知权限缺失则在应用内通知中心显示，不能宣称系统通知已成功送达。
- 应用未运行期间无后台通知保证；下次启动检查错过的提醒，在应用内集中提示但不制造通知风暴（最多 10 条汇总）。
- 睡眠/唤醒和时区变更需要重新计算待提醒队列。

### FR-015 重复任务（P1；V1 基础规则）

仅支持：每天、每 N 天；每周指定星期几；每月指定某日；每年固定月日；按完成后 N 天。`N>=1`。

- 周期规则是模板，实际产生可独立完成的任务实例；在 Logbook 保留历史，不能完成模板本身。
- 固定日期周期按**本地日历日期**计算而不是“UTC 每 24 小时”，以避免夏令时偏移。
- 当月不存在指定日期（如 31 日）时**跳过该月**；闰年 2 月 29 日缺失年份跳过，不能自动降为 2 月 28 日。
- 编辑模板只影响**尚未完成且计划日期不早于明天**的实例；用户已手工编辑的某个实例不被强行覆盖（设置 `instance_overridden=true`）。
- 生成实例唯一键 `(recurrence_template_id, occurrence_on)`，重复执行生成器必须幂等。
- 固定周期滚动生成未来 30 天实例；重新启动补全尚未生成的日期；为避免旧版本首次运行生成大量陈年任务，历史补全限最近 30 天，超过的遗漏显示规则维护提示。已存在的过期实例必须保留。
- “完成后 N 天”类型永远只保留一个未完成实例，完成后以完成当天本地日期 +N 天生成下一个。
- 删除规则：确认后停止产生新实例，既有任务实例保留；若需删除所有未来实例另提供明确选项。
- 不支持 RRULE 全规格，不宣称兼容所有 ICS recurrence；复杂规则 P2。

### FR-016 搜索（P0）

- 顶部搜索框快捷键 Ctrl/Cmd+F，立即筛标题与备注，支持中文、英文（大小写不敏感）、数字。
- 全局搜索覆盖 Inbox/ACTIVE/SOMEDAY，默认不包含 Logbook；勾选“包括已完成”可扩展。
- 搜索结果展示项目、日期和标签，可点开编辑。
- 至少 1 万条任务的数据集下输入搜索不阻塞 UI；可使用异步查询及 SQLite 索引；首版无需 FTS5，但优先考虑 Unicode 文本搜索的边界和测试。

### FR-017 备份、导入导出（P0）

- 备份：手动“创建备份”；默认每日首次启动时自动保留一份一致性快照（最近 7 份轮换），数据库迁移前强制备份；备份文件含 schema 版本和创建时间。若首次运行不存在用户数据，不必创建空备份。
- 导出：JSON 自有格式（任务、项目、领域、标签、清单、规则、设置的可迁移子集），UTF-8；同时支持 CSV 任务导出 P1。
- 导入：V1 提供自有 JSON 导入，严格检查格式版本、重复 ID、非法日期/外键；默认先预览数量，再以一个事务执行；可选择“仅添加”（遇到 ID 冲突跳过并报告）或“替换当前数据”（双重确认且先备份）。
- SQLite 热备份必须使用 SQLite backup API 或安全的数据库快照流程，不允许在 WAL 使用期间只复制 `.db` 主文件并宣称备份完整。
- 数据目录用 `QStandardPaths::AppDataLocation`，日志/缓存与核心数据分目录。
- 不把用户私人任务或备注写入遥测/错误日志。

### FR-018 设置与主题（P0/P1）

- P0：浅色/深色/跟随系统，周一/周日作为周首日，主窗口尺寸与状态，桌面组件开关/透明度/置顶/穿透/模式，关闭行为。
- P1：开机启动（原生平台适配，macOS 权限/用户设置以系统实际行为为准）、数据导出、备份周期、每日提醒行为。
- 设置改变立即生效并持久化；无效设置回退到安全默认值并记录非敏感日志。

## 3. UI/UX 设计系统

### 3.1 视觉定位

- 使用克制、精细、轻量的 macOS 风格设计，但遵守 Windows 输入与窗口交互习惯。
- 以白/浅灰/深灰为主；仅关键操作和日期使用一个主强调色，减少大面积底色与粗重卡片。
- 扁平层级、弱边界、适中留白；避免大量阴影、玻璃特效带来的渲染成本。
- 动效 120–200ms，尊重系统“减少动态效果”；功能可在关闭动效时完整使用。
- 深色主题中文字、禁用态、日期高亮具备足够对比；色彩不作为区分截止和计划的唯一手段。

## 4. 核心业务用例（Given/When/Then）

### UC-01 收集并安排

- Given 用户位于 Inbox，When 输入“准备周五评审”并回车，Then 新任务进入 Inbox 且存入 SQLite。
- When 选择 `start_on=明天` 并归属 Project A，Then 规划状态转 ACTIVE，移出 Inbox，出现在 Upcoming 和 Project A。
- When 到达明天本地午夜，Then 无需重启即可出现在 Today、Anytime，不再位于 Upcoming 的未来开始分组。

### UC-02 只有截止日期的任务

- Given 新任务 ACTIVE，`start_on=null`，`deadline_on=三天后`，Then 它属于 Anytime；日历三天后显示截止标记。
- When 三天后到达，Then 它也进入 Today，但不是系统自动补写 `start_on`。

### UC-03 Today 置顶与未来安排

- Given 任务 `start_on=七天后`，When 选择“加入今天”，Then 弹出说明并将 start_on 调整为今天；Today 立即出现，Upcoming 的未来开始分组不再出现。
- Given start_on=昨天的未完成任务，When 今日打开，Then Today 继续存在。

### UC-04 日历拖拽

- Given `start_on=10/24`、`deadline_on=10/28`，When 拖动“计划开始”到 10/26，Then 只更新 start_on。
- When 拖动“截止”到 10/25，Then 因违反 `start_on <= deadline_on`，提示且 DB 不变。

### UC-05 桌面组件

- Given 今天有 3 项，When 从托盘打开悬浮组件，Then 显示同源三项。
- When 勾选第一项，Then 数据库保存完成状态，主窗口 Today 与桌面组件立即剩两项，Logbook 中新增一项。
- When 开启穿透模式，Then 鼠标事件穿透整窗；可通过托盘菜单关闭穿透。
- When 显示器拔除，Then 下次窗口定位后组件处于当前可见屏幕区域。

### UC-06 离线和重启

- Given 网络已断开，When 新建/编辑/完成 50 项任务并退出，Then 重启后数据和手动排序均保留，无网络请求失败阻碍使用。

### UC-07 重复任务

- Given 每月 31 日重复规则，When 查看 2 月，Then 不生成 2 月 28 日任务；3 月 31 日正常生成。
- Given 每周周一规则，When 多次重启/触发生成，Then 每个 occurrence_on 最多有一个实例。
- Given 完成后 3 天重复规则，When 今日完成实例，Then 产生今日 +3 个本地日历日的新实例，下一条不是立即当天提醒。

### UC-08 备份恢复

- Given SQLite 为 WAL 模式且有未 checkpoint 数据，When 创建备份再恢复到隔离数据目录，Then 任务数量、标签关联、清单均一致。
- Given 导入损坏 JSON，When 校验失败，Then 原数据库完全不变。

## 追加需求 FR-019：本地事件与任务关联（2026-10-23用户授权）

- 事件独立CRUD：标题、备注、全天或定时起止。全天结束日期UI包含当天；存储结束日排他。定时事件保存UTC瞬间及IANA时区，非法/倒序/DST歧义时间拒绝且保留草稿。
- 事件在月/周日历及当天议程与任务同屏，类型有文字/图形标识；任务计划开始/截止不作为事件时段，提醒不占用日历时段。FR-011继续是全天周列表，本轮不要求小时轴。
- 同一事件可显式关联多个任务，同一任务可关联多个事件，关联角色为准备或跟进；从事件打开任务，从任务详情查看并打开关联事件。
- 完成任务不取消事件；改期各自独立。删除事件软删并提供8秒撤销，关联任务保留；任务软删不删除事件，关联隐藏，撤销可恢复。事件保存与关系修改同一事务，冲突/失败零修改。
- 任务日历增加直接完成/恢复，仍走统一命令及脏草稿保护。当天议程默认今天，月格超量入口、键盘日期移动、宽窗侧栏/窄窗上下布局、200%正文滚动与空态可用。
- JSON/一致快照包括事件及关联，兼容旧schema1/2导入；新schema3迁移前备份，旧应用不可打开升级库，回退用升级前快照。CSV继续仅导出任务，并在界面说明。
- 所有能力离线；外部账户、系统日历同步、自动生成或移动关联任务不在本轮范围。详见ADR-013。
## 追加需求 FR-020：独立桌面日历（2026-10-23用户授权）

- 日历可作为独立窗口显示，与主窗和任务Floating/Mini同时存在；月份/周模式/选中日期各自独立，业务任务/事件共用同一数据源与命令。
- 可调背景透明度50–100%，文字不随背景变淡；置顶可切换，关闭只隐藏，可从主窗日历及设置恢复。
- 本机持久化显示、透明度、置顶与独立几何；屏幕变化后位置可恢复，重置入口可用。不新增数据库、账号、云服务或穿透模式。
- 复用日历的完成、改期、事件与关联功能；任务编辑回主窗并保护草稿，事件草稿在所属窗口保留，隐藏/关闭确认不丢输入。

## 追加需求 FR-021：循环事件与提醒（2026-10-23用户授权）

- 事件支持每天/每周/每月/每年、1–365间隔和可选包含结束日；按锚点当地日期/时间投影，非法月日/闰日及DST歧义实例跳过。当前编辑/删除范围为整个系列，界面必须明示，不假装支持单次例外。
- 提醒支持开始时、提前5/15/30/60分钟/1天；全天事件基准本机09:00。运行/启动/恢复检查，补报最近24小时到期实例，无退出后台服务；持久化去重、应用内记录和回事件入口，系统实际送达不能仅以提交成功当验收。
- 月格内容层级参考用户iOS截图：清楚月份、圆形今天、事件色条、重复标识、细周线与留白；主窗/独立日历一致，资源独立，键盘/200%与草稿保护保留。
- schema4追加迁移，升级前一致快照，规则及提醒历史保留于JSON/快照，旧JSON兼容，失败零修改。细则见design/event-series.md及ADR-014。
